# write-technical-proposal 设计

本 Skill 帮助用户撰写、打磨和重组用于评审的技术方案，让跨岗位读者理解方案，让实施者找到具体设计与验收依据。本文供维护者理解结构选择、内容分工和验证方式；执行协议见 [SKILL.md](../../skills/write-technical-proposal/SKILL.md)。

## 方法依据

规则来自技术方案的多轮评审准备：从代码和实验材料确认现状，澄清本期目标，按场景重组总览，再将有效工程细节交给专题或已有技术文档。Skill 保留这些判断方法，具体项目、模型、设备、指标和日期由当前任务提供。

## 文档分工

文档层级和写作视角分别选择。层级决定内容范围与深度，视角决定围绕什么评审问题组织内容。

| 维度 | 选项 | 选择依据 |
| --- | --- | --- |
| 文档层级 | 总览、专题 | 总览说明整体方案；专题承接某个细分方向的详细设计 |
| 写作视角 | 产品／场景、工程／技术 | 前者围绕消费场景、能力和效果；后者围绕技术路线、职责、机制和验证 |

默认组合是产品／场景总览与工程／技术专题。每篇仍按主要评审问题独立选择，四种组合均可采用。采用场景视角的专题也要保留指导实施的技术设计。

方案只拆一层：总览 → 专题。短主题可以留在总览，更细内容放在专题内部或引用既有技术文档。四种组合的写作重点和章节结构集中维护在[结构选用与表格示例](../../skills/write-technical-proposal/references/document-shapes.md)。

## 章节分工

场景方案集中说明业务用途、现状、技术设计、本期改动和验收。多个场景共用的方案集中维护，场景章节保留各自的影响和要求。本期建设安排只说明实施顺序、依赖和阶段产出。

| 章节 | 作用与保留条件 |
| --- | --- |
| 共用机制（可选） | 多个场景共享且需要集中说明时保留；专题只展开自身范围，总览已有说明时引用并补充差异 |
| 独立建设主题（可选） | 总览中无法归入某个场景、需要独立说明技术路线和验收的主题 |
| 验证方案（可选） | 复杂实验、多平台对照或组合评测需要展开测试输入、环境配置、步骤、对照方法和统计口径时保留；方法简单时并入交付要求 |
| 交付要求 | 明确最终交付物、通过标准和验收证据；验证方案引用已确定的通过标准 |

未采用的可选章节整章省略。「参考依据」统一放在文末，影响数据理解的必要口径就近保留。

## 内容保留

- 执行者分别记录当前实现、本期目标设计、候选措施和待补输入。代码确认现状，已确认需求决定目标。
- 执行者用正式基线支撑比较，保留单位、统计对象、适用条件及相对变化口径，不编造期限或门槛。
- 执行者将业务方和基础设施的职责分别写清，不把消费方工作自动纳入基础设施建设。
- 执行者按用户授权处理分析、局部修改和重组。替换总览前，逐项确认有效细节已由专题或既有技术文档承接，再修复引用并收敛维护入口。
- 图表用于展示关系、过程、对比和验收。Skill 负责图意、占位和位置，正式绘图交给 `create-system-diagram`。

## 维护与依赖

本仓库的 `skills/write-technical-proposal/` 是维护源，宿主搜索路径中的副本用于运行，修改后按仓库约定手动同步。设计文档留在本仓库，安装包通过相对路径读取自身资源。

| 包内文件 | 职责 |
| --- | --- |
| `SKILL.md` | 写作流程、文档分工、事实与数据处理、交付检查 |
| `references/document-shapes.md` | 四种结构、可选条件、表格和图示占位示例 |
| `references/content-retention.md` | 内容迁移、归宿核对和同步规则 |
| `evals/` | 虚构项目输入及行为评价要求 |

执行者通过当前环境的 Skill 目录解析依赖：中文技术文案使用 `tech-doc-style-chinese`，长篇人类读者文档使用 `optimize-docs-readability`，正式系统图使用 `create-system-diagram`。目标仓库和输入材料由当前任务提供。

## 必要验证

维护者按变更范围选择检查：

- 包格式、相对引用与评测输入路径有效，安装包没有私人路径、真实项目标识或依赖原工作区的文件。
- 四种组合的结构与已确认分工一致，可选章节标记和条件完整，交付要求均保留。
- 修改写作行为时，用 `evals/evals.json` 中的代表性请求检查事实与目标区分、场景分工、指标口径和技术细节保留。
- 修改文件位置或导航时，核对入口、资源及安装副本一致性；单纯迁移不要求重跑完整模型评测。
