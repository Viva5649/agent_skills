# create-system-diagram 设计方案

状态：已在仓库实现。规则按通用、图类型与专项组织，专项按内容触发；保留已确认的信息层级、配色、版式与连线约定。验证范围见文末。本文供实现、审阅或维护本 Skill 的人理解绘图方法、视觉约定与验收标准。

Skill 名称为 `create-system-diagram`。本文按「通用规则 + 图类型规则 + 专项规则」定义绘图方法、样式参数和实现要求，实施者无需读取外部项目中的架构图。首次阅读按章节顺序理解规则，制作模板时查阅「固定视觉样式」，交付时查阅「验证与验收」。

## 目标与范围

本 Skill 根据用户提供的代码、文档或已有图，创建、更新和检查可独立打开的 HTML/SVG 系统图，覆盖架构图、流程图与数据流图。图按主要问题呈现模块职责、任务推进或数据去向，并保持一组图的视觉一致性。

默认采用本文的固定色板和图形样式。绘图代理根据图要回答的问题选择布局，保留项目已有术语。用户指定其他风格时遵从用户要求；没有指定时不随机生成配色。

架构图按稳定的架构单元组织，流程图按功能操作组织，数据流图按数据或存储对象及必要处理操作组织。完整时序图、状态机、交互式编辑器、自动布局引擎和批量导出工具不在范围内。默认静态 HTML；已有或用户要求的阅读交互按专项规则处理。

安装包在 `skills/create-system-diagram/` 维护。设计文档留在 `docs/design/`，不成为安装包的运行依赖。

## 通用规则

适用于全部图类型。每张主视图先确定主要问题，再选择图类型，最后按实际内容启用专项。一次请求、循环、指标和交互只在对应场景下检查，不作为所有图的必备内容。

### 输入、输出与事实边界

绘图代理开始工作时，先读取用户请求、来源材料、已有图稿和已确认决定，确定图的读者、要回答的问题、范围及事实版本。材料能确定的事实由代理自行核对，已确认决定直接沿用。用户要求当前架构时，代理核对范围内的生产调用、接口和配置；用户要求根据指定设计稿绘图时，代理按设计稿表达，并标明设计状态。

修改前，绘图代理明确目标对象、动作和影响范围。代理将「SDK」「引擎」「接入层」等通称对应到具体组件，核对参与者、调用入口和所在阶段。代理用现有标题或组件名称定位目标，区分页面分区、图内分组、节点与连线。例如合并「路线」与「目标与评测范围」所在的页面分区时，代理调整容器、标题和排布，保留图内模块归属、阶段划分与连线。

绘图代理区分生产实现、已确认设计和用户提供的外部现状。仓库内部行为核对生产调用与配置；具体观测字段、失败阶段等须找到真实生产者，不能为对称布局补出能力。用户已确认的外部能力按确认内容呈现，助手未亲自验证的范围在交付说明中交代；仅凭仓库未包含外部实现，不将外部能力标为待建设。已确认待建设的能力在对应对象旁标明。来源冲突影响图意时，沿用事实冲突处理规则。

关键节点和关系需要来源。绘图代理应能回答以下问题，不要求为每次任务额外生成固定格式的清单：

- 节点表示模块、类型、运行实例、功能操作、数据、存储，还是解释文字？
- 需要表达归属或存储时，节点属于哪个应用、进程、存储区域或职责分组？
- 箭头表示调用、依赖、回传、安装还是其他关系？谁是起点，谁是终点？
- 关系在什么条件下成立？当前已启用、可选与尚未接入生产是否已区分？
- 哪些信息由代码或文档确认，哪些仍未知？

查阅材料后，若对象、能力状态或修改范围仍有信息缺口、歧义或冲突，且不同结论会改变图意或修改范围，绘图代理说明未确定的含义、可选解释及各自影响，并询问用户。图意包括参与者、职责边界、实例归属、关系方向、阶段划分与场景范围。代理只暂停依赖答案的修改，继续整理已确认部分。间距、换行和不改变含义的连线避让由代理自行决定。

默认交付一个 HTML 文件，内嵌样式与 SVG。文件包含标题、图例、必要说明和事实来源或版本；同一文件内需要多张图时，每张图的 SVG 标识符必须唯一。用户指定输出路径时使用该路径，否则按目标仓库文档约定命名和存放。

交付说明提供文件链接、验证结果和未确认项。只有用户要求时才另行提供独立 SVG、图片或 PDF，不默认增加额外产物。

共同范围包括对象、抽象层次与事实版本。已有证据足以确定主线时先形成图稿，缺失部分就近标明；新增构建、真机测试和性能采集按任务授权另行执行。

### 绘图方法与布局选择

默认产物为静态 HTML 内嵌 SVG，不使用 JavaScript。CSS 定义可复用的颜色、文字和图形样式，SVG 使用显式坐标安排节点与连线。

绘图代理先按问题选择表达形式：职责与归属用架构图，任务如何完成用流程图，数据来源与去向用数据流图，纯指标或方案比较用表格，再选择下表中的布局。不同表达可以组合。重排和拆图保留请求范围内的性能、本期工作与验收信息。

| 布局 | 主要回答的问题 | 组织方式 |
| --- | --- | --- |
| 整体分层 | 谁调用谁，模块归属哪里，对外提供什么 | 按抽象层次纵向分层，横向排列同层模块，共享组件按实际依赖安排 |
| 模块内部结构 | 调用怎样进入功能域，功能域依赖什么 | 主路径纵向展开，功能域分类排列，侧面补充适配组件 |
| 多入口汇合 | 多个入口在哪里汇合，状态由谁持有 | 并列入口，共同运行区域，独立的请求与回传箭头 |
| 并列分支 | 同一入口下的不同运行方式有何区别 | 统一入口后分列，每列展开对应组件或有依据的步骤 |
| 职责对照 | 两个职责面有何区别，又复用了什么 | 左右排列职责，分别标注实例与存储，下方说明实现复用 |

布局中的位置只负责组织阅读。调用、执行顺序、实例共享和进程归属必须分别有事实依据，并通过明确的边界、标签或连线表达。重排后，绘图代理逐条确认关系的真实起止对象。构建、解析、依赖替换等机制单独表达，不能代替实际依赖目标；分组本身是关系对象时，连线才可连接分组边界。

每张图只回答一个主要问题，展开深度以回答这个问题为准。总览优先展示参与者、职责、主要依赖与产物归属，局部流程展示关键协作。属于同一任务的组件、执行角色和产物可以共同出现，须标明类型与关系。需要多个视图时，绘图代理分别写明各图的问题，避免重复铺开同一组细节。

当目标和评测范围直接用于判断同一条路线时，绘图代理可将路线、目标和评测摘要放在共同页面分区中，用内部标题和间距区分主体与摘要。问题、对象或展开深度明显不同时，拆成相关视图；共同主题不要求强制合并，内容仍须符合整页精简与布局容量规则。

默认 HTML 是图示页。图内保留主要关系、核心作用与关键条件，图下仅保留理解本图所需的目标、评测范围和约束摘要。完整路线表、验证步骤、验收细则与工程资料通过来源链接查看；用户明确要求完整资料页时按指定范围展开。精简后复看整个 HTML，确认图注、表格和说明没有重复铺开文档细节；不以主图文字变少代替整页信息取舍。

绘图代理按主要问题安排视觉优先级。主流程图让入口、处理与结果形成连续阅读路径，支持信息靠近服务对象；职责对照图让同级对象保持相近的面积、字号与对齐。通过位置、面积、留白和字重突出重点，颜色沿用本视图已声明的含义。

总览与局部视图沿用共同对象的名称及有助于理解关系的相对顺序和分组，同一颜色维度保持配色一致，局部标题注明所属对象。多视角图按专项规则声明不同视图的颜色维度。真实关系或展开深度需要重排时，保留可识别的共同节点。已有跳转或展开功能应能返回来源位置，返回后仍能找到原节点；静态图无需增加交互。

绘图代理先确定主次信息，再分配面积与文字。主要节点保留名称与必要定位标识，按需补充简短职责；维护资料、完整文件名、字段约束与长说明放到来源文档。影响实例归属、授权、可选路径或失败结果的条件仍须紧邻对应关系。辅助资料不能仅因内容多而获得与主架构相同的视觉权重。

### 按信息职责选择表达

绘图代理先判断信息在图中的作用，再决定是否画成独立节点。重要信息可能是参与者、条件或约束，不能统一装进同一种卡片。

| 信息类型 | 表达方式 | 例子 |
| --- | --- | --- |
| 实际组件、执行角色、工具或产物 | 使用节点，通过真实关系或明确分组表达归属 | 处理组件、校验工具、交接文件 |
| 决定流程走向的条件 | 接入主线，标明条件分支及结果；仅限制入口时使用入口条件标记 | 凭据有效时直接复用产物，绕过后续处理 |
| 解释某个节点或关系的局部说明 | 放进对应节点或紧邻对象；核心作用与关键条件用正文，辅助信息用次级文字 | 只读权限、实例创建方式 |
| 适用于整张图的约束 | 共同范围优先放在图标题下；图下仅保留必要约束摘要与责任角色，完整约束通过来源链接查看 | 整次运行的状态保护与恢复要求 |

辅助说明单独使用卡片时，绘图代理明确所说明的对象，并降低视觉权重。独立节点应有清楚的关系或分组归属；发现孤立节点时，代理先核对信息类型，不为消除孤块编造连线。全图约束中的某项若决定具体分支或执行入口，代理仍在对应位置保留必要条件，完整规则通过来源链接查看。

### 固定视觉样式

#### 模块配色与主题

以下映射适用于架构图及以模块协作为主要组织方式的图。满足多视角专项条件时，可按视角建立映射，并在对应视图声明颜色维度；同一维度保持一致。

模块决定色系，信息用途决定填色，包含关系表达层次；职责类别不分配固定主色。绘图代理先确定模块及其归属，再为本组图建立「模块 → 独立主色或继承对象 → 样式类」映射。源码或职责名称不直接决定颜色。

用户指定或同组图已经确认的模块映射优先，映射须能追溯到明确决定；临时试色不自动成为约定。没有既有映射时，子模块默认继承父模块。仅当本图主要用于比较或追踪多个同级子模块的分工与协作时，才为这一组统一制定独立配色，并说明参与区分的模块与选色依据。独立接口、进程、连线和内部职责数量用于核对架构，不自动触发换色。

一个模块的主色覆盖自身及继承配色的子模块。采用独立主色的模块之间保持可辨认的颜色差异，同一模块在本组相关视图中保持一致。新增独立映射时复核本组相关图，避免同一模块交替继承和独立配色。颜色不足时调整分组或拆图，不按位置轮换颜色。

为尚未定色的模块从固定色板选色，优先考虑淡橙、淡黄和淡红，搭配蓝、紫、绿、青。按主要区域的可见面积检查冷暖分布；已确认映射和模块辨识优先，不为凑颜色数量改色。普通模块可使用红色或绿色，状态通过明确文字和局部标签表达。

维护色板时，先用相同面积、文字与层次比较各色的视觉强度，再放回完整图检查主要区域。浅黄、浅橙和浅红应保留可见色相，青色等较明显底色不应让同级模块获得额外的视觉权重；优先微调浅底和职责区填色，保留模块映射与主色。透明度或对比度数值仅辅助判断，不能机械设成相同数值。通用校准样例见工具参考中的「固定色板与填色层次」。

用按实际模块命名的 `module-*` 类设置 `--module-color`、`--module-bg`、`--module-chip`，分别供主色、浅底和职责区及标签填色使用。继承配色的子模块复用父模块类或继承 CSS 变量，避免重新分色。跨模块汇总与中性分组使用 `group-neutral`；`role-*` 固定职责色不再作为模板入口。

示例中的模块映射仅适用于对应示例。实际绘图先按本组图的对象与问题确定映射，再复用色值。更新已有图且用户未要求重配时，保留已明确的映射。模块主色调整时同步边框、模块标题、附属信息归属、图例及新版对照视图，改前视图保留。仅修改文字配色时保留模块背景与边框。

#### 填色与边框

按对象用途和真实归属选择背景；层次通过包含关系、名称、位置和间距表达，填色不按嵌套深度逐级加深。

| 对象 | 填色与边框 | 模板用法 |
| --- | --- | --- |
| 外层模块，或采用独立主色的子模块 | 自身主色浅底、主色边框 | 分组用 `frame`，独立组件卡片用 `card card-tinted` |
| 继承父模块色系的子模块与内部组件 | 统一卡片背景，浅色主题为白色；边框保留继承的主色 | 分组用 `frame frame-inherited`，卡片用 `card` 或 `mini` |
| 模块内部的职责分区 | 所属色系中更明显的一档浅色，同组职责统一填色 | `duty`；名称、列表或分区区分具体职责 |
| 性能、本期工作及验收说明 | 保留所属模块主色，用指标卡、工作列表与条件说明区分用途 | 指标卡用 `card`；说明区可用 `annotation` 配合模块色标题 |
| 页面或场景分区、跨模块汇总说明 | 中性背景与边框；浅色主题为白底圆角，模块明细保留各自主色 | 页面分区用 `figure`；SVG 分区用 `annotation` 和 `section-title` |
| 应用、进程等边界 | 无填充、中性虚线，注明边界类型 | `boundary` |

职责分区共用所属模块的执行主体，不为每项职责递增加深。性能、工作与验收说明的边框及归属标题沿用模块主色，正文与当前值使用正文色；本期优化目标的数值及比较符号局部使用橙色加粗。具体通过或失败结果按状态规则表达。

绘图代理按实际显示尺寸确认父模块浅底、继承组件背景和职责区填色可以辨认，并复看填色面积较大时是否压过主线。需要强调当前工作、关键状态或目标时，使用位置、字重和带明确文字的局部标签，沿用既有主色与填色用途。

模块边框使用模块主色，正文使用主题正文色。`card` 与 `mini` 保留约 `2px` 的边框及 `vector-effect: non-scaling-stroke`，模块框保留 `1.5`；信息注释区使用中性细边框与模块色标题。父模块的浅底、继承组件的白底和职责区的填色在实际显示尺寸下分别复核。深色主题使用对应卡片背景与色值，保留相同含义。

Skill 实现者将这些值写成模板内的 CSS 变量，图形通过变量引用颜色。HTML 根元素默认使用 `data-theme="light"`，以 `data-theme="dark"` 选择深色变量，不新增主题切换控件。颜色不能独自承担信息：区域有名称，状态有文字，关系有方向、线型或标签。

#### 图形与含义

| 图形 / 样式类 | 表达什么 | 绘制约束 |
| --- | --- | --- |
| 大虚线边框 `boundary` | 应用、进程或隔离环境 | 边框旁写明具体边界；职责分组不能冒充进程边界 |
| 视角区域 `perspective-frame` | 已声明的业务、工程或算法等视角 | 只在多视角专项启用时使用，标题用 `perspective-title`，不表达模块包含关系 |
| 浅色区域 `frame` | 架构模块 | 按职责、协作与资源归属确定包含关系；源码与构建视图另行注明 |
| 卡片 `card`、`mini` | 组件、功能操作、数据、产物或局部解释 | 局部解释明确所说明的对象，不能作为调用者；全图约束放在图下 |
| 小标签 `chip` | 模块名、接口、状态或发布属性 | 图例说明当前图采用的含义；技术标识保持准确 |
| 标记 `pill`、`step` | 能力标记、真实步骤 | 只在标记能帮助阅读时使用；状态归属编号不转换成步骤 |
| 职责分区 `duty` | 模块承担的不同工作 | 同组职责沿用统一填色，标明所属模块 |
| 说明区 `annotation` | 场景分区，或性能、工作、验收说明 | 中性分区用正文色标题；模块附属说明用模块色标题，内部正文与当前值用正文色 |
| 横条 `band` | IPC、HTTPS 等通信通道 | 按所属模块着色，标明协议与跨越范围，按真实调用绘制箭头 |
| 连线 `edge` | 对象关系或注释关联 | 方向关系的箭头指向具体目标；注释关联不加箭头，标签与图例说明含义 |

模块标签跟随模块主色；状态标签根据本图图例单独选择颜色，并始终写明状态。状态标签的颜色不改变所在模块的主色。

混合节点类型时，绘图代理用简短文字标明组件、执行角色、文件或产物等实际类型，复用已有文字或标签样式，不另建一套颜色映射。同一视图中同类节点的标识方式一致。组件图中的节点保持稳定对象含义；执行阶段在局部流程中展开，不能让一个节点同时表示完整组件和组件内部的某个步骤。

卡片内的职责说明应与卡片主体一致。其他角色负责的收尾动作，绘图代理应放在对应角色或产物说明中，并写明执行者，避免读者因卡片包含关系误判职责归属。

区域颜色标识模块及继承范围，连线样式表达关系。模板中的蓝色业务模块沿用本例映射，蓝色箭头按图例表示主要调用。

| 连线样式类 | 颜色 | 线宽 / `stroke-dasharray` | 默认关系含义 |
| --- | --- | --- | --- |
| `k-flow` | 蓝色 | `2` / 实线 | 主要调用 |
| `k-alt` | 琥珀金色 | `2` / `7 4` | 条件分支或替代路径，注明触发条件 |
| `k-event` | 青色 | `1.8` / `2 4` | 事件或异步回传 |
| `k-plain` | 中性连线色 | `1.6` / 实线 | 一般关系，以标签或图例声明是依赖、安装等哪种关系 |
| `k-cfg` | 中性连线色 | `1.6` / `6 4` | 本图明确声明的可选关系或未接入关系 |
| `k-fail` | 红色 | `2` / 实线 | 失败或拒绝结果 |
| `k-association` | 中性连线色 | `1.4` / `3 4`，无箭头 | 性能等注释信息的归属 |

绘图代理在图例中说明实际使用的关系含义。同一图内一种连线样式只能承担一种已声明的含义。可选关系与未接入关系同时出现时，必须通过不同样式和明确标签区分，不能合并成一个含糊图例。没有使用的连线类型不需要出现在图例中。

图例默认放在对应视图内容框外的下方左侧，直接置于页面背景，不另加背景框。先列本图已声明的模块或视角色块，再列连线样例，逐项纵向排列。模板将图例作为 `figure` 后的 `.legend` 元素，放在图形横向滚动容器外；样例区域宽度、文字起点与行距一致。色块说明当前颜色维度与映射；模块配色同时说明继承范围，线型和箭头样例覆盖本图实际使用的全部含义，包括无箭头关联和双向箭头；未使用的类型省略。说明文字使用次级文字色，不分散成横向多列。用户另有指定时遵从指定。

模板默认使用与连线同色的实心三角形箭头，尺寸作为起点，按实际显示比例复核。注释关联使用 `k-association` 中性短虚线，不加箭头。marker 的 `viewBox` 为 `0 0 10 10`，三角形路径为 `M0,0 L10,5 L0,10 z`，`refX="9"`、`refY="5"`、`markerWidth="7"`、`markerHeight="7"`、`orient="auto-start-reverse"`。连线默认无填充，箭头引用本图独有的 marker ID。

#### 整图骨架与对齐

绘图代理先确定完整的层、并列区域和辅助区，安排共同左右边界与连线通道，再放组件。分层图优先让连续层共享外沿；并列区域优先顶底对齐，内部关键内容共享水平基线。列宽按信息量分配，不要求所有卡片等宽。对齐只组织阅读，不增加归属、调用或执行顺序。

共享代码的位置结合本图的抽象层次和实际依赖安排，并与具体适配实现分别表达。接口契约与公共实现承担不同职责，不因都被依赖就放在同一抽象层。依赖箭头从使用方指向被依赖方；运行调用、接口实现与模块依赖分别标注，不把上下位置画成未经确认的执行顺序。

「被依赖」只确定依赖关系的目标，不决定目标在上方还是下方。例如，以能力实现为主线的分层图可将接口契约放在适配层上方，将适配器使用的共享实现放在下方；实现关系向上、模块依赖向下。这是有适用条件的布局选择，不是所有共享组件的固定位置。

整图外部轮廓保持稳定，内部按内容变化。连续层应避免在全宽、中央窄块和侧边孤块之间反复收放。上下层列数不同时，绘图代理用层的共同外沿保持连续，在各层内部调整网格。辅助依赖可放在对应列底部或对齐的辅助横排；共享设施仍按实际使用范围标明关系，不能为了铺满底部暗示所有组件都依赖它。

留白用于区分层级、分组和容纳连线。出现一条中央长链、两侧大片空白，或底部只剩偏置节点时，绘图代理优先尝试层内横排、相邻辅助列或拆分视图。必要关系须保留；空节点和过大的无内容边界不能用于凑齐轮廓。

#### 文字用途与配色

先按文字在本图中的用途选样式，再按模块映射取色。模块主色只承担模块身份；正文层级由内容对当前问题的重要性决定。

| 文字用途 | 配色与字重 | 模板样式 |
| --- | --- | --- |
| 页面、章节、场景、进程边界标题 | 正文色，加粗 | 页面标题、`section-title`、`boundary-title` |
| 表达模块身份的名称 | 所属模块主色，加粗 | `frame-title`、`module-title`、`outer-title`；独立模块卡片用 `node-title module-name` |
| 模块内部组件名称、职责标题 | 正文色，加粗 | `node-title`、`mini-title`、`duty-title` |
| 本场景核心作用、正文、关键条件、指标名称及当前值 | 正文色；必要时加粗 | `body-text`、`duty-body`、`metric-value` |
| 补充说明、测量口径、图例文字 | 次级文字色 | `note`、`module-note`、`.legend` |
| 本期优化目标数值及比较符号 | 橙色，加粗，保留「目标」或「实测 → 目标」标记 | 仅为目标片段添加 `metric-target` |
| 状态与结果 | 默认正文色；突出时加粗或用局部状态标签 | 正文或带明确状态文字的标签 |
| 连线文字 | 普通关系用中性色；特殊关系按图例用对应颜色 | `edge-label`；两行主行可加 `edge-operation` |

模块标题按图中身份判定。内层子模块明确展开自身边界时，标题使用自身或继承的主色；内部组件名称仍使用正文色。附属说明区可用模块色标题标明归属，区内指标名称与当前值使用正文色。不要全局修改 `.node-title` 将所有标题染色。

核心解释、关键条件和当前值保持正文色，辅助文字仅用于次要信息。绘图代理在文字实际所在的浅底、卡片背景或职责区上复核小字号模块标题与连线标签；过淡时在同一色系内调整对应文字色或增大字号，保持已确认的颜色含义。

目标强调只改变数值及比较符号的局部文字，模块背景、边框与归属标题保持模块映射。橙色模块中的目标仍通过「目标」标记、比较符号和字重识别。图例的样例保留真实颜色，解释文字统一使用次级文字色。

#### 块内文字与场景作用

绘图代理先确定当前场景，再判断节点是否需要解释文字。当名称、分组和连线已能清楚表达本场景作用时，节点可以只保留标题，并按卡片空间居中或对齐。同级节点采用相近的信息粒度；解释文字用于补充必要含义，不为填满卡片或凑齐行数增加说明。影响理解的条件、状态和结果用途仍须保留。

需要解释时，选择每个块最有关联的动作、对象、输出用途与必要条件，按「对象或操作名称 → 本场景核心作用 → 必要补充」组织。操作标题说明当前作用或结果，函数名与公式按需补充。核心解释保持正文层级，只有辅助信息使用次级文字色或较小字号。

例如查询场景中的资料应用可写「提交查询条件，展示匹配内容」，索引服务可写「检索匹配条目，返回排序结果」。两个模块分别说明自己的贡献，共同适用的资料范围在图标题下说明一次。通用职责清单和完整工程细节留在来源文档；局部触发条件紧邻负责的块或连线。

精简后仍应能说清谁做什么、作用于什么对象、产生什么结果。使用「查询文本」「带签名的下载地址」「每条记录对应一次请求」等明确表述，保留动作、修饰关系和统计单位。外框已明确模块身份时，可省去内部重复前缀；项目术语和代码标识保持原样。

块内标题、核心解释与补充说明各自使用统一起点、间距和对齐方式，按语义换行。中文短并列用顿号，独立职责或条件分行，解释用冒号或括号；多条件写清「且」或「或」，时长紧邻适用条件。验收数值用 `≥`、`≤` 并保留比较对象与范围。中点「·」可分隔编号或类型，不通用于所有语义关系。

展开内容承接父节点的输入、处理和输出。术语在主图、明细与生成源中一致。公式可辅助表达计算，执行者、条件和存储动作仍用文字说明。主要结果、关键分支与当前问题的瓶颈留在主视图，原始日志和完整推导放入明细或来源。

不设机械行数或字数上限，也不为对齐凑相同的块数或文字数量。调整文字后按内容调整块尺寸。复看时，读者应能直接说清这个块在当前场景做什么、如何与相邻块协作。

#### 几何、字体与信息密度

默认 SVG 的 `viewBox` 宽度为 `1400`，高度按内容确定。页面最大宽度为 `1440px`，水平居中。页面内边距按上、右、下、左设置为 `24px 16px 32px 16px`。每张图下方预留 `40px`，标题与图之间预留 `14px`。

SVG 默认设置 `display: block; width: 100%; min-width: 1400px; height: auto`，外层图形容器设置 `overflow-x: auto`。窄屏在图形容器内横向滚动。绘图代理按用户指定尺寸和实际阅读效果调整最小显示宽度；缩放后难以阅读时，先精简信息、增大显示宽度或拆图，不通过不断缩小字号塞入内容。

| 文字层级 | 默认字号 | 字重与颜色 |
| --- | --- | --- |
| 页面标题 | `1.375rem` | `700`，正文色 |
| HTML 图注与图例 | `0.8125rem` | 次级文字色 |
| 组件标题 | `15px` | `700`，正文色 |
| 模块标题 | `14px` | `700`，模块主色 |
| 小卡片标题 | `12.5px` | `700`，正文色 |
| 通信横条标题 | `13.5px` | `700`，模块主色 |
| 正文、说明与代码标识 | `12px` | 正文色；辅助说明使用辅助文字色 |
| 连线标签与紧凑标签 | `11.5px` | 普通连线用次级文字色，特殊关系按图例用对应色；紧凑标签用正文色 |
| 两行连线标签的动作主行（可选） | `12.5px` | `600`，沿用连线色；次行使用普通连线标签样式 |
| 步骤编号 | `10.5px` | `700`，等宽字体；圆形使用正文色，编号使用页面背景色 |

HTML 标题、图注和图例使用相对单位，随浏览器基础字号变化；表中图内字号的 `px` 按 SVG 用户坐标解释。绘图代理从目标阅读尺寸反推字号与画布：等比缩放后的字号约为「SVG 字号 × 显示宽度 ÷ viewBox 宽度」。宽 `1400` 的图若显示为 `1040px`，`12` 单位正文仅约 `8.9px`；当前最小显示宽度保留 `1400px`，并按实际可读性继续调整。显式坐标 SVG 放大文字时，同步调整卡片、行距与连线通道，不能只更换字号单位。

模块框圆角默认 `10`，卡片为 `8`，标签为 `5`。卡片边框使用 `stroke-width: 2` 和 `vector-effect: non-scaling-stroke`，在 SVG 缩放时保持约 `2px` 的可见线宽。其他边框按 SVG 用户坐标设置：模块框与通信横条为 `1.5`，标签为 `1`。边界框不填充，边框使用中性连线色、线宽 `1.5`、虚线 `7 5`。绘图代理按实际显示尺寸检查边框颜色、背景和正文是否清楚；列宽、行高和间距随内容调整。

一张图选用少量重复的尺寸。以 `1400` 宽画布为例，外边距可从 `20`、区域内边距从 `16–20`、相邻卡片间距从 `16–24`、普通层间通道从 `40–56` 个 SVG 用户单位起步。这些数值是排版起点；分支或双向线需要更多空间时，绘图代理局部调整并复看整体。卡片高度按短标题、标题加一行说明等内容类型复用，同类文字保持一致的起点和行距。

同组内容的间距应小于跨组间距，并为连线保留通道。标题靠近所属区域，核心解释靠近对应块，条件靠近执行入口，标签靠近自己的线段。绘图代理按实际显示尺寸检查读者能否直接判断文字和块的归属；出现歧义时先调整邻近关系与留白。

区域表达模块或职责分组，卡片展示层内可识别的组件及必要说明，标签表达标识、属性和状态。在本图展开范围内，有明确组件的层应展开具体卡片，不能为紧凑把组件结构压缩成只有标题或标签串的空横幅。接口本身是需要展示的独立对象时，绘图代理也使用卡片；仅作为其他组件的属性时使用标签。

卡片数量以真实组成为准，不强求每层同样多或固定为三列。组件较少时，绘图代理调整列宽、间距和留白；不要虚构、重复或无依据地拆分组件来填满空间，也不把属性或说明凑成组件。组件的层内归属足以表达组成，不要求每张卡片都有独立连线。关键信息、条件和角色归属仍按信息职责规则保留。

外框必须增加模块或实例归属信息。外框与唯一子卡片若表示同一对象、重复同一说明，绘图代理保留一种表达；确有不同边界含义时可以嵌套。完整分组不要求每个辅助机制都占一条全宽层，也不能靠重复包框代替组件展开。

正文和代码分别使用以下字体栈：

```css
--font-body: "Noto Sans SC", "PingFang SC", "Hiragino Sans GB", "Microsoft YaHei", system-ui, sans-serif;
--font-mono: "JetBrains Mono", ui-monospace, "SF Mono", Menlo, Consolas, monospace;
```

模板不请求在线字体。本机缺少首选字体时使用后续字体，绘图代理在实际字体环境下检查文字宽度、中文标点与中英文混排，不全局套用英文紧字距。

#### 连线通道与端点

绘图代理根据本图要回答的问题，先为主要关系安排相邻节点和直接通道，再放创建、管理等辅助关系及其组件。辅助关系是否属于主线由图意决定，不能为辅助卡片让路而迫使主线绕完整图外沿。卡片之间预留连线通道，优先使用水平、垂直折线；请求与回传分开走线。长说明按信息职责安排，不能仅因篇幅长就将关键条件移出图。长标识通过加宽或明确分行处理，不依靠截断或压缩字符宽度隐藏内容。

分组内部的协作线可在分组内直接连接相关节点。跨区域连线优先连接相邻节点：绘图代理先让线段从端点侧就近离开所属区域，再沿区域之间的空白通道走线，在目标侧就近进入。背景色较浅也不等于空白通道：连线不能穿过无关的职责区域，或借有色区域内部绕行。连接所属区域内的节点时，可以保留必要的短距离穿入或穿出。

直线通道与分组标题、说明冲突时，绘图代理先调整文字位置、换行或留白，不默认让主线绕过文字。全图说明可移到图前或图注，局部条件仍紧邻对应关系。端点离边界过远、需要绕过大半张图或只能穿越背景时，绘图代理优先移动依赖节点、调整分组范围或拆分视图，再安排路径。

多条线共用侧边空白时，绘图代理统筹端口顺序和通道位置，让长短回路分层嵌套，避免横向接入段切过其他竖线。调整后仍保留真实端点、方向与关系，不合并独立关系制造汇合点，也不把线压到背景下面隐藏交叉。折线最后一段须有足够的直线长度，让箭头方向容易辨认；箭头挤在短促转角上时，调整接入侧、端口或通道。线段和箭头均与边框、标题、卡片保持可见间距。

分组与内部组件承担不同关系时，绘图代理须通过端点位置区分责任主体。例如，分组发起调用、内部组件接收回调时，调用出口位于分组边界，回调接到实际组件。若出口位置使调用线看起来由内部卡片发出，绘图代理应局部调整卡片宽度或端点，保留短路径和既有分组；不能仅靠标签解释，也不为走线增加虚构节点。

#### 连线标签与编号

标签须紧邻具体线段，让读者唯一确定标签归属。水平线的标签在对应线段上方或下方居中；竖线的标签放在线的一侧，左侧文字向右对齐，右侧文字向左对齐。绘图代理将多行标签作为整体定位，保持共同对齐边、稳定行距和可见的线文间距。标签不能漂在卡片下方，也不能因避让文字而远离对应线段。

同组连线先选一致的描述维度。动作型标签写「动作 + 对象」，数据交接可写「场景：载荷」。请求与返回配对，例如「入库：内容文本」与「入库：内容向量」、「检索：查询文本」与「检索：查询向量」，同类场景保持相同顺序。避免一条只写触发时机，另一条只写用途；时机影响流程时，就近保留为条件。

API、实现方式作为补充；需要两层信息时，主行说明关系，次行补充机制。例如「读取通用配置」配「配置接口（只读）」。主行可用 `edge-operation`；单行足够时保留单行。关键分支条件不能因压缩标签而省略。

使用 `M1` 等编号时，绘图代理在首次出现处或图注说明编号表示索引、阶段还是执行顺序。作为索引时，主行采用「编号 · 动作 + 对象」或「编号 · 场景：载荷」，不只写编号或 API 名；同一编号用于多个分支时，用具体对象区分。容量、证据和完整限制可放在表格，图内仍须说清主要关系与必要条件。编号不是所有图的必备元素，查表也不能成为理解主线的前提。

#### 阅读与导航

图形滚动容器使用可聚焦的原生区域，提供名称与清晰的焦点轮廓。已有链接、展开与返回操作须可通过键盘到达和使用；链接或控件不嵌套进 `role="img"` 的静态图形中。绘图代理检查 Tab 顺序、焦点位置、横向滚动及放大后的完整内容，避免焦点被遮挡或文字被裁切。仅当页面已有动态效果时，响应 `prefers-reduced-motion`，保留内容与操作结果。

颜色之外，模块仍有名称与包含边界，状态有文字，连线有方向、线型和标签。绘图代理检查灰度或降低色彩辨识时能否追踪关键关系；出现混淆时补足这些表达，不临时改变模块身份色。

#### 局部时间关系

需要表达阶段耗时的起止关系时，绘图代理用区间线连接明确的起点与终点，并注明操作及适用条件。里程碑放在时间轴节点旁，组件内动作通过无箭头关联线对应；图例说明时间区间和注释关联。这里只展开当前问题所需的局部时间关系，完整时序图与状态机仍在范围之外。

## 图类型规则

按主视图要回答的问题选择对应章节。共同视觉要求沿用通用规则。

| 图类型 | 适用问题 | 节点与连线 | 阅读验收 |
| --- | --- | --- | --- |
| 架构图 | 哪些模块承担什么职责，如何组成与协作 | 节点表达架构单元；连线表达依赖、调用、实现或协作 | 找到职责承担者、包含依据与协作对象 |
| 流程图 | 输入或事件如何推进到结果 | 节点表达功能操作、判断或结果；连线表达顺序、条件与循环 | 从入口追到结果，解释实际出现的分支与循环 |
| 数据流图 | 数据在哪里产生、传递、保留和使用 | 节点表达数据、存储及必要处理操作；连线表达读写、传递、复制或映射 | 从来源追到使用端，解释保留与变化 |

### 架构图

适用范围：模块分层、组成、职责协作与运行实例关系。按有依据的架构单元确定粒度，保留同层可比较的身份与边界；组件卡片可以说明多项职责。执行步骤只在需要解释局部协作时展开，并标明步骤含义。

#### 按架构职责划分模块

按架构职责划分模块，源码归属作为核对依据。根据模块对外承担的责任、内部协作、资源与生命周期归属确定边界。大框表达大模块的职责边界，小框展开内部组成与分工，连线表达模块间的调用、依赖或数据交接。

分组标题优先说明职责，目录、包名和构建模块名作为次级标识或来源链接。结合接口、生产调用和配置核对分组；同一代码包可以承载多个架构职责，一个架构模块也可以跨代码包实现。实现分布与职责边界有差异时，标明映射，保留真实的协作与资源归属。

支持组件按服务对象和管理责任归组，共享能力按实际复用与依赖关系组织。不能为了把同色组件放在一起而改变包含关系。进程和部署边界单独标明；源码结构、包依赖或构建集成视图可以按源码与构建关系组织，并在标题或图注中明确视图用途。

#### 模块、子模块与职责分区

绘图代理先确定图要回答的问题和展开范围。用前三项确认模块身份，展开子模块时再核对包含依据：

| 判定项 | 需要核对的内容 |
| --- | --- |
| 架构身份 | 代码或已确认设计将对象作为稳定的协作单元，有明确名称与实际对应对象 |
| 职责边界 | 能说明模块承担哪些能力，以及哪些工作由其他模块负责 |
| 协作边界 | 能说明其他对象如何调用、依赖模块或与模块交换数据，关系可明确连接到模块 |
| 包含依据 | 子模块承担父模块整体责任中的明确部分；仅有使用关系时，通过依赖线表达 |

现状图依据生产实现或已确认的外部现状，方案图依据已确认设计。涉及状态或资源时，继续核对创建、持有、修改和关闭责任。名称、功能相近或源码目录只提供线索；证据不足的结构保留待确认，不凭排版补出模块。

外层与内层表示模块之间的包含关系。当前视图可以只展示单模块，也可以展开有依据的子模块。职责表示模块承担的工作，执行主体仍是所属模块。父模块可包含子模块，各模块可同时展示职责；整体职责涉及多个子模块时，注明适用范围与责任方。模型、文件、产物等保留实际类型，不因使用卡片就改称子模块。

优先展示回答本图问题所需的子模块，再补充必要职责。职责可以写在模块卡片内，也可以用列表、短条或分区；短条可有细边框，通过标题、尺寸和排版与模块卡片区分。请求和结果关系连接实际模块或组件；职责分区只有在明确展示局部步骤时才承担相应流程关系。

### 流程图

适用范围：需要解释任务如何完成的图，包括架构图中的局部流程。先确定一次请求、一个批次、某一轮或完整任务的范围，以及入口事件、完成结果和必要前提。调用返回、业务完成与资源清理分别核对，只有影响本图问题时才展开对应边界。

#### 功能操作的拆分

每个操作块应能回答：执行者在什么输入或状态下，完成什么操作，得到什么结果。根据读者需要区分的结果、依赖、状态变化或开销拆分，保留同层粒度。

| 视角 | 拆分依据 | 放入明细的内容 |
| --- | --- | --- |
| 业务 | 有独立完成条件的任务进展 | 不影响任务理解的内部步骤 |
| 工程 | 组件责任交接、等待、存储或需要分析的成本边界 | 单纯函数拆分、变量赋值与封装层 |
| 算法 | 回答当前问题所需的数据变换、关键状态读写与依赖 | 同一操作内的公式推导与实现细节 |

例如「计算统计结果」与「写入结果文件」在分析计算与写入开销时分别成块；一般任务总览可以合为「生成报告」。函数或公式数量本身不决定块数。组件节点与操作节点混用时，就近注明操作的执行者。

复杂链路或粒度尚有争议时，先选包含关键依赖的一小段画出示例，再按同一标准展开全图。材料足以确定的粒度由代理选择；仍会改变用户要求的展开范围时，先澄清。概念解释不会自动扩大已确认的图稿范围。

#### 顺序、分支与循环

- 主线覆盖从入口到结果所需的功能操作；工程或算法完整链路是阅读目标时，不能全部隐藏在业务节点的展开内容中。
- 分叉说明择一、并行或广播，条件紧邻分叉。授权、另行发起等前提在实际入口可见；文件交接与执行触发分别表达。
- 出现循环时，明确重复范围、迭代推进和退出条件。例如「批次 i +1，继续处理下一批」；已有迭代变量时沿用原名。首轮与后续轮次不同则标明差异，跨轮读写的状态按资源与存储专项核对。
- 条件退出接在实际触发位置，取消或错误出口不排成每次必经的普通阶段。初始化、每次请求与满足条件时才发生的操作分别注明触发时机。
- 箭头、编号与完成条件核对当前实现或指定设计。通用教材流程只能辅助理解，不能覆盖实际调用顺序；编号表示索引还是执行顺序须明确。

验收时追踪一条完整路径；图中有分支或循环时，再追踪一个能解释条件与退出的实例。没有这些内容的图无需补出分支或循环。

### 数据流图

适用范围：需要解释数据来源、去向、转换、存储或复用的图。先确定展示的是逻辑数据、存储对象还是物理分配；按本图问题选择节点身份，需要混合时明确类型与对应关系。

- 为主要数据标明来源、接收者及必要的读写者。处理操作写明输入和输出；同一数据跨阶段保留时，保持可识别的身份。
- 连线区分读取、写入、同一存储区域内复制、跨区域复制、映射与别名。复制方向跟随数据去向，依赖箭头另行声明；多个视图指向同一分配时标明共享关系。
- 新建节点须有独立数据或存储身份依据。操作数量不决定分配数量，视图与别名通过明确关系关联实际分配。
- 读写与跨阶段保留是主要问题时，可将存储区域或 buffer 固定为列，执行进展向下，读写横向展开。持久状态保留在同列，后续读取接到实际保留状态；相关生命周期见专项规则。
- 固定列只适用于需要持续追踪存储的内容。一般数据转换可以使用直接的来源、处理与目标布局，无需增加介质列。多阶段重复展示同一对象时，注明同一对象及阶段。

验收时从输入追到最终使用端；存在跨阶段状态时，继续追踪其写入、保留和后续读取。仅凭图内信息应能区分数据变换与数据搬运。
### 架构含义的复核

**共用实现与共用实例分别表达。** 例如两个应用都使用 `PolicyEngine` 实现，但分别创建实例并持有存储。图中应分别绘制实例与存储，按实际应用归属和存储边界放置，并用说明标注「复用同一实现」。绘图代理确认节点代表的对象后再决定能否合并；同名类、同色区域或同一源码模块都不足以证明共享运行实例。运行实例图还须标明短期对象的创建者、持有者与实例范围，例如按请求、会话或任务创建。绘图代理将短期对象放在对应所有者分组内或用明确关系关联，避免将短期对象误画成全应用共享实例。

**位置不自动表示执行顺序。** 并排可以表示职责比较，纵向可以表示分层或内容组织。绘图代理只有在来源支持步骤关系时才加顺序标记或连接箭头。例如「状态 A 由请求对象持有、状态 B 由执行器持有」表达状态归属，不应画成先 A 后 B 的执行步骤。

**包含不自动表示调用。** 把卡片放进区域只表达归属。绘图代理分别核对归属关系和调用关系，不为了让图看起来连贯而补线。

**图中的条件必须保留。** 绘图代理在适当位置保留运行模式、可选路径、未接入状态和关键失败结果。例如两个节点都执行策略校验，其中一个会拦截请求，另一个只记录结果。两者沿用所属模块主色，并标明行为差异。

**总览与细节按问题分工。** 总览保留主要边界与调用方向，模块图展开局部职责和必要约束。一张图同时承担过多问题时，绘图代理拆成相关视图，保持术语、配色与共同节点一致，不默认展开整个仓库。

## 专项规则

这些规则可以跨架构图、流程图和数据流图使用。只读取触发条件成立的章节；没有出现的内容无需补画，也不因此增加测量、交互或额外交付物。

| 专项 | 触发条件 | 验收重点 |
| --- | --- | --- |
| 多视角对应 | 同一对象或链路需要通过多个视角共同解释 | 各视角完整，身份与一对多关系可追踪 |
| 性能指标 | 图中出现耗时、吞吐、内存、比例、基线或目标 | 测量对象、范围、来源、统计口径与关系明确 |
| 资源与存储 | 图意涉及持有、生命周期、线程、读写或搬运 | 责任组件、执行位置与存储边界各有依据 |
| 配置与实现差异 | 比较或切换后端、平台、场景、版本、运行配置 | 共同操作一致，差异及证据范围明确 |
| 交互与分享 | 已有或用户要求展开、切换、跳转、动画或独立分享 | 内容对应、返回位置、键盘操作与交付环境有效 |

### 多视角对应

适用范围：多个视角共同解释同一对象或链路。仅有几张不同主题的图时，沿用通用的术语与身份一致性要求即可。

绘图代理为各视角明确主要问题，保留读者需要独立追踪的完整主线。例如业务视角表达任务结果，工程视角表达组件操作，算法视角表达数据变换。需要完整工程或算法链路时，不能只把内容分散在业务节点的明细里。

以稳定的对象或操作标识建立对应关系。允许一对多、多对一；一次工程调用可以展开为多个算法操作。对应关系通过明确标签、分组、无箭头关联或已有交互表达，不能画成执行调用。缺少对应依据时标明未展开或待核对，不暗示无操作。按语义对应安排位置，不为统一行数拆块或合并操作。

#### 视角配色的启用条件

模块主色仍是架构图以及以模块协作为主的图的默认方式。只有用户明确要求按视角区分，或本图主要问题已确定为追踪多个视角且没有既定配色冲突时，才采用「视角 → 主色」映射。在视图标题或图例声明当前颜色维度，并从同一固定色板取色。

视角配色作用于对应视角区域和操作卡片。模块身份通过名称及必要的执行者说明保留，同一视图不把同一种区域颜色同时解释为模块和视角。跨视图改用不同颜色维度时，各视图分别声明含义，以共同标识建立对应；同一颜色维度内保持既定映射。

后端、平台、阶段和融合状态通过文字或局部标签表达，不自动改变主色。「融合」等强调只作用于对应词语或标签，并保留事实范围；橙色目标值仍遵守通用文字规则。

验收时选择一个业务结果，追踪到工程操作与展开的算法或数据操作，再返回原结果。各视角的起止、分支和结果须相容。

### 性能指标

适用范围：任一图类型出现定量指标、性能基线、比较或目标时。绘图代理使用任务已授权的证据；新增构建、真机实验和性能采集按任务授权另行执行。已有证据能确定主线时先形成图稿，缺失值标明未测或待确认，避免用持续取证推迟完整主线的交付。

每项指标先确定测量对象、版本或配置、输入与运行状态、单位、来源和统计口径。实测、估算、模拟数据与目标分别标明；基线须有证据。影响比较的条件在指标附近可见，原始记录及采集细节放入来源或展开内容。性能是主要问题时，主要耗时、占比和比较结论直接显示在主视图。

| 出现的内容 | 必须说明的关系 |
| --- | --- |
| 耗时 | 起点、终点，以及调用返回、业务完成或资源清理中的实际测量边界 |
| 单次、累计与平均值 | 单位工作范围、累计次数或样本数；平均值不能代替完整任务累计值 |
| 百分比与组成 | 分母、统计范围、是否来自同一次请求或同一批样本；局部分类标明覆盖范围 |
| 父阶段与子阶段 | 标明包含关系，汇总时只计算一次；分别统计的中位数不直接拼成一个请求总量 |
| 并行或重叠区间 | 明确重叠范围，端到端耗时按实际时间区间计算，不能把重叠耗时相加 |
| 融合操作 | 合并测量值只由一个测量对象承载，其他操作引用该对象；没有独立测量的部分保留未知 |
| 不同配置的比较 | 明确双方的输入、输出工作量、运行状态与统计方法；差异条件影响结论时就近注明 |
| 内存与分配 | 区分当前值、峰值、分配量及共享范围；别名或视图不重复计入同一分配 |

性能归属通过同色分组、邻近位置或 `k-association` 无箭头关联表达；多个模块的汇总区使用中性分组并分别标明测量对象。架构视图中性能区沿用所属模块色，视角配色的图中指标按测量对象注明归属，不再叠加一套区域颜色。

涉及本期工作和验收时，沿用用户确认的责任组件、改动、比较条件与判据。现状、本期工作、目标和待确认内容分开表达，测量与验收任务不得由图稿自行补造。跨场景共用工作注明适用范围。同类指标统一名称、单位和表达格式，未测部分不能填零或扩大为已测范围。

验收时解释一个数值的对象与来源，并按图中实际出现的内容检查一次汇总、占比或比较。完整组成应能覆盖声明的总量；局部组成须让读者看见覆盖范围。

### 资源与存储

适用范围：图意涉及运行实例、异步执行、资源持有、生命周期、存储或搬运。架构图可以只展开职责与资源归属，数据流图按问题继续展开读写路径。

#### 职责归属、执行线程与存储边界

涉及运行实例、异步执行或存储时，分别确定三个维度：

| 维度 | 核对依据 | 图中表达 |
| --- | --- | --- |
| 职责归属 | 谁创建、持有、修改和关闭资源，谁负责业务状态 | 职责分组与资源管理关系；连线接实际责任组件 |
| 执行线程 | 提交、执行、收集、状态更新与回调交付各由谁调度 | 节点或连线旁的线程说明；需要展开时使用执行角色节点 |
| 存储边界 | 对象驻留位置、持久化介质、生命周期与实际共享范围 | 进程对象放在进程框内；磁盘目录、文件和远端存储放在对应介质或服务边界中 |

执行器仅承载任务调度时，创建、持有和关闭关系仍从负责资源的组件发出。若组件通过工厂创建对象，分别标明「组件调用工厂」和「工厂创建对象」。例如控制组件在 Worker 上创建采样器，管理连线从控制组件指向采样器，Worker 作为操作的执行位置。

内部异步工作按业务职责归组。事件收集、结果转换等属于某个组件时，在该组件的职责分组内展开，或标明所属组件的执行角色；有实际公共服务职责时才归入公共基础设施。涉及协程、流或回调时，分别核对上游执行、事件收集、状态更新和回调交付的调度位置，再写线程标签。

进程框只包含驻留其中的对象。存储客户端、访问组件和句柄可放在框内，持久化文件、目录与远端数据库放在进程框外，并标明「使用」「读写」或有依据的管理关系。应用归属视图可将应用拥有的组件与存储放在同一应用边界内，边界标题须明确表达应用归属。

默认目录派生、自定义路径、跨实例复用或独占写入影响本图含义时，就近保留配置条件。用列对齐或使用关系表达实例与目录的对应关系，独占与共享范围以实际配置和生命周期合同为依据。归属修正须同时检查分组、节点位置、连线端点、配色与说明。

加载、显式释放与自动回收关系从实际发起者或负责组件发出，资源状态作为动作结果。后续请求从真实入口进入。跨阶段保留的状态明确写入者、持有者与读取者；初始化、复用、更新和释放只在来源支持且本图需要时展开。已有状态名和资源名保持一致。

验收时核对一个资源的管理责任和实际出现的操作端点。数据流涉及跨阶段复用时，继续追踪实际写入与读取路径；只有归属关系的架构图无需增加时间轴。

### 配置与实现差异

适用范围：需要比较或切换后端、平台、输入场景、版本或运行配置。先分开相互独立的维度，例如输入类型与执行后端，确认哪些组合属于本图范围。新增组合会改变图意而材料无法确定时向用户澄清。

| 证据层次 | 可以表达的结论 |
| --- | --- |
| 源码或已确认设计支持 | 在注明的条件下具有该能力；需要保留启用条件 |
| 配置选择 | 请求或环境选择了该路径；实际执行仍按调度或运行证据核对 |
| 本次实际执行 | 指定版本、配置与样本实际经过的操作或测量结果 |
| 尚未核实 | 保留待确认内容及其影响，不能写成已执行或不支持 |

相同功能操作保留稳定标识、名称与共同说明；差异集中在实际变化的执行者、融合、存储、复制或结果条件。融合能力、满足触发条件和本次实际融合分别核对。操作顺序依据当前目标实现，不能直接套用另一入口、平台或教材中的过程。

场景图需要让读者看清发起者、处理组件、输出与调用方用途。同一请求往返默认返回原调用方。按生命周期阶段重复对象时标明阶段并保持身份一致；独立实例另有依据。共同名称在主图、局部图、说明和生成源中同步，配置切换后指标只显示对应证据，复用其他场景数据时就近注明来源与限制。

验收选择本次修改涉及的代表性配置，核对共同操作没有改名或改变含义，主图、明细与指标的差异范围一致。图稿审阅不自动扩大为后端全组合实验。

### 交互与分享

适用范围：已有或用户明确要求展开、切换、跳转、动画或独立分享。默认静态 HTML 继续保持静态；普通文件交付核对内嵌资源即可。

- 展开内容承接父节点的输入、处理和输出，标题注明所属对象。完整链路是阅读目标时，主线保留在主视图。
- 跳转明确关联对象，进入局部图后能返回原来源与焦点位置。已有配置切换时，主图、明细、高亮、指标与动画跟随当前配置；切换后原对象不适用时明确说明，不留下上一配置内容。
- 已有历史导航时检查前进与后退。链接和控件可通过键盘到达，焦点可见，交互控件放在静态 `role="img"` 图形之外。
- 动画注明表达依赖顺序还是实测时间；教学演示按依赖组织，不暗示未经验证的真实并行与耗时。响应减少动态效果设置，保留全部内容与操作结果。
- 用户要求独立分享时，复制并改名后打开交付 HTML，检查实际导航、展开和所需资源。运行功能不得依赖原工作目录、临时服务或本机绝对路径；外部来源链接只承担资料查阅，并说明访问条件。

生成文件的修改回到实际生成源，再重新生成。设计约定、事实证据、图稿和生成源按目标仓库结构维护，术语、标识与来源引用同步；简单图无需新增生成器或固定数量的配套文件。

验收覆盖实际存在且受修改影响的阅读路径与交互。分别报告结构检查、代理走读、浏览器实测与用户测试；未执行的检查保留为未验证。

## Skill 的执行流程

以下动作由调用 Skill 的绘图代理执行。阶段产物用于支持绘图判断，不要求额外保存中间文件。

| 阶段 | 动作 | 预期结果与检查 |
| --- | --- | --- |
| 确定问题 | 读取请求、目标文件、来源材料与已确认决定，核对项目约定，明确对象、动作和影响范围 | 先查材料；仍有会改变图意或修改范围的缺口、歧义或冲突时才询问 |
| 整理事实 | 核对关键组件、归属、实例和关系来源，区分实际对象、条件与说明 | 每条关键关系都有依据；未确认内容不能冒充现状 |
| 确定表达 | 先选图类型，再按触发条件选专项；按节点身份确定粒度、颜色维度和样式 | 架构单元、功能操作与数据身份清楚，专项未扩大到不适用场景；复杂粒度先用代表性局部校准 |
| 选择布局 | 确定层、并列区域、共同边界与连线通道，按真实关系设置箭头和图例 | 外部轮廓稳定，同层对齐；上下位置有阅读依据，不从依赖方向直接推导；图例默认在视图内容框外的下方左侧纵向排列 |
| 绘制或更新 | 复用模板、匹配的布局示例或目标文件已有样式，安排坐标、文字与连线 | 生成完整 HTML；脚本生成时从节点矩形推导端点与标签；文案修改只涉及文字和必要排版；仅改文字颜色时保持模块背景与边框 |
| 几何检查 | 运行只读检查脚本，修复错误并判断警告和跳过项 | 返回可定位的诊断；不把支持范围外的内容算作通过 |
| 渲染与交付 | 在可用浏览器中检查实际显示，修复问题并复看受影响区域 | 关键文字与关系可读，实际图意与文字边界另经复核，说明验证范围和剩余缺口 |

HTML/SVG 中来自输入的文字必须正确转义，避免 `<`、`>`、`&` 等字符改变结构。SVG 提供 `role="img"` 和能概括图意的可访问名称。独立图形使用唯一的 marker ID；复制图形后，绘图代理同时更新箭头引用。

浏览器不可用时，绘图代理仍可检查 HTML/SVG 结构并交付草稿，但明确写出「未完成浏览器视觉验证」，并说明实际完成的离线复看范围。结构有效、截图文件生成成功或 DOM 尺寸正常都不能单独证明布局可读。

模板中的示例使用通用组件，并明确标为示例。两个入口横向并列，下接与主体同宽的编排层；业务执行区与工具适配区顶底对齐，公共基础设施在底部横向排列。示例通过预留的层间、列间和两侧通道展示汇合、条件分支和事件回传。示例中的组件与关系只演示绘图方法，不成为具体项目的默认事实。安装包不依赖本机绝对路径、外部项目或临时材料。

Skill 实现者按以下顺序实施或维护：

1. 读取本文，确认模块配色、图形含义、布局规则与验收要求。本文是模板和视觉语法的设计依据，无需寻找外部参考 HTML。
2. 根据本文的参数表、字体栈和箭头定义制作可直接打开的通用模板，加入前述示例，不引入在线静态资源。
3. 编写 `SKILL.md` 与视觉语法参考，保证包内相对引用成立，保留正常的自动匹配能力。
4. 完成下面的结构检查与代表性绘图验证，修复本次实现引起的问题，再更新仓库功能导航。

实现任务不包含自动安装、发布或 Git 历史操作。常规坐标与文字换行由实现者根据实际渲染结果调整；涉及职责、实例归属或关系含义的未知信息，按事实边界处理。

当前工具只固化已有反复出现的坐标计算和检查，不提供通用布局求解器、配置语言或多格式渲染引擎。简单修改可以直接编辑 HTML，不要求每张图先写 JSON。安装包工具只用 Python 3 标准库；手绘、交互式图编辑器、多格式导出和内嵌字体不属于本次扩展；用户明确要求或已有的阅读交互按专项规则维护。

### 布局示例与坐标来源

分层示例提供共同边界、层内卡片及编号标签；并列工作流示例提供统一基线和短交接线；回路示例将条件路径放在所属分组内的独立通道；嵌套示例展示父模块浅底、子模块继承与同组职责统一填色；场景示例展示调用方、同一调用方的请求与返回、性能归属、本期工作与验收条件。绘图代理按图意选择并修改，不把示例中的顺序、依赖或重试当成实际项目事实。模块及附属信息遵守示例内的模块映射，不按行号或职责名称换色。

生成脚本只定义一次节点矩形，从矩形边界求连线端点，再从线段求标签候选位置。最长线段的中点可作为候选，但绘图代理仍须检查文字尺寸、标题和其他线段。多回路须统筹端口与通道顺序；独立通道不保证无交叉。脚本和手工绘图都不能因容量不足截取节点、隐藏正文或自动缩到不可读字号，应增加空间、换行或拆图。

多视角示例用虚构报告导出演示业务、工程与算法对应，一个工程操作展开为三个算法操作，并以模拟数据展示完整请求、累计批次及包含关系。连续数据流示例固定存储列，展示跨阶段读写、别名与文件写入。两例均声明图类型、范围和启用的专项。

色板校准示例使用七种模块主色，以相同面积、相同内容呈现外层浅底、内部组件背景和职责区填色。色名只标识色值，不分配实际模块；维护者用它比较明暗主题及灰度下的边界和文字，再将调整放回完整布局复核。

主模板仍是固定样式的唯一维护来源。维护者修改模板或生成脚本后，在新目录重新生成示例，比较结果并只替换需要更新的包内 HTML；生成文件的修改必须回到生成源。最终 HTML 可独立打开，不依赖脚本或仓库路径。

### 自动检查的范围

`check_diagram.py` 接收 HTML 或独立 SVG，返回 `code`、`severity`、`path`、`message`、`fix` 和必要的几何位置。错误阻止机器检查通过，警告需要绘图代理判断。检查覆盖 SVG 结构与引用、显式矩形卡片越界和覆盖、正交连线越界、穿卡片、内部交叉、共线重叠，以及箭头末段长度和已绑定标签的锚点距离。标签通过 `data-edge-label` 关联连线 ID，图例使用 `data-legend="true"`。

末段长度和标签距离的默认提示阈值为 `18`、`48` 个 SVG 用户单位，可按实际字号与显示比例调整。这些阈值只帮助筛查，不构成视觉合格标准。有意汇合通过共同端点表达，端点接触和重叠仍需人工确认，不能把所有交点都当成错误或一律忽略。

检查器只处理绝对 `M/L/H/V` 路径、正交 `polyline`、`line` 和未变换的矩形。曲线、相对路径、变换等会报告跳过；CSS 几何覆盖、嵌套 SVG、字形回退、真实文字边界、穿字、标签含义、背景避让和浏览器宽窄屏显示须另行复核。`ok: true` 只表示没有检出的错误，必须同时阅读诊断与覆盖范围，不能替代视觉验收。工具不会修改输入或自动删除冲突元素。

维护者在 Skill 目录运行 `python3 -B -m unittest discover -s tests -v`，再复看新生成的明暗示例。穿标题、编号缺少动作描述、长中文与英文标识、双回路和标签归属混淆，另按工具参考中的输入做视觉与语义复核；不以固定措辞匹配代替判断。

### 实绘反馈如何进入设计

Skill 维护者先区分反馈中的架构事实、用户指定的视觉约定和当前案例的布局选择。架构事实在案例中核对；视觉约定同步到本文、视觉语法和必要的模板样式；布局选择提炼为带适用条件的判断，不把一次上移或下移写成全局规则。

维护者将可复用结论写入对应设计章节和执行检查，并补充能暴露原问题的代表性输入。`SKILL.md` 保留绘制顺序与关键检查，通用规则留在视觉语法，类型与专项细则分别维护。修订已有规则时替换冲突表述，不只在验证记录末尾追加要求。模板已有能力满足修订时，核对后复用。

## 验证与验收

Skill 实现者先用可用的 skill-creator 校验工具检查 frontmatter 与包格式，再检查包内相对链接、调用名称，以及是否残留仓库外的资源路径或在线静态资源请求。预览依赖宿主可用的浏览器。校验工具缺失时执行等价的格式检查，并说明未运行原工具；格式检查不替代绘图行为验证。

模板默认浅色主题与提供的深色主题都需要实际渲染。绘图代理在宽屏和窄屏下检查文字、箭头、图例及滚动容器；窄屏允许图内横向滚动，不能因此裁掉内容或让页面其他部分异常溢出。检查重点是遵守本文的视觉约定并保证最终可读性。

绘图代理为每张图选择一个符合主要问题的阅读任务，例如「从请求入口追到结果返回」或「找到资源持有者与关闭责任」。按最终显示尺寸，仅依靠图内内容走读一次，记录需要猜测归属、寻找远处标签或查表重建主线的位置并修正。涉及总览与局部视图时同时检查进入和返回路径。交付说明区分代理走读与实际用户测试。

共享样式或配色修改后，绘图代理单独复核浅色、深色与灰度效果：先用同尺寸样例比较各色，再检查整图的模块边界、填色层次、核心文字及暖色辨识，关注大面积底色是否意外主导阅读。灰度下仍能通过名称、包含关系、线型与标签识别图意和布局。

绘图代理先缩小看完整构图，检查主要层和并列区域的轮廓、阅读重心、对齐与空白。然后按实际显示尺寸阅读节点、条件与图例，追踪主要关系，最后检查箭头、边界及遮挡。连线检查覆盖线与线、线与文字、线与边框的关系，包括箭头末端，并区分有意汇合与非预期交叉。绘图代理还须逐条确认标签归属唯一、动作与对象可直接读懂，编号含义明确。没有溢出或遮挡，只说明通过了几何检查。

重排任务在相同显示宽度下对照改前、改后版本，确认层与分组更容易辨认，关键关系仍清楚。画布变短不单独构成改进；为了压缩高度而缩字、塞满区域或拉长回路线，仍须调整。

绘图代理分别判断图意、视觉效果和结构是否通过检查。图意检查按选定类型覆盖职责与协作、任务推进或数据去向，并检查已触发专项；视觉复看覆盖层次辨识、整图轮廓、留白和实际阅读；结构检查覆盖越界、碰撞、ID 与引用。交付时说明检查方法与缺口，不以其中一项通过替代其他检查。

图中涉及资源、线程或存储时，图意检查还须分别追踪资源管理组件、操作所在执行线程与持久化介质。绘图代理核对创建、持有和关闭关系的端点，确认线程标签与调度代码一致、进程框内只包含驻留对象。归属修正后，代理复核分组、节点位置、连线端点、配色和说明是否共同表达新的判断。

更新或简化后，绘图代理还须对照原图，确认读者仍能识别任务分组、协作者、交接条件与结果，并能分清执行触发条件和各角色的职责。节点更少、连线更短不单独构成改进；若读者需要从脚注重建原本清楚的主线，绘图代理应恢复相应节点与关系。

绘图代理逐个检查独立节点的关系或分组归属，确认局部说明有明确对象，全图约束未占用流程节点的位置。绘图代理还须沿主线核对改变执行顺序、准入或终止结果的条件；这些条件必须在图中可见，不能只留在图注中。

绘制后，绘图代理逐项对照用户要求，核对要求是否在正确模块中通过节点、关系或说明表达，状态与适用场景是否就近可见。有明确依据的遗漏直接补齐。核对按本图展开层级进行，不为每项要求强制新增节点；只在说明中提及能力却遗漏对应模块表达时，代理按已有依据补齐。

| 能力已明确纳入某模块的候选路线，图中只在说明里提及 | 代理在对应模块中补齐表达，保留候选状态与采用条件，不重复询问已明确的要求 |
| 「合并两块」既可能指页面分区，也可能指图内阶段 | 代理先用现有标题定位；仍有歧义时说明选项与影响，只暂停依赖答案的修改；仅合并页面分区时保留图内关系 |

| 已确认精简的图稿根据最新文档更新，并调整页面分区 | 同步事实变化，保留已确认的信息粒度和删除项；验证覆盖整个 HTML 的标题、间距、图注、图例与滚动，披露浏览器检查缺口 |
| 主图已精简，图下仍有完整路线表与验证细则 | 整页保留图意、目标和评测摘要，完整细节链接至来源；关键条件仍在对应位置 |
| 同级节点的名称、分组与连线已说明作用 | 可只保留标题，信息粒度与排版一致，没有重复解释；必要条件与状态保留 |
| 模板和示例重新生成 | 图例位于视图内容框外，直接使用页面背景并纵排；色块在前，实际使用的关系样例在后 |

| 块内说明沿用通用职责清单 | 改为当前场景核心作用，保留动作、对象、输出用途和必要条件；核心解释不降成辅助文字 |

| 不同输入或运行状态的数据用于比较 | 适用范围、统计口径和单位明确；实测、估算与目标分别标明，代表点和已测范围有依据 |

| 进程访问默认目录，也允许自定义路径并供后继实例复用 | 访问组件与持久化目录分开；目录在进程框外，配置条件与实际共享范围可辨认 |
| 源码包与架构职责并非一一对应，且支持组件与共享能力同色 | 架构大框按职责、协作与资源归属划分，源码名称作为次级定位标识；支持组件按服务对象和管理责任归组，共享能力按真实依赖连接；源码与构建视图明确组织维度 |
| 已有图中增加一个较长的组件标识 | 原有内容保持正确；新增文字不溢出；相关连线避开文字，其他图例保持一致 |
| 新建总览图及对应模块图，包含工具适配和公共基础设施 | 同一组件跨图配色一致；独立主色与继承范围符合已确认映射；明暗主题均能区分区域、边框和正文 |
| 新建图或重新配色，包含多个尚未定色的大模块 | 优先考虑淡橙、淡黄与淡红，暖色在主要区域可见；同一模块及其附属信息同色，已确认映射保持稳定；没有通过加深底色或按卡片轮换颜色增加暖色 |
| 调用方应用、编排组件、计算引擎及引擎性能信息同时出现 | 大模块主色可区分；同一模块在输入、结果及关联视图中同色；性能和优化工作沿用所属模块主色；模块映射有说明，未按粗分类把应用和引擎都涂成蓝色 |
| 公开入口、内部契约、编排、适配与公共设施同时出现，且未指定模块映射 | 先按架构身份及本图问题建立模块映射；内部对象默认继承，职责名称不会自动决定主色 |
| 父模块、继承配色子模块及不同职责共存 | 父模块浅底、继承子模块统一背景，职责区同色系统一填色；按架构证据确定模块边界，卡片边框清晰 |
| 为单个子模块临时换色，理由仅为独立接口或内部职责较多 | 恢复继承；只有已确认映射或针对多个同级模块的统一配色才允许独立主色 |
| 公开 API 的结果回调接口与 IPC 通道同时出现 | 回调接口和传输通道按实际模块映射着色，回传箭头沿用关系色，线程说明不改变模块归属 |
| 适配实现同时实现接口并依赖共享实现 | 实现箭头从实现方指向接口，依赖箭头从使用方指向共享实现；位置服务于分层阅读，不将两类目标强制放在同一层 |
| 已采用纵向图例和前后对照页的图，只调整模块色 | 颜色和图注同步，布局、关系与纵向图例保持；改前视图保留；以相同显示宽度复看 |
| 同时出现择一分配、初始化创建与业务调用 | 分叉就近说明选择条件或数量；各类关系的触发时机可区分，未将选择画成广播 |
| 构建机制与实际依赖目标同时出现，且外框和卡片重复描述同一对象 | 依赖仍指向实际目标；机制单独表达；仅保留提供不同边界或归属信息的外框 |
| 长期所有者持有按请求创建的短期对象，主调用绕行外沿 | 创建者、持有者和实例范围明确；主关系优先获得直接通道，辅助组件未挤占主线 |
| 分组发起调用、内部组件接收回调，调用出口与内部卡片上下对齐 | 调用出口与回调入口分别对应实际责任主体；调用线未被误读为从内部卡片延伸，也未引入长绕线或虚构节点 |
| 已知组成的层被压缩成只有标题或标签串的横幅 | 展开有依据的组件卡片，保留名称及必要说明；卡片数量随真实组成变化，不虚构、重复或无依据地拆分组件填满空间；属性仍用标签，归属明确的卡片不强行补线 |
| 同时包含组件、执行角色、交接文件与阶段说明 | 每张图的问题与层级明确；混合类型有标签；辅助细节不挤占主要节点，必要条件仍可就近找到 |
| 简化包含多条工作流与独立核查的既有图 | 工作流分组、独立协作者、交接条件与结果仍可沿图追踪；外部依赖不挤占主线，未因类型不同而删除关键角色 |
| 依赖连线原先在有色区域内绕行 | 调整后通过相邻节点或空白通道连接；无穿越无关区域、贴边重合或压在背景下隐藏的线段 |
| 多条侧边回路互相交叉，箭头挤在短促转角上 | 端口与通道顺序消除非预期交叉，末端直线足以辨认方向；真实关系未被合并或删除 |
| 主线穿过分组标题，标签远离线段或漂在卡片下方 | 先调整标题与留白，主线仍易追踪；标签紧邻具体线段且归属唯一，局部条件没有移入全图说明 |
| 编号标签混用动作、API 名和表格索引，部分通道狭窄 | 同类标签结构一致；图内可读懂动作与对象，实现信息按需要分行；编号含义明确，文字不缩小或挤入转角 |
| 层宽反复收放、中央长链或底部偏置节点的既有图 | 在相同显示宽度下比较，外部轮廓与关键基线更稳定；必要关系和实际依赖范围保持正确，未用空节点填补留白 |
| 凭据验证被画成游离说明，但验证结果决定是否继续处理 | 验证接入主线；有效凭据指向复用结果，绕过后续处理；验证失败不被擅自解释为自动重试 |
| 局部只读说明与全图运行约束都被画成独立卡片 | 只读说明归入对应角色或紧邻角色；全图约束移到图下，必要的入口与分支条件仍在图中；不为消除孤块编造关系 |

更新图稿时，绘图代理先核对事实变化，并沿用当前图稿已确认的简洁程度、信息粒度和删除项。来源文档仍保留的细节不自动恢复到图中；新增事实仅补充理解变化所需的信息。新事实与已确认的图意或范围冲突时，按事实冲突规则处理。删除项适用于同一图稿的后续更新，不固化为其他图的全局删除规则；用户已撤回的方案不再作为默认依据。

验证范围跟随修改对象。节点或文字修改后，绘图代理检查卡片排版与相关连线；页面分区或容器修改后，还须在浏览器中复看整个 HTML 的标题层级、间距、图注、框外图例与滚动。离线 SVG 复看只覆盖图形本身，不能完成页面组织效果的检查。绘图代理随后复看整图及同组图的术语、标签结构、文字颜色、字号、图例和模块映射，复用未受影响且仍有效的检查结果。

这些验证使用临时输出，不覆盖用户输入的图。实现者检查事实来源、节点与边界、箭头起止位置、文字遮挡、重复 SVG ID、图例一致性和来源说明。修正后复看受影响区域及整图，不只检查改过的路径。文件由脚本或模板生成时，实现者修改实际生成源并重新生成，确保后续生成保留修正。实现者只在相关内容改变、检查失败或仍有具体未解决问题时扩大验证，不用固定措辞匹配代替对图意的判断。
