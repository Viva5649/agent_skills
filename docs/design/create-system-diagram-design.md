# create-system-diagram 设计方案

状态：已在仓库实现，并根据实绘反馈修订信息层级、职责配色、协作表达、整图版式与连线避让规则。验证范围见文末。本文供实现、审阅或维护本 Skill 的人理解绘图方法、视觉约定与验收标准。

Skill 名称为 `create-system-diagram`。本文完整定义绘图方法、样式参数和实现要求，实施者无需读取外部项目中的架构图。首次阅读按章节顺序理解规则，制作模板时查阅「固定视觉样式」，交付时查阅「验证与验收」。

## 目标与范围

本 Skill 根据用户提供的代码、文档或已有图，创建、更新和检查可独立打开的 HTML/SVG 系统图，覆盖架构分层、模块关系、职责协作、局部流程与数据流。图应让读者看懂组件职责、归属边界、主要调用和必要的运行条件，并保持一组图的视觉一致性。

默认采用本文的固定色板和图形样式。绘图代理根据图要回答的问题选择布局，保留项目已有术语。用户指定其他风格时遵从用户要求；没有指定时不随机生成配色。

第一版覆盖整体分层、模块内部结构、多入口汇合、并列分支，以及不同职责的对照。图中可以局部表达处理步骤，但完整时序图、状态机、交互式编辑器、自动布局引擎和批量导出工具不在第一版范围内。

安装包在 `skills/create-system-diagram/` 维护。设计文档留在 `docs/design/`，不成为安装包的运行依赖。

## 绘图方法与布局选择

默认产物为静态 HTML 内嵌 SVG，不使用 JavaScript。CSS 定义可复用的颜色、文字和图形样式，SVG 使用显式坐标安排节点与连线。绘图代理先确认图要回答的问题，再选择下表中的布局；不同布局可以组合。

| 布局 | 主要回答的问题 | 组织方式 |
| --- | --- | --- |
| 整体分层 | 谁调用谁，模块归属哪里，对外提供什么 | 按抽象层次纵向分层，横向排列同层模块，共享组件按实际依赖安排 |
| 模块内部结构 | 调用怎样进入功能域，功能域依赖什么 | 主路径纵向展开，功能域分类排列，侧面补充适配组件 |
| 多入口汇合 | 多个入口在哪里汇合，状态由谁持有 | 并列入口，共同运行区域，独立的请求与回传箭头 |
| 并列分支 | 同一入口下的不同运行方式有何区别 | 统一入口后分列，每列展开对应组件或有依据的步骤 |
| 职责对照 | 两个职责面有何区别，又复用了什么 | 左右排列职责，分别标注实例与存储，下方说明实现复用 |

布局中的位置只负责组织阅读。调用、执行顺序、实例共享和进程归属必须分别有事实依据，并通过明确的边界、标签或连线表达。重排后，绘图代理逐条确认关系的真实起止对象。构建、解析、依赖替换等机制单独表达，不能代替实际依赖目标；分组本身是关系对象时，连线才可连接分组边界。

每张图只回答一个主要问题，展开深度以回答这个问题为准。总览优先展示参与者、职责、主要依赖与产物归属，局部流程展示关键协作。属于同一任务的组件、执行角色和产物可以共同出现，须标明类型与关系。需要多个视图时，绘图代理分别写明各图的问题，避免重复铺开同一组细节。

绘图代理先确定主次信息，再分配面积与文字。主要节点保留名称、定位所需的标识和简短职责；维护资料、完整文件名、字段约束与长说明放到邻近注释或来源链接。影响实例归属、授权、可选路径或失败结果的条件仍须紧邻对应关系。辅助资料不能仅因内容多而获得与主架构相同的视觉权重。

授权、另行请求等决定能否执行的前提，应在执行入口处用醒目文字或条件标记表达。绘图代理分别标明文件交接与执行触发，保留读写箭头的真实方向，不能只依赖卡片内的小字区分自动执行与另行发起。

简化必须保留解释任务如何完成的工作流分组、关键协作者与交接条件。例如初稿经过独立核查和裁定修复才形成最终报告，这些关系属于主线内容，不能仅移入脚注。绘图代理按工作流组织相关节点，将外部依赖放在使用节点附近，不为凑齐网格打散归属，也不为缩短连线删除关键关系。

分叉须明确表示择一、并行还是广播。择一路径在分叉处突出选择条件或数量，可使用条件线区分候选路径，不能仅靠远处注释解释多条相同实线只会走一条。

创建、初始化与业务调用同图时，绘图代理按事实标明初始化时、每次请求或满足条件时触发的关系，并配合清楚的图例。只有初始化时发生的创建关系，不能被读成每次请求的必经步骤。

### 按信息职责选择表达

绘图代理先判断信息在图中的作用，再决定是否画成独立节点。重要信息可能是参与者、条件或约束，不能统一装进同一种卡片。

| 信息类型 | 表达方式 | 例子 |
| --- | --- | --- |
| 实际组件、执行角色、工具或产物 | 使用节点，通过真实关系或明确分组表达归属 | 处理组件、校验工具、交接文件 |
| 决定流程走向的条件 | 接入主线，标明条件分支及结果；仅限制入口时使用入口条件标记 | 凭据有效时直接复用产物，绕过后续处理 |
| 解释某个节点或关系的局部说明 | 放进对应节点或紧邻对象，以次级文字表达 | 只读权限、实例创建方式 |
| 适用于整张图的约束 | 放到图下说明或表格，保留适用范围和责任角色 | 整次运行的状态保护与恢复要求 |

局部解释使用卡片时，绘图代理明确所说明的对象，并降低视觉权重。独立节点应有清楚的关系或分组归属；发现孤立节点时，代理先核对信息类型，不为消除孤块编造连线。全图约束中的某项若决定具体分支或执行入口，代理仍在对应位置保留必要条件，详细规则可放图下。

## 输入、输出与事实边界

绘图代理开始工作时，先从用户请求和输入材料确定图的读者、要回答的问题、范围及事实版本。用户要求当前架构时，代理核对范围内的生产调用、接口和配置；用户要求根据指定设计稿绘图时，代理按设计稿表达，并标明设计状态。

关键节点和关系需要来源。绘图代理应能回答以下问题，不要求为每次任务额外生成固定格式的清单：

- 节点表示模块、类型、运行实例、存储，还是解释文字？
- 节点属于哪个应用、进程、隔离环境或职责分组？
- 箭头表示调用、依赖、回传、安装还是其他关系？谁是起点，谁是终点？
- 关系在什么条件下成立？当前已启用、可选与尚未接入生产是否已区分？
- 哪些信息由代码或文档确认，哪些仍未知？

绘图代理不能用布局填补事实缺口。输入冲突影响边界、实例归属或关系方向时，代理先说明冲突并询问用户，暂停依赖该结论的绘制。代理可以继续整理已确认的部分。字号、间距、折线路径等常规排版由代理自行决定。

默认交付一个 HTML 文件，内嵌样式与 SVG。文件包含标题、图例、必要说明和事实来源或版本；同一文件内需要多张图时，每张图的 SVG 标识符必须唯一。用户指定输出路径时使用该路径，否则按目标仓库文档约定命名和存放。

交付说明提供文件链接、验证结果和未确认项。只有用户要求时才另行提供独立 SVG、图片或 PDF，不默认增加额外产物。

## 固定视觉样式

### 色板与主题

整体风格为低饱和度区域背景、彩色边框和清晰的正文。浅色主题使用深色文字，深色主题使用浅色文字。模块颜色表示主要职责，不表示重要程度、部署位置或运行状态。

绘图代理在绘制前按「对象 → 主要职责 → 样式类」确定主要区域的映射。职责分类决定颜色，事实关系决定箭头，布局决定位置。名称相似不代表职责相同；同一职责的对象可以同色，不按层号轮换颜色。若同色使本图需要比较的职责难以辨认，代理先检查分类是否过粗，再按下表修正。

| 主要职责 | 固定颜色 | 典型对象 |
| --- | --- | --- |
| 公开能力与业务计算 | 蓝色 | 公开 API、业务服务、推理执行器、计算模块 |
| 编排与协调 | 紫色 | 工作流、任务编排、请求路由 |
| 契约与规则约束 | 绿色 | 内部能力接口、扩展协议；鉴权、隐私保护、策略校验 |
| 工具与能力适配 | 琥珀金色 | 工具集合、插件、能力适配器 |
| 隔离执行 | 红色 | 沙箱、隔离运行时 |
| 通信与传输 | 青色 | 进程间通信、网络传输、消息通道 |
| 公共基础设施 | 橙色 | 通用配置、日志、存储基础组件 |
| 辅助说明与中性分组 | 灰色 | 注释、解释卡片、无职责归类的外围分组 |

绘图代理按节点的主要职责选择颜色。同一组件在总览图与模块图中保持一致；子组件承担独立职责时，可以使用对应职责的颜色。专门的通信组件即使被多个模块复用，也使用青色；通用日志与配置组件使用橙色。远程部署或位于外部边界，不会使组件自动变成红色。

公开能力入口与内部契约分别表达：对外提供业务能力的入口使用蓝色，规定内部实现必须遵循的能力接口或扩展协议使用绿色，具体适配实现使用琥珀金色，公共设施使用橙色。内部契约使用 `role-contract`，鉴权、隐私保护与策略校验继续使用 `role-governance`；两者共用绿色色板，具体职责由名称和分组标明。公开入口与内部契约同时出现时，分别检查边框、标题、背景和接口标签的配色。

新建图默认采用这套映射。用户明确指定的配色优先；更新已有图且用户未要求重配时，沿用目标文件已明确的颜色含义，新增节点遵守同类节点的配色规则。

调整配色时，绘图代理沿用模板色值，同步修改边框、标题、背景、标签及颜色说明。有对照页时只同步新版视图，保留改前视图作为比较依据。

### 图形与含义

| 图形 / 样式类 | 表达什么 | 绘制约束 |
| --- | --- | --- |
| 大虚线边框 `boundary` | 应用、进程或隔离环境 | 边框旁写明具体边界；职责分组不能冒充进程边界 |
| 浅色区域 `frame` | 模块或职责分组 | 嵌套表示有依据的归属，同色区域可以持有不同实例 |
| 卡片 `card`、`mini` | 组件、执行角色、产物或局部解释 | 局部解释明确所说明的对象，不能作为调用者；全图约束放在图下 |
| 小标签 `chip` | 模块名、接口、状态或发布属性 | 图例说明当前图采用的含义；技术标识保持准确 |
| 标记 `pill`、`step` | 能力标记、真实步骤 | 只在标记能帮助阅读时使用；状态归属编号不转换成步骤 |
| 横条 `band` | IPC、HTTPS 等通信通道 | 标明协议和跨越范围，按真实调用绘制穿越横条的箭头 |
| 连线 `edge` | 有方向的关系 | 箭头指向具体目标，标签说明必要条件，线型与图例一致 |

模块标签跟随模块职责色；状态标签根据本图图例单独选择颜色，并始终写明状态。状态标签的颜色不改变所在模块的职责色。

混合节点类型时，绘图代理用简短文字标明组件、执行角色、文件或产物等实际类型，复用已有文字或标签样式，不另建一套颜色映射。同一视图中同类节点的标识方式一致。组件图中的节点保持稳定对象含义；执行阶段在局部流程中展开，不能让一个节点同时表示完整组件和组件内部的某个步骤。

卡片内的职责说明应与卡片主体一致。其他角色负责的收尾动作，绘图代理应放在对应角色或产物说明中，并写明执行者，避免读者因卡片包含关系误判职责归属。

区域颜色与连线样式分别编码职责和关系。例如蓝色区域表示核心业务与计算，蓝色箭头表示主要调用，两者不要求一一对应。

| 连线样式类 | 颜色 | 线宽 / `stroke-dasharray` | 默认关系含义 |
| --- | --- | --- | --- |
| `k-flow` | 蓝色 | `2` / 实线 | 主要调用 |
| `k-alt` | 琥珀金色 | `2` / `7 4` | 条件分支或替代路径，注明触发条件 |
| `k-event` | 青色 | `1.8` / `2 4` | 事件或异步回传 |
| `k-plain` | 中性连线色 | `1.6` / 实线 | 一般关系，以标签或图例声明是依赖、安装等哪种关系 |
| `k-cfg` | 中性连线色 | `1.6` / `6 4` | 本图明确声明的可选关系或未接入关系 |
| `k-fail` | 红色 | `2` / 实线 | 失败或拒绝结果 |

绘图代理在图例中说明实际使用的关系含义。同一图内一种连线样式只能承担一种已声明的含义。可选关系与未接入关系同时出现时，必须通过不同样式和明确标签区分，不能合并成一个含糊图例。没有使用的连线类型不需要出现在图例中。

图例默认放在图下左侧，每行一个箭头样例和对应说明，逐项纵向排列。各行的箭头起止位置、文字起点与行距一致，行距可从 `26–28` 个 SVG 用户单位起步；不将图例分散成横向多列。用户另有指定时遵从指定。

箭头使用与连线同色的实心三角形。marker 的 `viewBox` 为 `0 0 10 10`，三角形路径为 `M0,0 L10,5 L0,10 z`，`refX="9"`、`refY="5"`、`markerWidth="7"`、`markerHeight="7"`、`orient="auto-start-reverse"`。连线默认无填充，箭头引用本图独有的 marker ID。

### 整图骨架与对齐

绘图代理先确定完整的层、并列区域和辅助区，安排共同左右边界与连线通道，再放组件。分层图优先让连续层共享外沿；并列区域优先顶底对齐，内部关键内容共享水平基线。列宽按信息量分配，不要求所有卡片等宽。对齐只组织阅读，不增加归属、调用或执行顺序。

共享代码的位置结合本图的抽象层次和实际依赖安排，并与具体适配实现分别表达。接口契约与公共实现承担不同职责，不因都被依赖就放在同一抽象层。依赖箭头从使用方指向被依赖方；运行调用、接口实现与模块依赖分别标注，不把上下位置画成未经确认的执行顺序。

「被依赖」只确定依赖关系的目标，不决定目标在上方还是下方。例如，以能力实现为主线的分层图可将接口契约放在适配层上方，将适配器使用的共享实现放在下方；实现关系向上、模块依赖向下。这是有适用条件的布局选择，不是所有共享组件的固定位置。

整图外部轮廓保持稳定，内部按内容变化。连续层应避免在全宽、中央窄块和侧边孤块之间反复收放。上下层列数不同时，绘图代理用层的共同外沿保持连续，在各层内部调整网格。辅助依赖可放在对应列底部或对齐的辅助横排；共享设施仍按实际使用范围标明关系，不能为了铺满底部暗示所有组件都依赖它。

留白用于区分层级、分组和容纳连线。出现一条中央长链、两侧大片空白，或底部只剩偏置节点时，绘图代理优先尝试层内横排、相邻辅助列或拆分视图。必要关系须保留；空节点和过大的无内容边界不能用于凑齐轮廓。

### 几何、字体与信息密度

默认 SVG 的 `viewBox` 宽度为 `1400`，高度按内容确定。页面最大宽度为 `1400px`，水平居中。页面内边距按上、右、下、左设置为 `24px 16px 32px 16px`。每张图下方预留 `40px`，标题与图之间预留 `14px`。

SVG 默认设置 `display: block; width: 100%; min-width: 1040px; height: auto`，外层图形容器设置 `overflow-x: auto`。窄屏在图形容器内横向滚动。绘图代理按用户指定尺寸和实际阅读效果调整最小显示宽度；缩放后难以阅读时，先精简信息、增大显示宽度或拆图，不通过不断缩小字号塞入内容。

| 文字层级 | 默认字号 | 字重与颜色 |
| --- | --- | --- |
| 页面标题 | `22px` | `700`，正文色 |
| 组件标题 | `15px` | `700`，正文色 |
| 模块标题 | `14px` | `700`，模块主色 |
| 小卡片标题 | `12.5px` | `700`，正文色 |
| 通信横条标题 | `13.5px` | `700`，青色 |
| 正文、说明与代码标识 | `12px` | 正文色；辅助说明使用辅助文字色 |
| 连线标签与紧凑标签 | `11.5px` | 辅助文字色；需要突出关系时使用对应连线色 |
| 两行连线标签的动作主行（可选） | `12.5px` | `600`，沿用连线色；次行使用普通连线标签样式 |
| 步骤编号 | `10.5px` | `700`，等宽字体；圆形使用正文色，编号使用页面背景色 |

页面标题使用 CSS 像素；图内字号、圆角、线宽与间距使用 SVG 用户坐标。绘图代理检查缩放后的实际文字大小，必要时增大显示宽度或拆图。模块框圆角默认 `10`，卡片为 `8`，标签为 `5`。模块框与通信横条边框为 `1.5`，卡片与标签边框为 `1`。边界框不填充，边框使用中性连线色、线宽 `1.5`、虚线 `7 5`。这些参数作为模板起点，列宽、行高和间距随内容调整。

一张图选用少量重复的尺寸。以 `1400` 宽画布为例，外边距可从 `20`、区域内边距从 `16–20`、相邻卡片间距从 `16–24`、普通层间通道从 `40–56` 个 SVG 用户单位起步。这些数值是排版起点；分支或双向线需要更多空间时，绘图代理局部调整并复看整体。卡片高度按短标题、标题加一行说明等内容类型复用，同类文字保持一致的起点和行距。

区域表达模块或职责分组，卡片展示层内可识别的组件及简短职责，标签表达标识、属性和状态。在本图展开范围内，有明确组件的层应展开具体卡片，不能为紧凑把组件结构压缩成只有标题或标签串的空横幅。接口本身是需要展示的独立对象时，绘图代理也使用卡片；仅作为其他组件的属性时使用标签。

卡片数量以真实组成为准，不强求每层同样多或固定为三列。组件较少时，绘图代理调整列宽、间距和留白；不要虚构、重复或无依据地拆分组件来填满空间，也不把属性或说明凑成组件。组件的层内归属足以表达组成，不要求每张卡片都有独立连线。关键信息、条件和角色归属仍按信息职责规则保留。

外框必须增加模块、职责或实例归属信息。外框与唯一子卡片若表示同一对象、重复同一说明，绘图代理保留一种表达；确有不同边界含义时可以嵌套。完整分组不要求每个辅助机制都占一条全宽层，也不能靠重复包框代替组件展开。

正文和代码分别使用以下字体栈：

```css
--font-body: "Noto Sans SC", "PingFang SC", "Hiragino Sans GB", "Microsoft YaHei", system-ui, sans-serif;
--font-mono: "JetBrains Mono", ui-monospace, "SF Mono", Menlo, Consolas, monospace;
```

模板不请求在线字体。本机缺少首选字体时使用后续字体，绘图代理在实际字体环境下检查文字宽度，不能假设不同字体等宽。

### 连线通道与端点

绘图代理根据本图要回答的问题，先为主要关系安排相邻节点和直接通道，再放创建、管理等辅助关系及其组件。辅助关系是否属于主线由图意决定，不能为辅助卡片让路而迫使主线绕完整图外沿。卡片之间预留连线通道，优先使用水平、垂直折线；请求与回传分开走线。长说明按信息职责安排，不能仅因篇幅长就将关键条件移出图。长标识通过加宽或明确分行处理，不依靠截断或压缩字符宽度隐藏内容。

分组内部的协作线可在分组内直接连接相关节点。跨区域连线优先连接相邻节点：绘图代理先让线段从端点侧就近离开所属区域，再沿区域之间的空白通道走线，在目标侧就近进入。背景色较浅也不等于空白通道：连线不能穿过无关的职责区域，或借有色区域内部绕行。连接所属区域内的节点时，可以保留必要的短距离穿入或穿出。

直线通道与分组标题、说明冲突时，绘图代理先调整文字位置、换行或留白，不默认让主线绕过文字。全图说明可移到图前或图注，局部条件仍紧邻对应关系。端点离边界过远、需要绕过大半张图或只能穿越背景时，绘图代理优先移动依赖节点、调整分组范围或拆分视图，再安排路径。

多条线共用侧边空白时，绘图代理统筹端口顺序和通道位置，让长短回路分层嵌套，避免横向接入段切过其他竖线。调整后仍保留真实端点、方向与关系，不合并独立关系制造汇合点，也不把线压到背景下面隐藏交叉。折线最后一段须有足够的直线长度，让箭头方向容易辨认；箭头挤在短促转角上时，调整接入侧、端口或通道。线段和箭头均与边框、标题、卡片保持可见间距。

分组与内部组件承担不同关系时，绘图代理须通过端点位置区分责任主体。例如，分组发起调用、内部组件接收回调时，调用出口位于分组边界，回调接到实际组件。若出口位置使调用线看起来由内部卡片发出，绘图代理应局部调整卡片宽度或端点，保留短路径和既有分组；不能仅靠标签解释，也不为走线增加虚构节点。

### 连线标签与编号

标签须紧邻具体线段，让读者唯一确定标签归属。水平线的标签在对应线段上方或下方居中；竖线的标签放在线的一侧，左侧文字向右对齐，右侧文字向左对齐。绘图代理将多行标签作为整体定位，保持共同对齐边、稳定行距和可见的线文间距。标签不能漂在卡片下方，也不能因避让文字而远离对应线段。

动作型标签先说明「动作 + 对象」，必要时补充目标。API、实现方式或局部条件作为第二层信息；需要同时表达动作与实现时可分成两行，同类标签采用一致结构。例如主行「读取通用配置」，次行「配置接口 · 只读访问」。模板用可选的 `edge-operation` 突出主行，次行沿用 `edge-label`；单行已足够时不凑第二行。标签过长时，绘图代理扩大局部间距、调整端点或明确分行，不靠远移标签或不断缩字解决。

使用 `M1` 等编号时，绘图代理在首次出现处或图注说明编号表示索引、阶段还是执行顺序。作为索引时，主行采用「编号 · 动作 + 对象」，不只写编号或 API 名；同一编号用于多个分支时，用具体对象区分。容量、证据和完整限制可放在表格，图内仍须说清主要关系与必要条件。编号不是所有图的必备元素，查表也不能成为理解主线的前提。

## 架构含义的表达规则

**共用实现与共用实例分别表达。** 例如两个应用都使用 `PolicyEngine` 实现，但分别创建实例并持有存储。图中应在两个应用边界内分别绘制实例与存储，并用说明标注「复用同一实现」。绘图代理确认节点代表的对象后再决定能否合并；同名类、同色区域或同一源码模块都不足以证明共享运行实例。运行实例图还须标明短期对象的创建者、持有者与实例范围，例如按请求、会话或任务创建。绘图代理将短期对象放在对应所有者分组内或用明确关系关联，避免将短期对象误画成全应用共享实例。

**位置不自动表示执行顺序。** 并排可以表示职责比较，纵向可以表示分层或内容组织。绘图代理只有在来源支持步骤关系时才加顺序标记或连接箭头。例如「状态 A 由请求对象持有、状态 B 由执行器持有」表达状态归属，不应画成先 A 后 B 的执行步骤。

**包含不自动表示调用。** 把卡片放进区域只表达归属。绘图代理分别核对归属关系和调用关系，不为了让图看起来连贯而补线。

**图中的条件必须保留。** 绘图代理在适当位置保留运行模式、可选路径、未接入状态和关键失败结果。例如两个节点都执行策略校验，其中一个会拦截请求，另一个只记录结果。两者都可以使用绿色，但必须标明行为差异。

**总览与细节按问题分工。** 总览保留主要边界与调用方向，模块图展开局部职责和必要约束。一张图同时承担过多问题时，绘图代理拆成相关视图，保持术语、配色与共同节点一致，不默认展开整个仓库。

## Skill 的执行流程

以下动作由调用 Skill 的绘图代理执行。阶段产物用于支持绘图判断，不要求额外保存中间文件。

| 阶段 | 动作 | 预期结果与检查 |
| --- | --- | --- |
| 确定问题 | 读取请求、目标文件与适用项目约定，确定读者、范围和事实版本 | 能用一句话说明本图要回答什么；缺少会改变目标的信息时先询问 |
| 整理事实 | 核对关键组件、归属、实例和关系来源，区分实际对象、条件与说明 | 每条关键关系都有依据；未确认内容不能冒充现状 |
| 确定表达 | 按信息职责选择节点、条件或说明，确定主要区域的职责与样式类 | 公开入口、内部契约、适配实现和公共设施能被区分；关键条件与说明各有明确对象 |
| 选择布局 | 确定层、并列区域、共同边界与连线通道，按真实关系设置箭头和图例 | 外部轮廓稳定，同层对齐；上下位置有阅读依据，不从依赖方向直接推导；图例默认在图下左侧纵向排列 |
| 绘制或更新 | 复用模板、匹配的布局示例或目标文件已有样式，安排坐标、文字与连线 | 生成完整 HTML；脚本生成时从节点矩形推导端点与标签；更新任务只改受影响部分 |
| 几何检查 | 运行只读检查脚本，修复错误并判断警告和跳过项 | 返回可定位的诊断；不把支持范围外的内容算作通过 |
| 渲染与交付 | 在可用浏览器中检查实际显示，修复问题并复看受影响区域 | 关键文字与关系可读，实际图意与文字边界另经复核，说明验证范围和剩余缺口 |

HTML/SVG 中来自输入的文字必须正确转义，避免 `<`、`>`、`&` 等字符改变结构。SVG 提供 `role="img"` 和能概括图意的可访问名称。独立图形使用唯一的 marker ID；复制图形后，绘图代理同时更新箭头引用。

浏览器不可用时，绘图代理仍可检查 HTML/SVG 结构并交付草稿，但明确写出「未完成浏览器视觉验证」，并说明实际完成的离线复看范围。结构有效、截图文件生成成功或 DOM 尺寸正常都不能单独证明布局可读。

### 布局示例与坐标来源

分层示例提供共同边界、层内卡片及编号标签；并列工作流示例提供统一基线和短交接线；回路示例将条件路径放在所属分组内的独立通道。绘图代理按图意选择并修改，不把示例中的顺序、依赖或重试当成实际项目事实。职责配色继续跟随组件职责，不按行号交替。

生成脚本只定义一次节点矩形，从矩形边界求连线端点，再从线段求标签候选位置。最长线段的中点可作为候选，但绘图代理仍须检查文字尺寸、标题和其他线段。多回路须统筹端口与通道顺序；独立通道不保证无交叉。脚本和手工绘图都不能因容量不足截取节点、隐藏正文或自动缩到不可读字号，应增加空间、换行或拆图。

主模板仍是固定样式的唯一维护来源。维护者修改模板或生成脚本后，在新目录重新生成示例，比较结果并只替换需要更新的包内 HTML；生成文件的修改必须回到生成源。最终 HTML 可独立打开，不依赖脚本或仓库路径。

### 自动检查的范围

`check_diagram.py` 接收 HTML 或独立 SVG，返回 `code`、`severity`、`path`、`message`、`fix` 和必要的几何位置。错误阻止机器检查通过，警告需要绘图代理判断。检查覆盖 SVG 结构与引用、显式矩形卡片越界和覆盖、正交连线越界、穿卡片、内部交叉、共线重叠，以及箭头末段长度和已绑定标签的锚点距离。标签通过 `data-edge-label` 关联连线 ID，图例使用 `data-legend="true"`。

末段长度和标签距离的默认提示阈值为 `18`、`48` 个 SVG 用户单位，可按实际字号与显示比例调整。这些阈值只帮助筛查，不构成视觉合格标准。有意汇合通过共同端点表达，端点接触和重叠仍需人工确认，不能把所有交点都当成错误或一律忽略。

检查器只处理绝对 `M/L/H/V` 路径、正交 `polyline`、`line` 和未变换的矩形。曲线、相对路径、变换等会报告跳过；CSS 几何覆盖、嵌套 SVG、字形回退、真实文字边界、穿字、标签含义、背景避让和浏览器宽窄屏显示须另行复核。`ok: true` 只表示没有检出的错误，必须同时阅读诊断与覆盖范围，不能替代视觉验收。工具不会修改输入或自动删除冲突元素。

维护者在 Skill 目录运行 `python3 -B -m unittest discover -s tests -v`，再复看新生成的明暗示例。穿标题、编号缺少动作描述、长中文与英文标识、双回路和标签归属混淆，另按工具参考中的输入做视觉与语义复核；不以固定措辞匹配代替判断。

### 实绘反馈如何进入设计

Skill 维护者先区分反馈中的架构事实、用户指定的视觉约定和当前案例的布局选择。架构事实在案例中核对；视觉约定同步到本文、视觉语法和必要的模板样式；布局选择提炼为带适用条件的判断，不把一次上移或下移写成全局规则。

维护者将可复用结论写入对应设计章节和执行检查，并补充能暴露原问题的代表性输入。`SKILL.md` 保留绘制顺序与关键检查，具体规则留在视觉语法中。修订已有规则时替换冲突表述，不只在验证记录末尾追加要求。模板已有能力满足修订时，核对后复用。

## 验证与验收

Skill 实现者先用可用的 skill-creator 校验工具检查 frontmatter 与包格式，再检查包内相对链接、调用名称，以及是否残留仓库外的资源路径或在线静态资源请求。预览依赖宿主可用的浏览器。校验工具缺失时执行等价的格式检查，并说明未运行原工具；格式检查不替代绘图行为验证。

模板默认浅色主题与提供的深色主题都需要实际渲染。绘图代理在宽屏和窄屏下检查文字、箭头、图例及滚动容器；窄屏允许图内横向滚动，不能因此裁掉内容或让页面其他部分异常溢出。检查重点是遵守本文的视觉约定并保证最终可读性。

绘图代理先缩小看完整构图，检查主要层和并列区域的轮廓、阅读重心、对齐与空白。然后按实际显示尺寸阅读节点、条件与图例，追踪主要关系，最后检查箭头、边界及遮挡。连线检查覆盖线与线、线与文字、线与边框的关系，包括箭头末端，并区分有意汇合与非预期交叉。绘图代理还须逐条确认标签归属唯一、动作与对象可直接读懂，编号含义明确。没有溢出或遮挡，只说明通过了几何检查。

重排任务在相同显示宽度下对照改前、改后版本，确认层与分组更容易辨认，关键关系仍清楚。画布变短不单独构成改进；为了压缩高度而缩字、塞满区域或拉长回路线，仍须调整。

绘图代理分别判断图意、视觉效果和结构是否通过检查。图意检查覆盖职责、归属、关系与条件；视觉复看覆盖层次辨识、整图轮廓、留白和实际阅读；结构检查覆盖越界、碰撞、ID 与引用。交付时说明检查方法与缺口，不以其中一项通过替代其他检查。

更新或简化后，绘图代理还须对照原图，确认读者仍能识别任务分组、协作者、交接条件与结果，并能分清执行触发条件和各角色的职责。节点更少、连线更短不单独构成改进；若读者需要从脚注重建原本清楚的主线，绘图代理应恢复相应节点与关系。

绘图代理逐个检查独立节点的关系或分组归属，确认局部说明有明确对象，全图约束未占用流程节点的位置。绘图代理还须沿主线核对改变执行顺序、准入或终止结果的条件；这些条件必须在图中可见，不能只留在图注中。

| 代表性输入 | 必须验证的结果 |
| --- | --- |
| 多入口、共享运行区域与异步回传 | 入口在正确位置汇合；请求和回传方向分别正确；状态编号未被误画成步骤 |
| 共用实现、独立实例和独立存储 | 节点未因名称相同而合并；职责区域、实例与存储归属明确 |
| 已有图中增加一个较长的组件标识 | 原有内容保持正确；新增文字不溢出；相关连线避开文字，其他图例保持一致 |
| 新建总览图及对应模块图，包含工具适配和公共基础设施 | 同一组件跨图配色一致；工具适配为琥珀金色，公共基础设施为橙色；明暗主题均能区分区域、边框和正文 |
| 公开入口、内部契约、编排、适配与公共设施同时出现 | 蓝、绿、紫、金、橙分别表达对应职责；边框、标题、背景、标签与说明一致；同职责对象仍可同色 |
| 适配实现同时实现接口并依赖共享实现 | 实现箭头从实现方指向接口，依赖箭头从使用方指向共享实现；位置服务于分层阅读，不将两类目标强制放在同一层 |
| 已采用纵向图例和前后对照页的图，只调整职责色 | 颜色和图注同步，布局、关系与纵向图例保持；改前视图保留；以相同显示宽度复看 |
| 同时出现择一分配、初始化创建与业务调用 | 分叉就近说明选择条件或数量；各类关系的触发时机可区分，未将选择画成广播 |
| 构建机制与实际依赖目标同时出现，且外框和卡片重复描述同一对象 | 依赖仍指向实际目标；机制单独表达；仅保留提供不同边界或归属信息的外框 |
| 长期所有者持有按请求创建的短期对象，主调用绕行外沿 | 创建者、持有者和实例范围明确；主关系优先获得直接通道，辅助组件未挤占主线 |
| 分组发起调用、内部组件接收回调，调用出口与内部卡片上下对齐 | 调用出口与回调入口分别对应实际责任主体；调用线未被误读为从内部卡片延伸，也未引入长绕线或虚构节点 |
| 已知组成的层被压缩成只有标题或标签串的横幅 | 展开有依据的组件卡片，保留名称与简短职责；卡片数量随真实组成变化，不虚构、重复或无依据地拆分组件填满空间；属性仍用标签，归属明确的卡片不强行补线 |
| 同时包含组件、执行角色、交接文件与阶段说明 | 每张图的问题与层级明确；混合类型有标签；辅助细节不挤占主要节点，必要条件仍可就近找到 |
| 简化包含多条工作流与独立核查的既有图 | 工作流分组、独立协作者、交接条件与结果仍可沿图追踪；外部依赖不挤占主线，未因类型不同而删除关键角色 |
| 依赖连线原先在有色区域内绕行 | 调整后通过相邻节点或空白通道连接；无穿越无关区域、贴边重合或压在背景下隐藏的线段 |
| 多条侧边回路互相交叉，箭头挤在短促转角上 | 端口与通道顺序消除非预期交叉，末端直线足以辨认方向；真实关系未被合并或删除 |
| 主线穿过分组标题，标签远离线段或漂在卡片下方 | 先调整标题与留白，主线仍易追踪；标签紧邻具体线段且归属唯一，局部条件没有移入全图说明 |
| 编号标签混用动作、API 名和表格索引，部分通道狭窄 | 同类标签结构一致；图内可读懂动作与对象，实现信息按需要分行；编号含义明确，文字不缩小或挤入转角 |
| 层宽反复收放、中央长链或底部偏置节点的既有图 | 在相同显示宽度下比较，外部轮廓与关键基线更稳定；必要关系和实际依赖范围保持正确，未用空节点填补留白 |
| 凭据验证被画成游离说明，但验证结果决定是否继续处理 | 验证接入主线；有效凭据指向复用结果，绕过后续处理；验证失败不被擅自解释为自动重试 |
| 局部只读说明与全图运行约束都被画成独立卡片 | 只读说明归入对应角色或紧邻角色；全图约束移到图下，必要的入口与分支条件仍在图中；不为消除孤块编造关系 |

这些验证使用临时输出，不覆盖用户输入的图。实现者检查事实来源、节点与边界、箭头起止位置、文字遮挡、重复 SVG ID、图例一致性和来源说明。修正后复看受影响区域及整图，不只检查改过的路径。文件由脚本或模板生成时，实现者修改实际生成源并重新生成，确保后续生成保留修正。实现者只在相关内容改变、检查失败或仍有具体未解决问题时扩大验证，不用固定措辞匹配代替对图意的判断。
