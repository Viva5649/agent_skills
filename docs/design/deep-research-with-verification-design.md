# deep-research-with-verification 设计

本 Skill 面向需要横纵分析研究、Markdown 交付和独立事实核查的用户。
用户于 2026-09-10 确认：完整复用 `hv-analysis` 的研究方法，不拆解重组研究流程，保留原有字数要求；仅覆盖交付格式，并在初稿完成后追加核查与修复。

## 已确认的契约

- 主 agent 读取已安装的 `hv-analysis` 并执行其研究流程，保留搜索策略、分析方法、写作风格、篇幅和非 PDF 质量要求。包装层不复制或改写原技能。
- 主 agent 将研究成果保存为 Markdown 初稿，跳过 PDF 环境准备、依赖安装、转换和排版检查。
- 初稿固定后，主 agent 创建两个独立核查 agent。两人分别核查完整初稿、联网取证，各写一份 Markdown 报告；不得读取对方结论或修改初稿。
- 两份报告完成后，主 agent 创建第三个独立 agent。第三人复核证据，裁定每条发现，修复真实问题及受影响的结论，输出最终研究报告与裁定记录。
- 三名核查 agent 均使用新上下文，不复用研究阶段的 agent。第三人按证据裁定，不能以两人一致代替证据。
- 默认执行一轮双人核查和一轮裁定修复。第三人复查改动及关联结论；无法解决的问题明确披露，不无限重启核查。
- 所有交付物均为 Markdown：初稿、两份核查报告、裁定与修订记录、最终研究报告。保留初稿与核查报告以便追溯。

## 依赖与边界

运行时规则位于 [SKILL.md](../../skills/deep-research-with-verification/SKILL.md)。执行环境需要可读取的 `hv-analysis`、联网工具和支持独立上下文的子 agent 工具。技能按当前环境发现依赖，不绑定作者机器的绝对路径，也不携带原技能副本。

主 agent 在研究前确认这些能力可用。核查 agent 完成全文检查并记录限制后，仍无法取证的陈述交第三人裁定；因中断而尚未检查的范围必须由原核查 agent 补齐，不能以“证据不足”替代未执行的检查。

“证据不足”不等于“事实错误”；明确标注且前提可靠的合理推断可以保留。核查不得成为重组研究方法或放宽字数要求的理由。依赖缺失、核查未完成或资料无法验证时，执行者报告实际状态，不能声称完整流程已经完成。

## 必要验证

- 使用 skill-creator 的 `scripts/quick_validate.py` 检查技能格式；人工检查包装层只覆盖输出格式并追加核查，没有重写研究方法。
- 使用独立 agent 做执行推演，覆盖正常交接、证据分歧和依赖不可用，检查角色隔离、文件所有权与结束条件。
- 执行推演不等于真实调研验收。真实运行需保存五份 Markdown，核对两个 agent 的独立取证、第三人的逐项裁定和最终修复；未实际运行时不得声称已完成端到端调研验证。
