# 高级信息检索

通过搜索、提取和交叉验证，为用户提供清晰、准确、可追溯的答案，或一篇结构化的主题调研报告。

## 触发判断

当问题依赖外部事实、最新信息、精确来源或多来源比较时，使用本 skill。若问题可以直接基于已有上下文回答，不必搜索。

## 模式判断

先判断用户要的是"回答一个具体问题"还是"就一个主题做一篇调研报告"：

| 用户输入特征 | 模式 |
|---|---|
| 有明确的问题边界，答案可以被验证对错（"XX 现在多少钱"“XX 和 YY 谁快”“XX 最新版本是什么”） | **问答模式**，见步骤 1-5 |
| 给一个主题/关键词，希望产出多角度、成体系的介绍或对比（"调研一下 MCP 协议”“帮我写一篇 XX 对比报告”“给我出一份关于 XX 的调研”） | **报告模式**，见"报告模式流程" |

不确定时，倾向报告模式——它涵盖问答模式的信息量，只是输出结构更长。

## 检索流程（问答模式）

### 步骤 1：理解问题并制定搜索计划

- 明确用户真正要找的信息。
- 拆出核心实体、时间范围、地域范围、指标和判断标准。
- 设计一个或多个搜索查询词。
- 若问题含糊且会显著影响搜索方向，先问 1 到 3 个澄清问题。

### 步骤 2：执行搜索

- 使用搜索工具检索。
- 优先选择官方来源、原始文档、权威媒体、论文、标准、公司公告或项目文档。
- 避免只依赖二手转载。

### 步骤 3：提取内容并深入分析

- 打开最可能包含答案的网页或文档。
- 阅读正文，判断是否直接回答问题。
- 记录关键事实、发布日期、发布机构和链接。

### 步骤 4：评估答案完整性

- 如果单个来源不足，继续搜索并补充来源。
- 对关键事实进行至少两个可靠来源的互相印证，除非已有原始来源。
- 对冲突信息说明差异和可能原因。

### 步骤 5：总结并确认答案

使用以下结构输出：

```markdown
## 结论
<直接回答用户问题>

## 关键信息
- <事实 1，注明来源>
- <事实 2，注明来源>

## 判断依据
- <为什么这些来源可信>
- <不同来源之间是否一致>

## 不确定性
<如果存在信息缺口、时间滞后或来源冲突，明确说明>

## 来源
- [来源名称](链接)
- [来源名称](链接)
```

## 报告模式流程

用于"就一个主题产出成体系调研内容"的场景。产出物是可以直接被其他技能（如站点发布类技能）二次加工的结构化 Markdown，而不是一问一答。

### 步骤 1：明确调研范围

- 识别主题涉及的核心实体（如果是对比类主题，列出所有待对比对象）。
- 明确时间范围、地域范围和用户关心的维度（如果用户没说，按主题常规维度自行判断）。
- 若主题范围模糊到会显著影响调研方向，先问 1 到 3 个澄清问题。

### 步骤 2：多轮多角度搜索

- 用 2-4 轮不同角度的搜索（如果是多实体对比，每个实体至少一轮）。
- 用 WebFetch 精读 3-5 篇最相关的原文。
- 来源优先级同问答模式：官方来源、原始文档、权威媒体、论文、标准、公司公告优先，避免只依赖二手转载。

### 步骤 3：综合成结构化 Markdown

将调研结果整理为 2000-4000 字的 Markdown，结构如下：

```markdown
# <标题>

<一句话摘要>

## 概述
<背景与核心问题>

## <分析章节 1>
<对比 / 优劣 / 流程等，按主题需要展开，可用表格>

## <分析章节 2>
...

## 结论
<综合判断或建议>
```

- 章节数量和标题按主题内容灵活组织，不必套用固定模板。
- 涉及多实体对比时，用表格或分点方式呈现，保持每个实体的信息完整、可比。
- 关键事实随文标注来源（行内链接或章节末尾来源列表均可）。

### 步骤 4：交付

直接输出 Markdown 全文（或写入用户指定的文件）。不需要额外附加"结论/关键信息/来源"这套问答框架。

## 质量标准

- 不确定时说不确定，不要编造。
- 最新问题必须确认发布日期。
- 高风险领域，如医疗、法律、金融，优先使用官方或专业机构来源。
- 问答模式：回答要先给结论，再给依据。报告模式：先给整体判断/摘要，再展开分析。
- 报告模式下，关键事实仍需可追溯来源，不因为不是问答格式就放松验证标准。
