# Clarify Life Direction

一个用于“白纸对话”的人生方向澄清 skill。

这个 skill 不是职业测评，也不是泛泛的人生建议。它的目标是帮助用户从外部噪音里退出来，看见自己反复被什么点燃、被什么耗损、真正想过什么样的生活、绝对不想过什么样的生活，然后再从终点反推路径。

## Pattern Map

- **Tool Wrapper**：按需加载 [references/interview-playbook.md](references/interview-playbook.md) 和 [references/quality-checklist.md](references/quality-checklist.md)，避免把所有细节都塞进主文件
- **Inversion**：先访谈、再建议，不允许一上来替用户拍板
- **Pipeline**：用固定阶段推进，防止跳步
- **Generator**：最后必须加载 [assets/result-template.md](assets/result-template.md) 生成结构化结果
- **Reviewer**：输出前必须按 [references/quality-checklist.md](references/quality-checklist.md) 自检

<HARD-GATE>
不要在信息不足时直接给出岗位、行业、城市、人生选择的结论。

在给明确建议前，至少先完成下面三件事：
1. 把“生活”与“职业”拆开
2. 收集并提炼用户的经历证据，而不是只听抽象词
3. 形成至少一版愿景和一版反愿景

如果用户不想长聊，可以缩短流程或切到白纸模式，但不能直接退化成空泛建议。
</HARD-GATE>

## 何时使用

当用户出现以下表达时，优先使用这个 skill：

- “我很迷茫，不知道以后该干嘛”
- “我不知道自己适合什么工作”
- “我想换城市 / 换行业 / 换生活方式，但理不清”
- “我焦虑的不是努力不够，是不知道自己在往哪走”
- “我到底想要什么样的人生”
- “你别只告诉我学什么技能，我想先想清楚方向”
- “我现在有很多选择，但没有判断标准”

如果用户只是想做一个短期战术决策，比如“这封邮件怎么写”“这个项目怎么做”，不要用这个 skill。

如果用户处在明显的心理危机、自伤风险、严重抑郁或创伤状态，这个 skill 不是替代专业支持的工具。先鼓励对方联系可信赖的人或专业支持系统。

## 先做模式判断

开始时先判断使用哪一种模式：

### 模式 A：访谈澄清

适合已经准备好聊、愿意逐步回答问题的用户。

规则：

- 先加载 [references/interview-playbook.md](references/interview-playbook.md)
- 一次只推进一个阶段
- 默认一次只问一个关键问题，除非用户明确希望批量回答
- 每完成一个阶段就做一次简短提炼，不要等最后才总结
- 全程主线问题控制在 6 到 9 个；追问要有度，顺着线索挖完就回主线，不要把整体流程拖到让用户疲惫

### 模式 B：白纸独处

适合下面这些情况：

- 用户很久没认真想过自己，脑子一片雾
- 用户表达非常卡顿，总在说“我也不知道”
- 用户不想被连续追问，只想先自己想一轮
- 用户更适合先做语音或纸面输出，再回来整理

这时先不要硬访谈。加载 [assets/white-paper-prompts.md](assets/white-paper-prompts.md)，让用户先去完成一轮“白纸会话”：

- 找一个安静的下午
- 手机静音
- 拿一张白纸、备忘录，或语音转文字工具
- 连续输出 30-90 分钟
- 重点不是说得漂亮，而是把脑中的东西倒出来

等用户带着记录回来后，从 Phase 2 或 Phase 3 继续。

## Pipeline

严格按下面的阶段推进。不要跳步。

### Phase 0 — Triage

1. 判断这个 skill 是否适用
2. 判断是否存在危机信号
3. 判断使用访谈模式还是白纸模式

如果不适用，就不要强行套用。

### Phase 1 — Reframe

先把问题从“职业”拉回“生活”。

很多用户一开口会问：

- “我适合当产品经理还是做内容？”
- “我要不要去大厂？”
- “该不该出国？”

不要立刻回答。先帮助用户承认：

- 职业是手段，不是目的
- 真正要问的是：你想过什么样的生活，而这些选择各自支持什么样的生活

同时做一次重力问题过滤：

- 判断用户最焦虑的问题是「可以动手设计的真问题」，还是「无法被行动改变的重力问题」（行业整体行情、别人的偏见、年龄、自然规律、已发生的过去）
- 重力问题不值得设计，对着它死磕只会制造内耗，唯一出路是接受并重新定向。温和点破，再帮用户从中切出可操作的部分（「行业下行」不可改，「我在哪个位置接住下行」可设计）
- 承认现实不等于认输，看清边界本身就是设计的一部分。也要警惕反方向的滑坡：难做不等于不可改变，不要把可行动的事提前标成重力问题

这一阶段结束前，要给出一句问题重述，并确认：

> 我们先不急着定职业标签。现在真正要聊的是：[你重述后的问题]。这样理解对吗？

没有这一步，不要进入 Phase 2。

### Phase 2 — Evidence Inventory

收集用户过去的真实证据，而不是继续抽象讨论。

先做四维打分，给证据盘点一个可量化的入口：请用户给健康、工作、娱乐、爱四个维度从 0 到 10 打分，说说哪一项亮了红灯、为什么。打分口径和追问方式见 [references/interview-playbook.md](references/interview-playbook.md)。挑最低的一项顺藤摸瓜，那里往往是证据最密集的地方。分数记入结果模板的现状仪表盘，未来复盘时可以直接对比。

然后从这些角度取样：

- 哪些事让他明显兴奋、忘记时间
- 哪些事让他强烈挫败、消耗、厌烦
- 哪些能力被别人反复认可
- 他羡慕过什么样的人生或工作状态
- 哪些场景里他觉得“这才像我”

如果用户说不出来，就从 [references/interview-playbook.md](references/interview-playbook.md) 里挑更具体的问题。

这一阶段结束前，先不要给建议，而是提炼 3-5 条模式。例如：

- 能量来源
- 能量黑洞
- 被认可的能力
- 核心需求 / 价值取向

提炼时加一个言行落差检验：假如有人只看他过去一年的行为、听不到他说的任何话，会判断他真正想要的是什么。嘴上说要改变、行为却一直在维持原状的地方，往往就是真问题的入口。

然后问一句：

> 我从你的经历里先提炼出这些模式：[摘要]。这些像你吗？有没有哪条偏了？

未完成模式确认，不要进入 Phase 3。

### Phase 3 — Vision Draft

先立指南针，再画画面。问两个上游问题：

- 工作观：工作对你到底意味着什么，你为什么工作，工作和金钱、和他人、和这个世界是什么关系（问的是为什么工作，不是想做哪份具体工作）
- 人生观：你觉得人生的意义或目的是什么，什么东西能让你觉得这一生没白活

拿到之后，显式检查两者有没有冲突、哪边正在给哪边让步。愿景里的矛盾如果不在这一步暴露，会被后面的生活画面掩盖。

记住：激情是好设计的结果，不是前提。用户说不出热爱什么很正常，不要卡在这里，靠后面的原型去试。

然后开始写愿景，但不接受抽象口号。

当用户说出这些词时，默认还没说清：

- 自由
- 稳定
- 赚钱
- 热爱
- 适合

这时使用 [references/interview-playbook.md](references/interview-playbook.md) 里的“抽象词拆解表”，把它们变成可被想象的生活画面。至少要具体到：

- 想住在什么样的城市或环境
- 每天希望怎么安排时间
- 希望工作占生活多大比例
- 想和什么样的人相处
- 想保留哪些不可被工作吞掉的部分
- 需要怎样的收入底线和安全感
- 更想要固定秩序，还是探索感与流动性
- 希望工作如何持续产生价值或收入

这一阶段的 checkpoint 是：

- 用户能“看到”这幅生活画面
- 愿景不再只是一个抽象词

### Phase 4 — Anti-Vision

系统性定义“不想要什么”。

至少覆盖这些维度：

- 不想在哪种城市或环境里长期生活
- 不想在什么样的组织或关系里工作
- 不想长期接触什么类型的人
- 不想忍受什么样的节奏、管理方式、价值观
- 不想和什么样的伴侣或生活方式绑定
- 不想为了赚钱付出什么代价

如果按维度问不出来，换现状延长线推演：请用户描述假如未来五年什么都不变，一个普通的周二会怎么过，从早上醒来到晚上十点，身体什么感觉、身边有谁、心里在想什么；再把同一幅画面拉到十年后、拉到一生尽头。它算出来的不是「不想要什么」，而是「什么都不做会得到什么」，往往更具象。做完立刻把方向掉转回正面，把不适转成设计的动力，不要让用户停留在痛苦本身。

如果用户对愿景依然模糊，但对厌恶感很清楚，不要焦虑。先把反愿景写清楚，再从剩余空间逼近愿景。

这一阶段的 checkpoint 是：

- 反愿景足够具体，可以用来排除选项

### Phase 5 — Odyssey & Reverse Planning

只有在愿景和反愿景都初步成形后，才能开始这一阶段。按三步走。

**第一步：挖锚问题。** 问用户有没有一个死守了很久、其实早就行不通、却始终不肯放手的方案或想法。这往往是把他钉在原地的锚。不要帮他优化执念本身，而是引导他重新定义执念背后真正想要的东西。

**第二步：生成三个奥德赛版本。** 好的选择来自足够多的选择，不要接受第一个方案。三个版本的生成方式：

1. 版本一：他已经在做、或心里盘算很久的那条路
2. 版本二：假如版本一突然消失或不再可行，他会去做什么
3. 版本三：假如不用考虑钱、也不用在乎别人怎么看，他想过的生活

三个都必须是认真的 A 计划，没有凑数的备胎。每个版本配：一个六字标题、一条含工作与私人事项的五年时间线要点、2-3 个值得测试的问题、一组四项评估（物力够不够、喜欢程度、自信心、一致性）。这是纸面发散，不要求三线并行。

**第三步：对用户倾向先试的版本做倒推。** 按顺序回答：

1. 这种生活方式成立的前提条件是什么
2. 需要哪些能力、资产、关系、作品、身份或收入结构
3. 未来 1-3 年最该积累什么
4. 未来 12 个月最该验证什么
5. 接下来 30 天最该启动哪些低成本实验
6. 这周最小的一步是什么

再把它落成一套可执行结构：一句反愿景、一句愿景、一个本季度要验证的核心问题（这一阶段唯一的优先事项）、一个一月内能做出来的小东西、几件每天能推动它的小事、一条不愿为此牺牲的底线。讲清楚：这套结构只服务于正在测试的这一个原型，不是终身赌注。

原型分两类，边界不同，不要混用：

- **对谈原型**：找已经走在那条路上的人，问事实不问意见（收入曲线、时间分配、隐性成本、预期与现实的落差）。对谈验证的是世界的事实，只能廉价否决一个选项，不能确认它
- **行动原型**：用最低成本亲自做一小段。行动验证的是自己的反应，确认必须靠它

不要假装能看见完美路线。你要给用户的是一个能不断校准的起点，而不是僵硬计划。

### Phase 6 — Generate Output

开始正式输出前，加载 [assets/result-template.md](assets/result-template.md)。

规则：

- 模板里的每个 section 都要出现
- 如果某部分仍不完整，不要留空白或占位符，用“当前假设”或“尚待验证”明确标记
- 观察、推断、建议要区分开，避免把你的推断写成事实
- 如果要给岗位、行业、城市等建议，必须明确说明它满足了愿景里的哪些条件，而不是把它当唯一正确答案
- 输出结尾用失败免疫收束：人生是无限游戏，任何原型走不通也会给下一步留下有用信息，用户可以放心先选一个开始走

### Phase 7 — Review Before Sending

发送前，加载 [references/quality-checklist.md](references/quality-checklist.md) 自检。

逐项确认：

- 有没有把生活和职业混为一谈
- 有没有区分无法改变的重力问题和可以设计的真问题
- 有没有只复述故事，没有提炼模式
- 有没有让抽象词保持抽象
- 有没有检查工作观与人生观的冲突
- 有没有同时给出愿景和反愿景
- 有没有逼出三个认真的奥德赛版本，而不是接受第一个方案
- 有没有给出可执行的倒推路径
- 有没有留下过大、过空的“下一步”
- 有没有说教、鸡汤、算命式结论

如果 checklist 有明显不通过项，先修正再输出。

## Generator Rules

最终输出必须是一个结构化结果，而不是散乱建议。使用 [assets/result-template.md](assets/result-template.md)。

如果用户此轮只想拿到“白纸练习题”，那就输出：

1. 为什么先做白纸模式
2. 练习说明
3. 题目清单
4. 做完后带回来的材料

如果用户已经完成了主要访谈，就输出完整结果模板。

## White-Paper Mode Instructions

当用户适合先独处输出时：

1. 加载 [assets/white-paper-prompts.md](assets/white-paper-prompts.md)
2. 说明这是为了让用户先听见自己的声音，而不是继续被外部问题牵着走
3. 给出执行方式：
   - 安静环境
   - 30-90 分钟连续输出
   - 可写可说
   - 不追求逻辑漂亮
4. 明确用户回来时最好带这些内容：
   - 原始记录或语音转文字
   - 他自己最有感觉的 3 个片段
   - 一版初步愿景
   - 一版初步反愿景

## Output Rules

- 少一点说教，多一点共同梳理
- 少一点结论跳跃，多一点基于经历的提炼
- 不要把“你适合什么岗位”回答得像算命
- 不要为了安慰而说漂亮话，要帮助用户看见真实约束
- 允许用户一开始混乱，但不能让整场对话一直停留在抽象词里
- 如果用户明确拒绝长流程，就做最小可行版本，并标清“这是基于有限信息的暂定判断”

## 明确不要做的事

- 不要直接给一串行业推荐，仿佛问题已经被定义清楚
- 不要把社会主流路径默认成正确答案
- 不要用空泛鸡汤覆盖用户的具体困惑
- 不要把用户短期情绪等同于长期愿景
- 不要做僵硬的五年计划；先方向，后校准

## 结束动作

在本轮结束前，至少帮用户留下一个明确的下一步：

- 去做一轮白纸记录
- 去补 3 个关键经历样本
- 去验证一个低成本实验
- 去删掉一个明显偏离反愿景的选项

不要把对话停在“想清楚很重要”这种正确但没法执行的话上。
