# 工具与布局示例

新建布局、编写生成脚本或运行几何检查时读取本文件。工具只使用 Python 3 标准库，不安装依赖，不启动浏览器。模板与示例均默认浅色，保留深色样式。

## 选择可编辑的骨架

| 示例 | 适用问题 | 复用内容 |
| --- | --- | --- |
| [连续分层](../assets/examples/layered.html) | 公开能力、编排与基础设施之间有什么关系 | 共同边界、层内卡片、直接通道、编号加两行标签 |
| [并列工作流](../assets/examples/parallel.html) | 不同任务各由谁处理、产生什么 | 工作流分组、同类基线、短交接线，模块及产物按归属配色 |
| [局部回路](../assets/examples/loop.html) | 检查结果如何决定交付或返回修正 | 正常路径与条件回路分开，回路有完整直线接入段 |
| [模块嵌套与职责分区](../assets/examples/nested.html) | 外层模块如何包含子模块，职责由谁承担 | 父模块浅底、子模块继承配色、同组职责统一填色，调用连接真实模块 |
| [场景能力与验收](../assets/examples/scenario.html) | 谁使用能力，性能属于谁，本期改什么，如何验收 | 请求与返回连接同一调用方，核心说明用正文色，当前值与目标分色，无箭头关联表达性能归属 |
| [固定色板与填色层次](../assets/examples/palette.html) | 各色的视觉强度与填色层次是否清楚 | 等面积、相同内容的七色校准样例；用于检查配色，不提供架构关系 |

示例只描述通用绘图场景，使用时替换标题、节点、关系、条件与图注。没有事实依据的默认关系必须删除；示例中允许返回修正，不代表实际项目也允许重试。组件多于示例时，调整布局或拆图，不能截取前几项或隐藏正文。

示例由 [render_examples.py](../scripts/render_examples.py) 生成。脚本从 [architecture-template.html](../assets/architecture-template.html) 读取 CSS、页面结构和 marker，避免维护另一套色板。需要重新生成时，在 Skill 目录运行：

```bash
python3 scripts/render_examples.py --outdir /tmp/architecture-examples
# 也可只生成一种：--layout layered、parallel、loop、scenario、nested 或 palette
```

目标文件已经存在时，脚本拒绝覆盖。维护者在新目录生成并比较后，只替换确认需要更新的包内示例。产物可独立打开，运行时不依赖生成脚本。

色板校准样例只改变所用色系，外框、内部组件和职责区的面积与文字保持一致。维护者在相同显示尺寸下比较浅色、深色与灰度效果，再复看完整布局，重点检查暖色是否过淡、某种浅底是否意外抢眼、核心文字和边界是否清楚。主色继续表达模块身份；调整浅底和职责区时，不用统一透明度或对比度数值代替视觉判断。

## 复用坐标计算

生成脚本中的节点记录包含 ID、矩形位置与尺寸、模块样式类及文字。`port(box, side)` 从矩形求边界端点；`edge(...)` 用端点和明确的中间点生成路径。`label_anchor(...)` 从最长线段选择候选位置，水平线在上方居中，竖线按指定侧对齐。移动节点后重新计算端点与标签，不再分别手写三套坐标。

这些函数是可复制修改的示例，不是任意图的布局求解器。分组、列宽、主路径、回路顺序和中间点仍由绘图代理根据图意安排。多回路须统筹长短顺序，分配不同通道仍可能交叉。两行标签按整体定位；候选位置与标题、卡片或其他线冲突时，调整位置并复看，不机械采用最长线段的中点。

`card(node, tinted=True)` 为独立配色的组件或产物使用模块浅底，继承配色的内部组件保留统一卡片背景。只有卡片本身表达模块身份时才传 `module_title=True`，内部组件及产物标题保持正文色。块内核心说明使用 `body-text`，辅助说明才使用 `note`。`frame(..., style="frame frame-inherited")` 绘制继承配色的子模块容器；`style="annotation"` 绘制附属说明区；中性场景分区使用 `annotation` 和 `section-title`。`body` 为空时，`card(...)` 只绘制居中标题；同级入口示例采用这种表达。`legend(...)` 生成 `figure` 后的 HTML 图例，先列模块色块，再列关系样例，说明文字统一使用次级文字色；图例位于内容框和图形横向滚动容器外，不另加背景框。修改归属时按视觉语法的「填色与边框」选择，保留约 `2px` 的卡片边框。

模板的 `module-*` 类只定义示例内的模块映射，使用 `--module-color`、`--module-bg`、`--module-chip`，职责名称不绑定固定颜色。`group-neutral` 表达跨模块分组或中性资料。各示例独立构造架构，颜色只在对应示例内适用；复用到同一组实际图时重新确定统一映射。

嵌套示例以虚构的资料检索系统展示模块包含与职责归属。两个子模块都继承橙色，内部职责共用一档较明显浅色，没有按职责顺序逐级加深。实际模块判定仍须核对身份、职责、协作和包含依据，不能直接复制例子的分组结论。

场景模板中的「资料应用」「索引服务」均为虚构组件，所有数值均为模拟数据。实际使用时替换组件、指标、来源、本期工作与验收条件，不携带真实项目资料。资料应用用淡红色，索引服务及其性能、工作和验收说明沿用橙色；指标卡、列表和验收条件区分信息用途，指标名称和当前值用正文色；目标数值及比较符号用 `metric-target` 局部橙色加粗，保留「目标」标记。查询与更新分别成对标注，返回线接回原调用方。普通交接使用中性箭头，性能归属使用无箭头的 `k-association`。

## 运行只读检查

```bash
python3 scripts/check_diagram.py <图文件.html>
```

输入可以是含内嵌 SVG 的 UTF-8 HTML，也可以是独立 SVG。工具不改输入，输出 JSON；发现 `error` 时退出码为 `1`，否则为 `0`。诊断包含 `code`、`severity`、`path`、`message`、`fix`，必要时包含交点或距离。`path` 使用 SVG 序号与元素 ID 定位问题，无 ID 时退回元素位置。

| 自动检查 | 范围与判断 |
| --- | --- |
| SVG 与引用 | XML 结构、viewBox、文件内重复 ID、marker 与可访问名称引用 |
| 卡片 | `rect.card`、`rect.mini` 的越界与相互覆盖；分组外框不当成组件卡片 |
| 连线 | 带 `edge` 类的绝对 `M/L/H/V` 路径、正交 `polyline` 和 `line`；检查越界、穿卡片及不同连线内部交叉 |
| 共用通道 | 共线重叠作为警告，交点恰为线段端点的接触仍需人工检查；有意汇合应明确拆分到共同端点 |
| 箭头末段 | 带 `marker-end` 的折线末段短于阈值时提示；不测量实际 marker 的像素轮廓 |
| 标签锚点 | 按 `data-edge-label` 绑定的连线计算距离，检查空标签；距离不等于真实文字边界或可读性 |

为连线设置 ID，为每个标签文字绑定对应连线；多行共享同一连线 ID。模板中的 HTML 图例独立于主图，其符号不计入主图连线。若另用 SVG 文字绘制图例，使用 `data-legend="true"` 避免误报为缺少关系绑定。主图标签绑定示例：

```html
<path id="read-config" class="edge k-plain" d="M350,504 V640" />
<text class="edge-label k-plain" data-edge-label="read-config"
      x="366" y="570">读取通用配置</text>
```

没有绑定的标签会报告 `unbound_label`，不会通过猜测把最近的箭头当作目标。现有图可先运行检查，再补充受影响标签的绑定，不必为了局部修改重写整张图。

末段长度提示默认 `18`、标签锚点距离提示默认 `48`，单位均为 SVG 用户单位。它们是筛查起点，可用 `--min-entry`、`--max-label-distance` 调整；改变阈值须符合实际字号和显示比例，不能只为消除警告。

**检查结果必须连同覆盖范围阅读。** `ok: true` 只表示支持范围内没有检出的错误。`coverage` 列出 SVG、连线、已检查连线与标签数量，以及跳过项。曲线、相对路径、坐标变换等未支持内容会提示跳过。CSS 覆盖几何、嵌套 SVG、真实文字边界、字形回退、穿字、标签语义和背景避让不在自动检查范围内；这些内容见输出的 `manual_checks`，继续用真实渲染复核。

## 维护时验证

```bash
python3 -B -m unittest discover -s tests -v
```

[测试](../tests/test_diagrams.py) 覆盖交叉回路、共线重叠、有意汇合、短促折弯、穿卡片、标签偏移、引用错误、未支持几何的披露、坐标随节点移动、色板样例等面积，以及所有示例的结构检查和图例位于内容框外的回归检查。修改共享样式或生成脚本后，重新生成示例，对照明暗主题并检查实际显示尺寸；不能只更新生成的 HTML。

另用下列输入做视觉与语义复核，机器检查不能代替这些判断：

| 输入变化 | 应验证的结果 |
| --- | --- |
| 同样的组件用于主流程和职责对照 | 主流程的入口、处理与结果连续，职责对照的同级对象视觉权重相近；按对应阅读任务走读，修正猜归属和查表才能读懂的位置 |
| 总览进入局部图，页面已有跳转或展开 | 保留共同名称、主色与有助于阅读的相对关系，局部注明所属模块；键盘可操作并能返回来源位置 |
| 修改色板或放大职责区面积 | 用等面积样例比较明暗与灰度，再检查整图；模块边界、暖色、填色层次与核心文字可辨认，主色不承担临时强调 |
| 改小显示宽度、放大基础字号或浏览器缩放 | 按实际字号读图，SVG 文字与几何同步调整，文字完整、焦点可见、图内可滚动；已有动态效果遵守减少动态效果设置 |
| 标签没有重叠，但离自己的线段和模块太远 | 同组更近、跨组更清楚，读者能直接确定文字归属；通过邻近与留白修正，保留真实关系 |
| 将全部标题设为模块色，或把核心解释降为灰色 | 模块身份与内部组件分开选样式，核心说明用正文色，灰色仅用于辅助信息及图例 |
| 请求与返回混用时机、动作或用途 | 同组标签维度及顺序一致，动作与对象或场景与载荷完整，返回关系连接实际调用方 |
| 增加优化目标、局部耗时或里程碑 | 目标局部橙色加粗，当前值及模块背景不变；耗时有起止点，里程碑与组件动作通过无箭头关联对应 |
| 用户确认外部能力，仓库中只有接入代码 | 按确认呈现外部现状，观测字段仍核对实际生产者，未亲验范围在交付说明交代 |
| 继承配色的子模块增加接口、运行进程或内部职责 | 主色继续继承；独立配色须有已确认映射，或基于本图问题为一组同级模块统一制定 |
| 父模块、子模块和职责分区同时出现 | 模块边界有架构依据，父模块保留浅底，继承子模块使用统一背景，同组职责统一填色 |
| 将验收说明因规则职责改为绿色 | 恢复所属模块配色，通过或失败结果在局部状态标签表达 |
| 将场景图拆成调用、性能和验收视图 | 发起者与结果用途完整，本期工作未遗漏，共同组件名称和颜色一致 |
| 同一请求被拆为调用方与结果方，性能区移到远处 | 返回原调用方并保留结果用途；性能归属仍能辨认，注释关联没有调用箭头。生命周期阶段展开才按需重复节点并标明阶段 |
| 用局部测量推导上限，或把方案目标写成基线 | 恢复已测范围和数据性质，单位、配置与统计口径明确，未确认标准保留待确认 |
| 长比较结论或本期工作挤入卡片 | 保持正文层级，按语义换行并调整空间，同组图的同类文字一并复看 |
| 资源创建与关闭被画成从 Worker 发出，实际由控制组件负责 | 管理关系接到控制组件；任务调度另行标明；工厂调用与对象创建可区分 |
| 将组件内部的事件收集放入公共设施，且上游与收集线程不同 | 收集工作归回所属组件；线程标签逐段对应实际调度位置 |
| 将磁盘目录画入进程框，并与进程内存储客户端合为一个节点 | 客户端与持久化介质分别表达，读写关系和配置、复用条件保留 |
| 把分组标题移到竖直主线处 | 调整标题或通道，保留清楚的直线关系，不用底色遮住穿字 |
| 将两行标签移到相邻另一条线附近 | 标签仍能唯一对应所属连线；机器距离通过也要复看 |
| 将「R1 · 提交查询」改成只有「R1」或 API 名 | 恢复动作与对象，编号含义明确，主要内容无需查表 |
| 增加很长的中文组件名、英文标识和必要条件 | 内容完整、实际字号可读；扩大、换行或拆图，不隐藏正文或自动缩字 |
| 增加第二条返回不同目标的回路 | 统筹端口与通道顺序；独立通道不作为无交叉的证明 |

只有用户请求时才增加其他输出格式。浏览器或离线渲染不可用时披露缺口，不以结构检查通过宣称完成视觉验证。
