# 系统图视觉语法

本文件定义布局选择和图形含义。具体色值、字体及样式由包内 [HTML 模板](../assets/architecture-template.html) 提供，复制模板后复用，不凭描述重新配色。

## 按问题选择布局

| 布局 | 要回答的问题 | 组织方式 |
| --- | --- | --- |
| 整体分层 | 谁调用谁，模块归属哪里 | 按抽象层次纵向分层，同层模块横向排列，共享组件按实际依赖安排 |
| 模块内部结构 | 入口如何进入功能域，功能域依赖什么 | 主路径纵向展开，功能域分类排列，侧面补充适配组件 |
| 多入口汇合 | 多个入口在哪里汇合，状态由谁持有 | 并列入口，共同运行区域，请求与回传独立走线 |
| 并列分支 | 不同运行方式使用哪些组件 | 统一入口后分列，每列展开组件或有依据的步骤 |
| 职责对照 | 两个职责面有什么区别，复用什么 | 左右列出职责、实例及存储，另外说明实现复用 |

可组合布局，但每张图保持一个主要问题，展开深度以回答这个问题为准。总览保留参与者、职责、主要依赖和产物归属，局部流程展示关键协作；属于同一任务的组件、执行角色和产物可以共同出现，须标明类型与关系。不要为图形连贯而补出不存在的调用。

需要可运行的骨架时，使用[工具与布局示例](tools-and-examples.md)中的分层、并列工作流或局部回路示例。布局适用性由分组和真实关系决定，不按组件数量硬套。容量不足时调整或拆图，不截取列表、隐藏正文或用自动缩字容纳全部内容。

先确定主次再分配面积。主要节点保留名称、定位所需标识和简短职责；维护资料、字段和长说明放到注释或来源链接。实例归属、授权、可选路径和失败条件仍须紧邻对应关系，辅助内容不与主体争夺同等空间。

授权、另行请求等决定能否执行的前提，使用入口旁的醒目文字或条件标记表达。文件交接与执行触发分别标明，保留读写箭头的真实方向；不要只依赖卡片内的小字区分自动执行与另行发起。

简化时保留能解释任务如何完成的工作流分组、协作者与交接条件。例如独立核查和裁定修复决定报告如何形成，属于主线内容，不能仅移入脚注。按工作流组织相关节点，外部依赖放在使用节点附近；不为凑齐网格而打散归属，也不为缩短连线删除关键关系。

## 按信息职责选择表达

先判断信息在图中的作用，再选择节点、条件标记或说明；重要程度本身不决定是否使用独立卡片。

| 信息类型 | 表达方式 | 例子 |
| --- | --- | --- |
| 实际组件、执行角色、工具或产物 | 使用节点，通过真实关系或明确分组表达归属 | 处理组件、校验工具、交接文件 |
| 决定流程走向的条件 | 接入主线，标明条件分支及结果；仅限制入口时使用入口条件标记 | 凭据有效时直接复用产物，绕过后续处理 |
| 解释某个节点或关系的局部说明 | 放进对应节点或紧邻对象，以次级文字表达 | 只读权限、实例创建方式 |
| 适用于整张图的约束 | 放到图下说明或表格，保留适用范围和责任角色 | 整次运行的状态保护与恢复要求 |

局部解释使用卡片时，必须明确所说明的对象，视觉权重低于主体。独立节点应有清楚的关系或分组归属；发现孤立节点时先核对信息类型，不为消除孤块编造连线。全图约束中的某项若决定具体分支或执行入口，应同时在对应位置保留必要条件，详细规则可放图下。

分叉须明确表示择一、并行还是广播。择一路径在分叉处突出选择条件或数量，可使用 `k-alt` 区分候选路径；不能仅靠远处注释解释几条相同实线只会走一条。

创建、初始化与业务调用同时出现时，按事实标明初始化时、每次请求或满足条件时触发的关系，并配合清楚的图例。只有初始化时发生的创建关系，不能被读成每次请求的必经步骤。

## 默认职责配色

绘制前按「对象 → 主要职责 → 样式类」确定主要区域的映射。名称相似不代表职责相同；同一职责的对象可以同色，不按层号轮换颜色。若同色使本图需要比较的职责难以辨认，先检查分类是否过粗，再按下表修正。

| 主要职责 | 颜色 | 模板类 | 典型对象 |
| --- | --- | --- | --- |
| 公开能力与业务计算 | 蓝色 | `role-business` | 公开 API、业务服务、推理执行器、计算模块 |
| 编排与协调 | 紫色 | `role-orchestration` | 工作流、任务编排、请求路由 |
| 契约与规则约束 | 绿色 | `role-contract`、`role-governance` | 内部能力接口、扩展协议；鉴权、隐私保护、策略校验 |
| 工具与能力适配 | 琥珀金色 | `role-tools` | 工具集合、插件、能力适配器 |
| 隔离执行 | 红色 | `role-isolation` | 沙箱、隔离运行时 |
| 通信与传输 | 青色 | `role-transport` | 进程间通信、网络传输、消息通道 |
| 公共基础设施 | 橙色 | `role-infrastructure` | 通用配置、日志、存储基础组件 |
| 辅助说明与中性分组 | 灰色 | `role-neutral` | 注释、解释卡片、外围中性分组 |

颜色跟随主要职责。同一组件跨视图保持一致；子组件有独立职责时可使用对应颜色。通信组件即使被多个模块复用仍用青色，通用配置与日志用橙色。外部部署不等于隔离执行，不据此改成红色。

公开能力入口与内部契约分别表达：对外提供业务能力的入口使用蓝色，规定内部实现必须遵循的能力接口或扩展协议使用绿色，具体适配实现使用琥珀金色，公共设施使用橙色。内部契约使用 `role-contract`，鉴权、隐私保护与策略校验继续使用 `role-governance`；两者共用绿色色板，具体职责由名称和分组标明。公开入口与内部契约同时出现时，分别检查边框、标题、背景和接口标签的配色。

调整配色时沿用模板色值，更新对应样式类及颜色说明。有对照页时只同步新版视图，保留改前视图作为比较依据。

职责类可以加在 SVG 的 `g` 上，让区域、标题和卡片共用颜色。`frame` 使用低饱和度区域背景，`card` 与 `mini` 使用统一卡片背景和职责色边框，模块标签使用同色标签背景。正文保持正文色。状态标签依本图图例单独选色并写明状态，不改变模块职责色。

新建图默认使用本表。用户指定配色优先；更新未要求重配的既有图时，保留其明确的颜色含义。

## 图形与关系

| 样式类 | 含义 | 约束 |
| --- | --- | --- |
| `boundary` | 应用、进程或隔离环境 | 虚线、无填充，写明边界类型；职责分组不冒充进程 |
| `frame` | 模块或职责分组 | 嵌套表达有依据的归属，同色不表示同一实例 |
| `card`、`mini` | 组件、执行角色、产物或局部解释 | 局部解释明确所说明的对象，不能作为调用者；全图约束放在图下 |
| `chip`、`pill` | 模块、接口、状态、发布属性或能力标记 | 有文字，仅在帮助阅读时使用；含义由图例说明 |
| `step` | 真实执行步骤 | 只有事实支持顺序关系时使用 |
| `band` | 通信通道 | 青色，标明协议及跨越范围；穿越箭头必须对应真实调用 |
| `edge` | 有方向的关系 | 配合下面的关系类、同色箭头和必要标签 |

| 关系类 | 样式 | 默认含义 |
| --- | --- | --- |
| `k-flow` | 蓝色实线 | 主要调用 |
| `k-alt` | 琥珀金色虚线 | 条件分支或替代路径，注明触发条件 |
| `k-event` | 青色点线 | 事件或异步回传 |
| `k-plain` | 中性实线 | 一般关系，标签或图例声明依赖、安装等具体含义 |
| `k-cfg` | 中性虚线 | 本图明确声明的可选关系或未接入关系 |
| `k-fail` | 红色实线 | 失败或拒绝结果 |

职责色与关系色是不同维度。蓝色模块可以通过青色箭头回传事件，橙色模块可以接收蓝色调用线。同图内每种连线样式只承担一种已声明的含义；可选关系与未接入关系同时出现时，用不同样式和明确标签区分。图例只列实际使用的关系。

图例默认放在图下左侧，每行一个箭头样例和对应说明，逐项纵向排列。各行的箭头起止位置、文字起点与行距一致，行距可从 `26–28` 个 SVG 用户单位起步；不将图例分散成横向多列。用户另有指定时遵从指定。

混合组件、执行角色、文件或产物时，用已有文字或标签样式写明类型；同类节点的标识方式一致，颜色继续表示职责。组件节点不能同时充当某个执行阶段。只有单一类型且含义明确时，可以省略重复的类型标签。

卡片内的职责说明与卡片主体一致。其他角色负责的收尾动作，放到对应角色或产物说明中，并写明执行者，避免读者因卡片包含关系误判职责归属。

模板的 marker ID 带 `sample-` 前缀。生成图时采用本图独有的前缀；箭头、标题和描述的引用要一起更新。

## 容易误画的含义

- **共用实现与共用实例。** 两个应用可以复用 `PolicyEngine` 的实现，却分别创建实例并持有独立存储。分别绘制实例与存储，用说明标注实现复用；仅凭同名类或同一源码模块不能合并运行实例。运行实例图还需标明短期对象的创建者、持有者与实例范围，例如按请求、会话或任务创建；将短期对象放在对应所有者分组内或用明确关系关联，不能因类只有一份实现就画成全应用共享实例。
- **状态归属与执行顺序。** 「状态 A 由请求对象持有、状态 B 由执行器持有」应放在对应所有者旁说明，不画成先 A 后 B 的步骤。
- **包含与调用。** 卡片放在区域内表达归属；调用另外核对并连线。分组发起调用、内部组件接收回调时，调用出口位于分组边界，回调接到实际组件。若出口位置使调用线看起来由内部卡片发出，应局部调整卡片宽度或端点，在保留短路径的同时明确责任主体；不能仅靠标签解释，也不为走线增加虚构节点。
- **相同职责与不同行为。** 两个策略校验节点都可使用绿色，但会拦截请求与只记录结果的差异必须通过文字或条件表达。
- **说明与参与者。** 「复用同一实现」或「没有外部调用方」是解释文字，不是能发起调用的组件。

## 排版

### 先建立整图骨架

先确定完整的层、并列区域和辅助区，安排共同左右边界与连线通道，再放组件。分层图优先让连续层共享外沿；并列区域优先顶底对齐，内部关键内容共享水平基线。列宽按信息量分配，不要求所有卡片等宽。对齐只组织阅读，不增加归属、调用或执行顺序。

使用生成脚本时，从同一份节点矩形推导端点，再从线段推导标签候选位置；移动节点后一起重新计算。不强制简单图采用脚本或 JSON。示例生成脚本复用主模板的 CSS 和 marker，不另维护职责色板。

共享代码的位置结合本图的抽象层次和实际依赖安排，并与具体适配实现分别表达。接口契约与公共实现承担不同职责，不因都被依赖就放在同一抽象层。依赖箭头从使用方指向被依赖方；运行调用、接口实现与模块依赖分别标注，不把上下位置画成未经确认的执行顺序。重排后逐条确认关系的真实起止对象。构建、解析、依赖替换等机制单独表达，不能成为原有依赖目标的替身；连线到分组仅在分组本身就是关系对象时成立。

「被依赖」只确定依赖关系的目标，不决定目标在上方还是下方。例如，以能力实现为主线的分层图可将接口契约放在适配层上方，将适配器使用的共享实现放在下方；实现关系向上、模块依赖向下。这是有适用条件的布局选择，不是所有共享组件的固定位置。

避免连续层在全宽、中央窄块和侧边孤块之间反复收放。辅助依赖可放在对应列底部或对齐的辅助横排；共享设施按实际使用范围标明关系，不能为了铺满底部暗示所有组件都依赖它。上下层列数不同时，以层的外沿保持整体连续，局部网格在层内变化。

留白用于区分层级、分组和容纳连线。出现一条中央长链、两侧大片空白，或底部只剩偏置节点时，优先尝试层内横排、相邻辅助列或拆分视图。不要通过删掉必要关系、添加空节点或扩大无内容边界来凑齐轮廓。

### 统一间距与信息层级

一张图选用少量重复的尺寸。以 `1400` 宽画布为例，外边距可从 `20`、区域内边距从 `16–20`、相邻卡片间距从 `16–24`、普通层间通道从 `40–56` 个 SVG 用户单位起步；它们是排版起点，不是内容约束。分支或双向线需要更多空间时，局部调整并复看整体。卡片高度按短标题、标题加一行说明等内容类型复用，同类文字保持一致的起点和行距。

区域表达模块或职责分组，卡片展示层内可识别的组件及简短职责，标签表达标识、属性和状态。在本图展开范围内，有明确组件的层应展开具体卡片，不能为紧凑把组件结构压缩成只有标题或标签串的空横幅。接口本身是需要展示的独立对象时，也使用卡片；仅作为其他组件的属性时使用标签。

卡片数量以真实组成为准，不强求每层同样多或固定为三列。组件较少时调整列宽、间距和留白；不要虚构、重复或无依据地拆分组件来填满空间，也不把属性或说明凑成组件。组件的层内归属足以表达组成，不要求每张卡片都有独立连线。关键信息、条件和角色归属仍按前面的信息职责规则保留。

外框必须增加模块、职责或实例归属信息。外框与唯一子卡片若表示同一对象、重复同一说明，保留一种表达即可；确有不同边界含义时可以嵌套。完整分组不等于每个辅助机制都要占一条全宽层，也不以重复包框代替组件展开。

### 画布与文字

模板画布宽度为 `1400` 个 SVG 用户单位，高度随内容调整；页面最大宽度为 `1400px`，SVG 默认最小显示宽度为 `1040px`。保留图形容器内的横向滚动，检查缩放后的实际可读性。字太小时先精简信息、提高最小显示宽度或拆图，不以没有溢出作为可读性结论。

页面标题为 `22px`，图内组件标题为 `15px`，模块标题为 `14px`，正文和代码标识为 `12px`。使用模板的字体栈和系统回退；换字体后重新检查文字宽度。

先布置边界与主路径，再布置辅助组件。长标识通过加宽或 `tspan` 分行处理，长说明按信息职责安排；改变执行顺序、准入或终止结果的条件仍在图中可见。调整卡片后复核箭头端点，不能靠截断或压缩字符宽度隐藏内容。

### 连线与整图复核

连线按以下顺序处理：

1. 根据图要回答的问题，先为主要关系安排相邻节点和直接通道，再放创建、管理等辅助关系及其组件。辅助关系是否属于主线由图意决定。不能为辅助卡片让路而迫使主线绕完整图外沿。
2. 分组内部的协作线可在分组内直接连接相关节点。跨区域连线从端点侧就近离开所属区域，在区域间的空白通道走线，再在目标侧就近进入。必要的短距离穿入或穿出可以保留；有色背景不充当绕行通道，无关分组不得穿越。
3. 直线通道与分组标题、说明冲突时，先调整标题位置、换行或预留通道；全图说明可移到图前或图注，局部条件仍紧邻对应关系。不要默认让主线绕过一整段文字。路径绕远、贴边或穿过背景时，先移动节点、调整分组范围或拆图。
4. 多条线共用侧边空白时，统筹端口顺序和通道位置，让长短回路分层嵌套，避免横向接入段切过其他竖线。保留真实端点、方向与关系；独立关系不能为消除交叉而合成汇合点，也不能用背景遮住冲突。
5. 折线可以保留，但最后一段应有足够的直线长度，让箭头方向容易辨认。端点附近只剩短促折弯时，调整接入侧、端口或通道，不把箭头挤在转角上。线段和箭头均与边框、标题、卡片保留可见间距；连接所属区域时仍只保留必要的穿入或穿出。

### 连线标签与编号

标签属于具体线段，不能只放在附近的空白区域。水平线的标签在对应线段上方或下方居中；竖线的标签放在一侧，左侧文字向右对齐（`text-anchor="end"`），右侧文字向左对齐。标签靠近线段，但留出可见间距；相邻还有其他线时，读者应能唯一确定标签归属。多行标签作为整体移动，保持相同的对齐边和稳定行距，避免主行靠近箭头、次行却落在卡片下方。

可以先以最长线段的中点生成候选位置，避开箭头附近的短段，再按文字尺寸、分组标题和邻近线段修正。最长线段不一定有足够空白。需要工具核对标签距离时，用 `data-edge-label` 绑定连线 ID；距离检查只检查锚点，不证明真实文字边界或语义归属正确。

动作型标签优先说明「动作 + 对象」，必要时带上目标；API、实现方式或局部条件作为补充。需要同时表达动作和实现时，可用两行：主行突出动作，次行补充机制。例如「读取通用配置」配「配置接口 · 只读访问」。模板提供可选的 `edge-operation` 主行样式；一句已经足够时保留单行，不凑第二行。同类标签采用一致的语义顺序和文字层级，关键分支条件不能因压缩标签而省略。

使用 `M1` 等编号时，在首次出现处或图注说明编号表示索引、阶段还是执行顺序。编号只是索引时，主行采用「编号 · 动作 + 对象」，不能只写编号或 API 名；同一编号覆盖不同分支时，用具体对象区分。容量、证据和完整限制可留在表格，关系的主要含义应在图内读懂。不要求所有图使用编号。

标签放不下时，先扩大局部间距、调整端点或明确分行，再复看整图；不要把标签推离连线，或不断缩小字号。光晕、底色及查表都不能代替清楚的标签归属。

渲染后先缩小看整图轮廓、阅读重心、对齐与空白，再按实际显示尺寸读文字和追踪主线，最后检查箭头、边界及遮挡。重排时以相同显示宽度比较改前、改后版本，确认分组和关键关系仍清楚。逐条追踪主要关系，检查起止对象、分支选择、触发时机与实例范围，并确认每个标签指向哪条线、说明什么动作。复核覆盖修改区域及整图，包括线与线、线与文字、线与边框的关系；区分有意汇合与非预期交叉。无重叠、节点更少或画布更短，都不能单独证明版式更好。
