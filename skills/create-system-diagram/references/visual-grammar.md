# 系统图视觉语法

本文件定义布局选择和图形含义。具体色值、字体及样式由包内 [HTML 模板](../assets/architecture-template.html) 提供，复制模板后复用，不凭描述重新配色。

## 对象、修改范围与澄清

绘图代理先读取请求、来源材料、已有图稿和已确认决定，再判断是否需要澄清。将「SDK」「引擎」「接入层」等通称对应到具体组件，核对参与者、调用入口和所在阶段；使用现有标题或组件名称定位修改对象。材料已明确的事实由代理自行核对，已确认决定直接沿用。

| 情形 | 绘图代理先核对 | 需要询问用户的条件 |
| --- | --- | --- |
| 对象未明确 | 通称对应的具体组件、参与阶段及调用关系 | 材料仍无法确定对象，不同选择会改变参与者、职责或调用链 |
| 要求尚未完整落实到图中 | 要求对应的模块、节点或关系、状态及适用场景 | 能力归属、采用状态或场景范围仍无依据；有明确依据的遗漏直接补齐 |
| 修改范围有多种解释 | 现有标题指向页面分区、图内分组、节点还是连线 | 合理解释会改变模块包含关系、阶段划分、调用关系或修改范围，且材料无法排除歧义 |

澄清时，绘图代理说明未确定的含义、可选解释及各自影响，只暂停依赖答案的修改，继续整理已确认部分。间距、换行和不改变含义的连线避让由代理自行决定。

例如「合并两块」应先定位为合并「路线」与「目标与评测范围」所在的页面分区，或调整图内的两个阶段。用户只要求合并页面分区时，代理调整容器、标题和排布，保留图内模块归属、阶段划分和连线。

绘制后，代理逐项对照用户要求，检查要求是否在正确对象上表达，状态和适用范围是否就近可见。核对按本图展开层级进行，不为每项要求强制新增节点；只在说明中提及能力却遗漏对应模块表达时，按已有依据补齐。

## 按问题选择布局

先选择表达形式：职责与归属用架构图，任务如何完成用流程图，指标或方案比较用表格。可在同一页面组合，避免将整段文档搬进流程卡片。重排或拆图前确认请求范围内的必要内容；性能、本期工作与验收条件在相关视图中保留。

| 布局 | 要回答的问题 | 组织方式 |
| --- | --- | --- |
| 整体分层 | 谁调用谁，模块归属哪里 | 按抽象层次纵向分层，同层模块横向排列，共享组件按实际依赖安排 |
| 模块内部结构 | 入口如何进入功能域，功能域依赖什么 | 主路径纵向展开，功能域分类排列，侧面补充适配组件 |
| 多入口汇合 | 多个入口在哪里汇合，状态由谁持有 | 并列入口，共同运行区域，请求与回传独立走线 |
| 并列分支 | 不同运行方式使用哪些组件 | 统一入口后分列，每列展开组件或有依据的步骤 |
| 职责对照 | 两个职责面有什么区别，复用什么 | 左右列出职责、实例及存储，另外说明实现复用 |

可组合布局，但每张图保持一个主要问题，展开深度以回答这个问题为准。总览保留参与者、职责、主要依赖和产物归属，局部流程展示关键协作；属于同一任务的组件、执行角色和产物可以共同出现，须标明类型与关系。不要为图形连贯而补出不存在的调用。

当目标和评测范围直接用于判断同一条路线时，绘图代理可将路线、目标和评测摘要放在共同页面分区中，用内部标题和间距区分主体与摘要。问题、对象或展开深度明显不同时，拆成相关视图；共同主题不要求强制合并，内容仍须符合整页精简与布局容量规则。

需要可运行的骨架时，使用[工具与布局示例](tools-and-examples.md)中的分层、并列工作流、局部回路、模块嵌套或场景能力与验收示例。布局适用性由分组和真实关系决定，不按组件数量硬套。容量不足时调整或拆图，不截取列表、隐藏正文或用自动缩字容纳全部内容。

默认 HTML 是图示页。图内保留主要关系、核心作用与关键条件，图下仅保留理解本图所需的目标、评测范围和约束摘要。完整路线表、验证步骤、验收细则与工程资料通过来源链接查看；用户明确要求完整资料页时按指定范围展开。精简后复看整个 HTML，确认图注、表格和说明没有重复铺开文档细节；不以主图文字变少代替整页信息取舍。

绘图代理按主要问题安排视觉优先级。主流程图让入口、处理与结果形成连续阅读路径，支持信息靠近服务对象；职责对照图让同级对象保持相近的面积、字号与对齐。通过位置、面积、留白和字重突出重点，模块主色继续表达身份。

总览与局部视图沿用共同组件的名称、配色及有助于理解关系的相对顺序和分组，局部标题注明所属总览模块。真实关系或展开深度需要重排时，保留可识别的共同节点。已有跳转或展开功能应能返回来源位置，返回后仍能找到原节点；静态图无需增加交互。

先确定主次再分配面积。主要节点保留名称与必要定位标识，按需补充简短职责；维护资料、字段和长说明放到来源文档。实例归属、授权、可选路径和失败条件仍须紧邻对应关系，辅助内容不与主体争夺同等空间。

授权、另行请求等决定能否执行的前提，使用入口旁的醒目文字或条件标记表达。文件交接与执行触发分别标明，保留读写箭头的真实方向；不要只依赖卡片内的小字区分自动执行与另行发起。

简化时保留能解释任务如何完成的工作流分组、协作者与交接条件。例如独立核查和裁定修复决定报告如何形成，属于主线内容，不能仅移入脚注。按工作流组织相关节点，外部依赖放在使用节点附近；不为凑齐网格而打散归属，也不为缩短连线删除关键关系。

## 按架构职责划分模块

按架构职责划分模块，源码归属作为核对依据。根据模块对外承担的责任、内部协作、资源与生命周期归属确定边界。大框表达大模块的职责边界，小框展开内部组成与分工，连线表达模块间的调用、依赖或数据交接。

分组标题优先说明职责，目录、包名和构建模块名作为次级标识或来源链接。结合接口、生产调用和配置核对分组；同一代码包可以承载多个架构职责，一个架构模块也可以跨代码包实现。实现分布与职责边界有差异时，标明映射，保留真实的协作与资源归属。

支持组件按服务对象和管理责任归组，共享能力按实际复用与依赖关系组织。不能为了把同色组件放在一起而改变包含关系。进程和部署边界单独标明；源码结构、包依赖或构建集成视图可以按源码与构建关系组织，并在标题或图注中明确视图用途。

### 模块、子模块与职责分区

绘图代理先确定图要回答的问题和展开范围。用前三项确认模块身份，展开子模块时再核对包含依据：

| 判定项 | 需要核对的内容 |
| --- | --- |
| 架构身份 | 代码或已确认设计将对象作为稳定的协作单元，有明确名称与实际对应对象 |
| 职责边界 | 能说明模块承担哪些能力，以及哪些工作由其他模块负责 |
| 协作边界 | 能说明其他对象如何调用、依赖模块或与模块交换数据，关系可明确连接到模块 |
| 包含依据 | 子模块承担父模块整体责任中的明确部分；仅有使用关系时，通过依赖线表达 |

现状图依据生产实现或已确认的外部现状，方案图依据已确认设计。涉及状态或资源时，继续核对创建、持有、修改和关闭责任。名称、功能相近或源码目录只提供线索；证据不足的结构保留待确认，不凭排版补出模块。

外层与内层表示模块之间的包含关系。当前视图可以只展示单模块，也可以展开有依据的子模块。职责表示模块承担的工作，执行主体仍是所属模块。父模块可包含子模块，各模块可同时展示职责；整体职责涉及多个子模块时，注明适用范围与责任方。模型、文件、产物等保留实际类型，不因使用卡片就改称子模块。

优先展示回答本图问题所需的子模块，再补充必要职责。职责可以写在模块卡片内，也可以用列表、短条或分区；短条可有细边框，通过标题、尺寸和排版与模块卡片区分。请求和结果关系连接实际模块或组件；职责分区只有在明确展示局部步骤时才承担相应流程关系。

### 职责归属、执行线程与存储边界

涉及运行实例、异步执行或存储时，分别确定三个维度：

| 维度 | 核对依据 | 图中表达 |
| --- | --- | --- |
| 职责归属 | 谁创建、持有、修改和关闭资源，谁负责业务状态 | 职责分组与资源管理关系；连线接实际责任组件 |
| 执行线程 | 提交、执行、收集、状态更新与回调交付各由谁调度 | 节点或连线旁的线程说明；需要展开时使用执行角色节点 |
| 存储边界 | 对象驻留位置、持久化介质、生命周期与实际共享范围 | 进程对象放在进程框内；磁盘目录、文件和远端存储放在对应介质或服务边界中 |

执行器仅承载任务调度时，创建、持有和关闭关系仍从负责资源的组件发出。若组件通过工厂创建对象，分别标明「组件调用工厂」和「工厂创建对象」。例如控制组件在 Worker 上创建采样器，管理连线从控制组件指向采样器，Worker 作为操作的执行位置。

内部异步工作按业务职责归组。事件收集、结果转换等属于某个组件时，在该组件的职责分组内展开，或标明所属组件的执行角色；有实际公共服务职责时才归入公共基础设施。涉及协程、流或回调时，分别核对上游执行、事件收集、状态更新和回调交付的调度位置，再写线程标签。

进程框只包含驻留其中的对象。存储客户端、访问组件和句柄可放在框内，持久化文件、目录与远端数据库放在进程框外，并标明「使用」「读写」或有依据的管理关系。应用归属视图可将应用拥有的组件与存储放在同一应用边界内，边界标题须明确表达应用归属。

默认目录派生、自定义路径、跨实例复用或独占写入影响本图含义时，就近保留配置条件。用列对齐或使用关系表达实例与目录的对应关系，独占与共享范围以实际配置和生命周期合同为依据。归属修正须同时检查分组、节点位置、连线端点、配色与说明。

## 按信息职责选择表达

先判断信息在图中的作用，再选择节点、条件标记或说明；重要程度本身不决定是否使用独立卡片。

| 信息类型 | 表达方式 | 例子 |
| --- | --- | --- |
| 实际组件、执行角色、工具或产物 | 使用节点，通过真实关系或明确分组表达归属 | 处理组件、校验工具、交接文件 |
| 决定流程走向的条件 | 接入主线，标明条件分支及结果；仅限制入口时使用入口条件标记 | 凭据有效时直接复用产物，绕过后续处理 |
| 解释某个节点或关系的局部说明 | 放进对应节点或紧邻对象；核心作用与关键条件用正文，辅助信息用次级文字 | 只读权限、实例创建方式 |
| 适用于整张图的约束 | 共同范围优先在图标题下说明一次；图下仅保留必要约束摘要与责任角色，完整约束通过来源链接查看 | 整次运行的状态保护与恢复要求 |

辅助说明单独使用卡片时，必须明确所说明的对象，视觉权重低于主体。独立节点应有清楚的关系或分组归属；发现孤立节点时先核对信息类型，不为消除孤块编造连线。全图约束中的某项若决定具体分支或执行入口，应同时在对应位置保留必要条件，完整规则通过来源链接查看。

分叉须明确表示择一、并行还是广播。择一路径在分叉处突出选择条件或数量，可使用 `k-alt` 区分候选路径；不能仅靠远处注释解释几条相同实线只会走一条。

创建、初始化与业务调用同时出现时，按事实标明初始化时、每次请求或满足条件时触发的关系，并配合清楚的图例。只有初始化时发生的创建关系，不能被读成每次请求的必经步骤。

## 事实来源与状态

绘图代理区分生产实现、已确认设计和用户提供的外部现状。仓库内部行为核对生产调用与配置；具体观测字段、失败阶段等须找到真实生产者，不能为对称布局补出能力。用户已确认的外部能力按确认内容呈现，助手未亲自验证的范围在交付说明中交代；仅凭仓库未包含外部实现，不将外部能力标为待建设。已确认待建设的能力在对应对象旁标明。来源冲突影响图意时，沿用事实冲突处理规则。

## 场景能力与验收

场景图沿「发起者 → 处理组件 → 输出 → 调用方用途」组织。先确认谁发起请求、谁负责处理，以及调用方拿到结果后做什么，再安排卡片。总览保留角色、主要关系、结果与决策条件；接口字段、调用封装和完整实现细节放到来源材料或局部视图。

同一条请求往返默认保留一个调用方节点，结果返回原节点，并在节点内说明结果用途。按不同生命周期阶段展开组件时可以重复节点，须标明阶段并保持名称、身份和颜色一致。独立运行实例按实际创建与持有范围表达。

加载、显式释放与自动回收关系从真实发起者或负责组件发出，资源状态作为动作结果。后续请求从真实入口重新进入，不从「已销毁」等结果节点发起调用。总览只需表达往返关系时可使用单线双向箭头；局部图需要区分载荷、条件或时序时，分开绘制请求与返回。

绘图代理按最新确认材料与用户决定整理现状、本期工作和待确认项。已完成内容归入现状；本期工作说明责任组件、具体改动及预期结果；待确认内容保留未知条件。测量、优化和验收工作须来自本次请求或权威材料。跨场景共用的工作可集中呈现，并标明适用场景，避免每张图重复成独立任务。

性能信息先确定测量对象，再选择同色分组、邻近排布或无箭头的注释关联线表达归属。关联线使用 `k-association`，图例写明说明关系；实际调用与数据交接继续使用带方向的关系线。性能区沿用所属模块主色，多个模块的汇总区按模块分别标明。

绘图代理按下表核对数据，再统一同组图中的表达：

| 项目 | 表达要求 |
| --- | --- |
| 数据范围 | 核对模型或版本、输入、配置、运行状态、统计口径与来源；影响比较的条件就近可见 |
| 数据性质 | 分别标明实测、估算、目标与待确认；有据可查的现状才能写成基线 |
| 代表点 | 按比较目的选择有依据的档位和数量；下限、上限注明已测范围，不将局部结果扩成全范围结论 |
| 指标格式 | 同类指标统一名称、数值、单位、目标与必要注释；单位靠近数值，测量对象明确 |
| 比较与验收 | 写明比较双方，可用「A vs B」或「A 与 B 对比」；保留比较条件、结果判据和责任方，未确认的标准不自行补齐 |

需要组合这些内容时，可选用「场景能力与验收」模板。模板只演示虚构组件与模拟数据；使用时按实际问题替换，不要求每张架构图增加性能或验收区。

## 模块配色

模块决定色系，信息用途决定填色，包含关系表达层次；职责类别不分配固定主色。绘图代理先确定模块及其归属，再为本组图建立「模块 → 独立主色或继承对象 → 样式类」映射。源码或职责名称不直接决定颜色。

用户指定或同组图已经确认的模块映射优先，映射须能追溯到明确决定；临时试色不自动成为约定。没有既有映射时，子模块默认继承父模块。仅当本图主要用于比较或追踪多个同级子模块的分工与协作时，才为这一组统一制定独立配色，并说明参与区分的模块与选色依据。独立接口、进程、连线和内部职责数量用于核对架构，不自动触发换色。

一个模块的主色覆盖自身及继承配色的子模块。采用独立主色的模块之间保持可辨认的颜色差异，同一模块在本组相关视图中保持一致。新增独立映射时复核本组相关图，避免同一模块交替继承和独立配色。颜色不足时调整分组或拆图，不按位置轮换颜色。

为尚未定色的模块从固定色板选色，优先考虑淡橙、淡黄和淡红，搭配蓝、紫、绿、青。按主要区域的可见面积检查冷暖分布；已确认映射和模块辨识优先，不为凑颜色数量改色。普通模块可使用红色或绿色，状态通过明确文字和局部标签表达。

维护色板时，先用相同面积、文字与层次比较各色的视觉强度，再放回完整图检查主要区域。浅黄、浅橙和浅红应保留可见色相，青色等较明显底色不应让同级模块获得额外的视觉权重；优先微调浅底和职责区填色，保留模块映射与主色。透明度或对比度数值仅辅助判断，不能机械设成相同数值。通用校准样例见工具参考中的「固定色板与填色层次」。

用按实际模块命名的 `module-*` 类设置 `--module-color`、`--module-bg`、`--module-chip`，分别供主色、浅底和职责区及标签填色使用。继承配色的子模块复用父模块类或继承 CSS 变量，避免重新分色。跨模块汇总与中性分组使用 `group-neutral`；`role-*` 固定职责色不再作为模板入口。

示例中的模块映射仅适用于对应示例。实际绘图先按本组图的对象与问题确定映射，再复用色值。更新已有图且用户未要求重配时，保留已明确的映射。模块主色调整时同步边框、模块标题、附属信息归属、图例及新版对照视图，改前视图保留。仅修改文字配色时保留模块背景与边框。

## 填色与边框

按对象用途和真实归属选择背景；层次通过包含关系、名称、位置和间距表达，填色不按嵌套深度逐级加深。

| 对象 | 填色与边框 | 模板用法 |
| --- | --- | --- |
| 外层模块，或采用独立主色的子模块 | 自身主色浅底、主色边框 | 分组用 `frame`，独立组件卡片用 `card card-tinted` |
| 继承父模块色系的子模块与内部组件 | 统一卡片背景，浅色主题为白色；边框保留继承的主色 | 分组用 `frame frame-inherited`，卡片用 `card` 或 `mini` |
| 模块内部的职责分区 | 所属色系中更明显的一档浅色，同组职责统一填色 | `duty`；名称、列表或分区区分具体职责 |
| 性能、本期工作及验收说明 | 保留所属模块主色，用指标卡、工作列表与条件说明区分用途 | 指标卡用 `card`；说明区可用 `annotation` 配合模块色标题 |
| 页面或场景分区、跨模块汇总说明 | 中性背景与边框；浅色主题为白底圆角，模块明细保留各自主色 | 页面分区用 `figure`；SVG 分区用 `annotation` 和 `section-title` |
| 应用、进程等边界 | 无填充、中性虚线，注明边界类型 | `boundary` |

职责分区共用所属模块的执行主体，不为每项职责递增加深。性能、工作与验收说明的边框及归属标题沿用模块主色，正文与当前值使用正文色；本期优化目标的数值及比较符号局部使用橙色加粗。具体通过或失败结果按状态规则表达。

绘图代理按实际显示尺寸确认父模块浅底、继承组件背景和职责区填色可以辨认，并复看填色面积较大时是否压过主线。需要强调当前工作、关键状态或目标时，使用位置、字重和带明确文字的局部标签，沿用既有主色与填色用途。

模块边框使用模块主色，正文使用主题正文色。`card` 与 `mini` 保留约 `2px` 的边框及 `vector-effect: non-scaling-stroke`，模块框保留 `1.5`；信息注释区使用中性细边框与模块色标题。父模块的浅底、继承组件的白底和职责区的填色在实际显示尺寸下分别复核。深色主题使用对应卡片背景与色值，保留相同含义。

## 图形与关系

| 样式类 | 含义 | 约束 |
| --- | --- | --- |
| `boundary` | 应用、进程或隔离环境 | 虚线、无填充，写明边界类型；职责分组不冒充进程 |
| `frame` | 架构模块 | 按职责、协作与资源归属确定包含关系；源码与构建视图另行注明 |
| `card`、`mini` | 组件、执行角色、产物或局部解释 | 局部解释明确所说明的对象，不能作为调用者；全图约束放在图下 |
| `chip`、`pill` | 模块、接口、状态、发布属性或能力标记 | 有文字，仅在帮助阅读时使用；含义由图例说明 |
| `step` | 真实执行步骤 | 只有事实支持顺序关系时使用 |
| `duty` | 模块内部职责 | 沿用模块色系，同组职责统一填色；标明所属模块 |
| `annotation` | 场景分区，或性能、工作、验收说明 | 中性分区用正文色标题；模块附属说明用模块色标题，内部正文与当前值用正文色 |
| `band` | 通信通道 | 按所属模块着色，标明协议及跨越范围；穿越箭头对应真实调用 |
| `edge` | 对象关系或注释关联 | 配合关系类与必要标签，方向关系有箭头，注释关联无箭头 |

| 关系类 | 样式 | 默认含义 |
| --- | --- | --- |
| `k-flow` | 蓝色实线 | 主要调用 |
| `k-alt` | 琥珀金色虚线 | 条件分支或替代路径，注明触发条件 |
| `k-event` | 青色点线 | 事件或异步回传 |
| `k-plain` | 中性实线 | 一般关系，标签或图例声明依赖、安装等具体含义 |
| `k-cfg` | 中性虚线 | 本图明确声明的可选关系或未接入关系 |
| `k-fail` | 红色实线 | 失败或拒绝结果 |
| `k-association` | 中性短虚线，无箭头 | 性能等注释信息的归属，说明对象明确 |

模块色与关系色分别决定节点和连线。蓝色模块可以通过青色箭头回传事件，橙色模块可以接收蓝色调用线。同图内每种连线样式只承担一种已声明的含义；可选关系与未接入关系同时出现时，用不同样式和明确标签区分。图例只列实际使用的关系。

图例默认放在对应视图内容框外的下方左侧，直接置于页面背景，不另加背景框。先列模块色块，再列连线样例，逐项纵向排列。模板将图例作为 `figure` 后的 `.legend` 元素，放在图形横向滚动容器外；样例区域宽度、文字起点与行距一致。色块说明模块映射及继承范围，线型和箭头样例覆盖本图实际使用的全部含义，包括无箭头关联和双向箭头；未使用的类型省略。说明文字使用次级文字色，不分散成横向多列。用户另有指定时遵从指定。

混合组件、执行角色、文件或产物时，用已有文字或标签样式写明类型；同类节点的标识方式一致，颜色继续表示模块归属。组件节点不能同时充当某个执行阶段。只有单一类型且含义明确时，可以省略重复的类型标签。

卡片内的职责说明与卡片主体一致。其他角色负责的收尾动作，放到对应角色或产物说明中，并写明执行者，避免读者因卡片包含关系误判职责归属。

模板的 marker ID 带 `sample-` 前缀。生成图时采用本图独有的前缀；箭头、标题和描述的引用要一起更新。

## 容易误画的含义

- **共用实现与共用实例。** 场景图按生命周期阶段展开同一组件时，明确阶段与身份；运行实例图再按实际实例展开。两个应用可以复用 `PolicyEngine` 的实现，却分别创建实例并持有独立存储。分别绘制实例与存储，用说明标注实现复用；仅凭同名类或同一源码模块不能合并运行实例。运行实例图还需标明短期对象的创建者、持有者与实例范围，例如按请求、会话或任务创建；将短期对象放在对应所有者分组内或用明确关系关联，不能因类只有一份实现就画成全应用共享实例。
- **状态归属与执行顺序。** 「状态 A 由请求对象持有、状态 B 由执行器持有」应放在对应所有者旁说明，不画成先 A 后 B 的步骤。
- **包含与调用。** 卡片放在区域内表达归属；调用另外核对并连线。分组发起调用、内部组件接收回调时，调用出口位于分组边界，回调接到实际组件。若出口位置使调用线看起来由内部卡片发出，应局部调整卡片宽度或端点，在保留短路径的同时明确责任主体；不能仅靠标签解释，也不为走线增加虚构节点。
- **相同职责与不同行为。** 同一模块的两个策略校验节点沿用模块主色，但会拦截请求与只记录结果的差异必须通过文字或条件表达。
- **说明与参与者。** 「复用同一实现」或「没有外部调用方」是解释文字，不是能发起调用的组件。

## 排版

### 先建立整图骨架

先确定完整的层、并列区域和辅助区，安排共同左右边界与连线通道，再放组件。分层图优先让连续层共享外沿；并列区域优先顶底对齐，内部关键内容共享水平基线。列宽按信息量分配，不要求所有卡片等宽。对齐只组织阅读，不增加归属、调用或执行顺序。

使用生成脚本时，从同一份节点矩形推导端点，再从线段推导标签候选位置；移动节点后一起重新计算。不强制简单图采用脚本或 JSON。示例生成脚本复用主模板的 CSS 和 marker，不另维护色板。

共享代码的位置结合本图的抽象层次和实际依赖安排，并与具体适配实现分别表达。接口契约与公共实现承担不同职责，不因都被依赖就放在同一抽象层。依赖箭头从使用方指向被依赖方；运行调用、接口实现与模块依赖分别标注，不把上下位置画成未经确认的执行顺序。重排后逐条确认关系的真实起止对象。构建、解析、依赖替换等机制单独表达，不能成为原有依赖目标的替身；连线到分组仅在分组本身就是关系对象时成立。

「被依赖」只确定依赖关系的目标，不决定目标在上方还是下方。例如，以能力实现为主线的分层图可将接口契约放在适配层上方，将适配器使用的共享实现放在下方；实现关系向上、模块依赖向下。这是有适用条件的布局选择，不是所有共享组件的固定位置。

避免连续层在全宽、中央窄块和侧边孤块之间反复收放。辅助依赖可放在对应列底部或对齐的辅助横排；共享设施按实际使用范围标明关系，不能为了铺满底部暗示所有组件都依赖它。上下层列数不同时，以层的外沿保持整体连续，局部网格在层内变化。

留白用于区分层级、分组和容纳连线。出现一条中央长链、两侧大片空白，或底部只剩偏置节点时，优先尝试层内横排、相邻辅助列或拆分视图。不要通过删掉必要关系、添加空节点或扩大无内容边界来凑齐轮廓。

### 统一间距与信息层级

一张图选用少量重复的尺寸。以 `1400` 宽画布为例，外边距可从 `20`、区域内边距从 `16–20`、相邻卡片间距从 `16–24`、普通层间通道从 `40–56` 个 SVG 用户单位起步；它们是排版起点，不是内容约束。分支或双向线需要更多空间时，局部调整并复看整体。卡片高度按短标题、标题加一行说明等内容类型复用，同类文字保持一致的起点和行距。

同组内容的间距应小于跨组间距，并为连线保留通道。标题靠近所属区域，核心解释靠近对应块，条件靠近执行入口，标签靠近自己的线段。绘图代理按实际显示尺寸检查读者能否直接判断文字和块的归属；出现歧义时先调整邻近关系与留白。

区域表达模块或职责分组，卡片展示层内可识别的组件及必要说明，标签表达标识、属性和状态。在本图展开范围内，有明确组件的层应展开具体卡片，不能为紧凑把组件结构压缩成只有标题或标签串的空横幅。接口本身是需要展示的独立对象时，也使用卡片；仅作为其他组件的属性时使用标签。

卡片数量以真实组成为准，不强求每层同样多或固定为三列。组件较少时调整列宽、间距和留白；不要虚构、重复或无依据地拆分组件来填满空间，也不把属性或说明凑成组件。组件的层内归属足以表达组成，不要求每张卡片都有独立连线。关键信息、条件和角色归属仍按前面的信息职责规则保留。

外框必须增加模块或实例归属信息。设备、进程或部署边界只在影响图意时展开。单个组件足以表达一台设备或一个进程时，可在卡片直接注明范围；多个独立进程共用外围分组时，标题说明应用或设备归属，各进程边界分别标明。外框与唯一子卡片若表示同一对象、重复同一说明，保留一种表达即可；确有不同边界含义时可以嵌套。完整分组不等于每个辅助机制都要占一条全宽层，也不以重复包框代替组件展开。

### 文字用途与配色

先按文字在本图中的用途选样式，再按模块映射取色。模块主色只承担模块身份；正文层级由内容对当前问题的重要性决定。

| 文字用途 | 配色与字重 | 模板样式 |
| --- | --- | --- |
| 页面、章节、场景、进程边界标题 | 正文色，加粗 | 页面标题、`section-title`、`boundary-title` |
| 表达模块身份的名称 | 所属模块主色，加粗 | `frame-title`、`module-title`、`outer-title`；独立模块卡片用 `node-title module-name` |
| 模块内部组件名称、职责标题 | 正文色，加粗 | `node-title`、`mini-title`、`duty-title` |
| 本场景核心作用、正文、关键条件、指标名称及当前值 | 正文色；必要时加粗 | `body-text`、`duty-body`、`metric-value` |
| 补充说明、测量口径、图例文字 | 次级文字色 | `note`、`module-note`、`.legend` |
| 本期优化目标数值及比较符号 | 橙色，加粗，保留「目标」或「实测 → 目标」标记 | 仅为目标片段添加 `metric-target` |
| 状态与结果 | 默认正文色；突出时加粗或用局部状态标签 | 正文或带明确状态文字的标签 |
| 连线文字 | 普通关系用中性色；特殊关系按图例用对应颜色 | `edge-label`；两行主行可加 `edge-operation` |

模块标题按图中身份判定。内层子模块明确展开自身边界时，标题使用自身或继承的主色；内部组件名称仍使用正文色。附属说明区可用模块色标题标明归属，区内指标名称与当前值使用正文色。不要全局修改 `.node-title` 将所有标题染色。

核心解释、关键条件和当前值保持正文色，辅助文字仅用于次要信息。绘图代理在文字实际所在的浅底、卡片背景或职责区上复核小字号模块标题与连线标签；过淡时在同一色系内调整对应文字色或增大字号，保持已确认的颜色含义。

目标强调只改变数值及比较符号的局部文字，模块背景、边框与归属标题保持模块映射。橙色模块中的目标仍通过「目标」标记、比较符号和字重识别。图例的样例保留真实颜色，解释文字统一使用次级文字色。

### 块内文字与场景作用

绘图代理先确定当前场景，再判断节点是否需要解释文字。当名称、分组和连线已能清楚表达本场景作用时，节点可以只保留标题，并按卡片空间居中或对齐。同级节点采用相近的信息粒度；解释文字用于补充必要含义，不为填满卡片或凑齐行数增加说明。影响理解的条件、状态和结果用途仍须保留。

需要解释时，选择每个块最有关联的动作、对象、输出用途与必要条件，按「模块名称 → 本场景核心作用 → 必要补充」组织；产物或其他类型的块使用实际名称。核心解释保持正文层级，只有辅助信息使用次级文字色或较小字号。

例如查询场景中的资料应用可写「提交查询条件，展示匹配内容」，索引服务可写「检索匹配条目，返回排序结果」。两个模块分别说明自己的贡献，共同适用的资料范围在图标题下说明一次。通用职责清单和完整工程细节留在来源文档；局部触发条件紧邻负责的块或连线。

精简后仍应能说清谁做什么、作用于什么对象、产生什么结果。使用「查询文本」「带签名的下载地址」「每条记录对应一次请求」等明确表述，保留动作、修饰关系和统计单位。外框已明确模块身份时，可省去内部重复前缀；项目术语和代码标识保持原样。

块内标题、核心解释与补充说明各自使用统一起点、间距和对齐方式，按语义换行。中文短并列用顿号，独立职责或条件分行，解释用冒号或括号；多条件写清「且」或「或」，时长紧邻适用条件。验收数值用 `≥`、`≤` 并保留比较对象与范围。中点「·」可分隔编号或类型，不通用于所有语义关系。

不设机械行数或字数上限，也不为对齐凑相同的块数或文字数量。调整文字后按内容调整块尺寸。复看时，读者应能直接说清这个块在当前场景做什么、如何与相邻块协作。

### 画布与文字

模板画布宽度为 `1400` 个 SVG 用户单位，高度随内容调整；页面最大宽度为 `1440px`，SVG 默认最小显示宽度为 `1400px`，容器内允许横向滚动。绘图代理从目标阅读尺寸反推字号、画布与最小显示宽度。等比缩放时，实际字号约为「SVG 字号 × 显示宽度 ÷ viewBox 宽度」；宽 `1400` 的图显示为 `1040px` 时，`12` 单位正文仅约 `8.9px`，需调整显示宽度、排版或拆图。

页面标题用 `1.375rem`，图注与图例用 `0.8125rem`，随浏览器基础字号变化。图内组件标题为 `15`、模块标题为 `14`、正文和代码标识为 `12` 个 SVG 用户单位；这些是排版起点，按实际显示大小复核。显式坐标 SVG 调整字号时，同步调整卡片、行距和连线通道，不能仅将所有字号换成相对单位。使用模板字体栈和系统回退；换字体后重新检查字宽、中文标点及中英文混排，不全局套用英文紧字距。

主要工作、比较结论与关键条件使用与同类正文一致的字号，不能因篇幅长降成小字。长句按动作、对象和条件分行，比较双方保持完整；需要更多空间时加宽、增高或拆图。保留来源中的名称与技术标识，不为缩短文字替换术语。

先布置边界与主路径，再布置辅助组件。长标识通过加宽或 `tspan` 分行处理，长说明按信息职责安排；改变执行顺序、准入或终止结果的条件仍在图中可见。调整卡片后复核箭头端点，不能靠截断或压缩字符宽度隐藏内容。

### 阅读与导航

图形滚动容器使用可聚焦的原生区域，提供名称与清晰的焦点轮廓。已有链接、展开与返回操作须可通过键盘到达和使用；链接或控件不嵌套进 `role="img"` 的静态图形中。绘图代理检查 Tab 顺序、焦点位置、横向滚动及放大后的完整内容，避免焦点被遮挡或文字被裁切。仅当页面已有动态效果时，响应 `prefers-reduced-motion`，保留内容与操作结果。

颜色之外，模块仍有名称与包含边界，状态有文字，连线有方向、线型和标签。绘图代理检查灰度或降低色彩辨识时能否追踪关键关系；出现混淆时补足这些表达，不临时改变模块身份色。

### 局部时间关系

需要表达耗时时，区间线连接明确的起点与终点，标签写清所测操作及适用条件。里程碑放在时间轴节点旁，组件内动作通过无箭头关联线对应到里程碑；关系图例标明时间区间与注释关联。只展开回答本图问题所需的局部时间关系，完整时序图或状态机沿用 Skill 的范围约定。

### 连线与整图复核

多色模块中的普通调用或交接可选中性色，减轻连线对模块配色的干扰。条件、事件与失败继续保留本图既定含义；用颜色、虚实线、箭头方向和必要的箭头形状共同区分。按正文、卡片及实际显示比例调整线宽和箭头大小，方向清楚且不压过内容；无箭头注释关联与执行关系分别列入图例。

更新图稿时，绘图代理先核对事实变化，并沿用当前图稿已确认的简洁程度、信息粒度和删除项。来源文档仍保留的细节不自动恢复到图中；新增事实仅补充理解变化所需的信息。新事实与已确认的图意或范围冲突时，按事实冲突规则处理。删除项适用于同一图稿的后续更新，不固化为其他图的全局删除规则；用户已撤回的方案不再作为默认依据。

局部修改先限定对象：文案修改只涉及文字及必要排版，文字配色修改保留模块背景与边框。节点或文字修改后，绘图代理检查卡片排版与相关连线；页面分区或容器修改后，还须在浏览器中复看整个 HTML 的标题层级、间距、图注、框外图例与滚动。离线 SVG 复看只覆盖图形本身，不能完成页面组织效果的检查。随后复看整图及同组图的术语、标签结构、文字颜色、字号、图例和模块映射；各图按自身问题选择布局，未受影响且仍有效的检查结果可以复用。

连线按以下顺序处理：

1. 根据图要回答的问题，先为主要关系安排相邻节点和直接通道，再放创建、管理等辅助关系及其组件。辅助关系是否属于主线由图意决定。不能为辅助卡片让路而迫使主线绕完整图外沿。
2. 分组内部的协作线可在分组内直接连接相关节点。跨区域连线从端点侧就近离开所属区域，在区域间的空白通道走线，再在目标侧就近进入。必要的短距离穿入或穿出可以保留；有色背景不充当绕行通道，无关分组不得穿越。
3. 直线通道与分组标题、说明冲突时，先调整标题位置、换行或预留通道；全图说明可移到图前或图注，局部条件仍紧邻对应关系。不要默认让主线绕过一整段文字。路径绕远、贴边或穿过背景时，先移动节点、调整分组范围或拆图。
4. 多条线共用侧边空白时，统筹端口顺序和通道位置，让长短回路分层嵌套，避免横向接入段切过其他竖线。保留真实端点、方向与关系；独立关系不能为消除交叉而合成汇合点，也不能用背景遮住冲突。
5. 折线可以保留，但最后一段应有足够的直线长度，让箭头方向容易辨认。端点附近只剩短促折弯时，调整接入侧、端口或通道，不把箭头挤在转角上。线段和箭头均与边框、标题、卡片保留可见间距；连接所属区域时仍只保留必要的穿入或穿出。

### 连线标签与编号

标签属于具体线段，不能只放在附近的空白区域。水平线的标签在对应线段上方或下方居中；竖线的标签放在一侧，左侧文字向右对齐（`text-anchor="end"`），右侧文字向左对齐。标签靠近线段，但留出可见间距；相邻还有其他线时，读者应能唯一确定标签归属。多行标签作为整体移动，保持相同的对齐边和稳定行距，避免主行靠近箭头、次行却落在卡片下方。

可以先以最长线段的中点生成候选位置，避开箭头附近的短段，再按文字尺寸、分组标题和邻近线段修正。最长线段不一定有足够空白。需要工具核对标签距离时，用 `data-edge-label` 绑定连线 ID；距离检查只检查锚点，不证明真实文字边界或语义归属正确。

同组连线先选一致的描述维度。动作型标签写「动作 + 对象」，数据交接可写「场景：载荷」。请求与返回配对，例如「入库：内容文本」与「入库：内容向量」、「检索：查询文本」与「检索：查询向量」，同类场景保持相同顺序。避免一条只写触发时机，另一条只写用途；时机影响流程时，就近保留为条件。

API、实现方式作为补充；需要两层信息时，主行说明关系，次行补充机制。例如「读取通用配置」配「配置接口（只读）」。主行可用 `edge-operation`；单行足够时保留单行。关键分支条件不能因压缩标签而省略。

使用 `M1` 等编号时，在首次出现处或图注说明编号表示索引、阶段还是执行顺序。编号只是索引时，主行采用「编号 · 动作 + 对象」或「编号 · 场景：载荷」，不能只写编号或 API 名；同一编号覆盖不同分支时，用具体对象区分。容量、证据和完整限制可留在表格，关系的主要含义应在图内读懂。不要求所有图使用编号。

标签放不下时，先扩大局部间距、调整端点或明确分行，再复看整图；不要把标签推离连线，或不断缩小字号。光晕、底色及查表都不能代替清楚的标签归属。

绘图代理为每张图选择一个符合主要问题的阅读任务，例如「从请求入口追到结果返回」或「找到资源持有者与关闭责任」。按最终显示尺寸，仅依靠图内内容走读一次，记录需要猜测归属、寻找远处标签或查表重建主线的位置并修正。涉及总览与局部视图时同时检查进入和返回路径。交付说明区分代理走读与实际用户测试。

共享样式或配色修改后，绘图代理单独复核浅色、深色与灰度效果：先用同尺寸样例比较各色，再检查整图的模块边界、填色层次、核心文字及暖色辨识，关注大面积底色是否意外主导阅读。灰度下仍能通过名称、包含关系、线型与标签识别图意和布局。

渲染后先缩小看整图轮廓、阅读重心、对齐与空白，再按实际显示尺寸读文字和追踪主线，最后检查箭头、边界及遮挡。重排时以相同显示宽度比较改前、改后版本，确认分组和关键关系仍清楚。逐条追踪主要关系，检查起止对象、分支选择、触发时机与实例范围，并确认每个标签指向哪条线、说明什么动作。复核覆盖修改区域及整图，包括线与线、线与文字、线与边框的关系；区分有意汇合与非预期交叉。无重叠、节点更少或画布更短，都不能单独证明版式更好。
