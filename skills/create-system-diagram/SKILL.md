# Create System Diagram

创建、更新或检查系统架构、职责协作、局部流程与数据流图。默认交付一个可独立打开、可编辑的静态 HTML 文件，内嵌 CSS 与 SVG。图回答组件职责、归属边界和主要关系，默认使用固定的职责配色。用户指定的风格、路径和范围优先。

## 确定图意

从请求和材料确定读者、图要回答的问题、范围及事实版本。更新任务先读取目标文件及适用的项目约定。

- 表达当前架构时，核对范围内的生产调用、接口和配置；按设计稿绘图时，标明设计状态。
- 区分模块、类型、运行实例、存储、产物、条件与解释文字，先按信息职责决定是否画成独立节点。为关键节点、归属、箭头方向和条件找到依据；运行实例图还须确认创建者、持有者和实例范围。
- 保留可选、未接入、运行模式和关键失败结果。输入冲突影响边界、实例归属或关系方向时，说明冲突并询问用户，暂停依赖结论的绘制，继续整理已确认部分。

为每张图确定一个主要问题，并按回答这个问题所需的层级展开。总览突出参与者、职责、主要关系与产物归属，局部流程展示关键协作。属于同一任务的组件、执行角色和产物可以共同出现，须标明类型与关系。常规间距、折线路径和文字换行由绘图代理决定。

## 绘制或更新

新建图、重排布局或修改架构含义时，先读 [visual-grammar.md](references/visual-grammar.md)，据此选择布局、职责颜色和关系图例。仅修订文字或局部样式时，读取目标文件中受影响的节点、连线及对应样式。

绘制前先确定主要区域的「对象 → 职责 → 样式类」，再安排共同边界和连线通道。职责分类决定颜色，事实关系决定箭头，布局决定位置；不要从名称中的「接口」「公共」或上下层位置直接推导三者。重排时保持关系的真实起止对象，不用构建或解析机制替代依赖目标。这个判断不要求额外交付清单。

新建图复制 [architecture-template.html](assets/architecture-template.html)，保留配套 CSS、字体回退与需要的箭头定义，替换示例内容。模板是样式与色值的唯一运行时来源；通用示例中的组件、关系和来源说明均须替换为本次任务的内容。

需要分层、并列工作流或回路骨架时，按 [工具与布局示例](references/tools-and-examples.md) 选择对应 HTML。复杂图可参考示例生成脚本：节点尺寸只定义一次，端点从节点边界推导，标签候选位置从线段推导。最长线段只是标签的候选位置，仍须检查字宽与邻近线段。简单修改直接编辑 HTML，不强制改成 JSON 配置或生成脚本。

- 默认浅色主题，保留深色主题定义；不增加主题切换控件、在线字体或其他在线静态资源。
- 公开能力入口用蓝色，内部能力契约用绿色 `role-contract`，适配实现用琥珀金色，公共设施用橙色；不因都涉及接口而统一着色。共享代码按本图的层次和实际依赖安排。图例默认在图下左侧逐项纵向排列。
- 更新已有图时保留用户内容，只改受影响部分。文件由脚本或模板生成时，修改实际生成源并重新生成，避免下次生成覆盖修正。用户未要求重配时，沿用文件已明确的颜色含义，新增节点使用同类节点的配色。改色时同步边框、标题、背景、标签及图注；有对照页时同步新版视图，保留改前视图。
- 混合组件、执行角色、文件或产物时，用简短类型标签区分。职责说明放在实际负责的角色旁；跨角色收尾动作可与产物一起呈现，并明确执行者。节点保持稳定对象含义，执行阶段另在局部流程中表达。
- 主要节点保留名称、定位标识与简短职责。简化时保留工作流分组、关键协作与交接条件，让读者仍能追踪任务如何完成；次要资料降为注释或链接。
- 在本图展开范围内，有明确组件的层应展示具体卡片，保留组件名称与简短职责，不能为紧凑只剩层标题或一条空横幅。卡片数量以真实组成为准，不为填满空间虚构、重复或无依据地拆分组件；属性和状态仍用标签表达。外框须提供额外的归属或边界信息，不为统一轮廓重复包裹同一对象。
- 影响流程走向的条件接入主线，在分叉处明确择一或并行，标明分支条件与结果。创建、初始化与业务调用同图时，按事实标明各自触发时机。局部说明放进对应节点或紧邻对象；全图约束放到图下说明或表格。具体分类见视觉语法的「按信息职责选择表达」。
- 授权和另行触发等决定能否执行的前提，在执行入口处醒目标明；文件交接与执行触发分别表达，不能靠小字让读者辨别是否自动执行。
- 使用显式坐标。先确定完整的层、并列区域、共同边界与连线通道，再放节点。外部轮廓保持稳定，内部按内容分配列宽；同层节点共享基线，并列区域优先顶底对齐。间距与紧凑表达按视觉语法的「排版」执行。
- 优先为主要关系安排相邻节点和直接通道，再放辅助组件。跨区域连线走空白通道，仅在端点处必要地短距离穿入或穿出所属区域。先调整节点、标题与留白，再处理折线；多条侧边线统筹端口顺序和走线通道，避免相互交叉及箭头前的短促折弯。具体方法见视觉语法的「连线与整图复核」。
- 标签紧邻对应线段，先说明动作与对象，必要时第二行补充实现方式或条件。同类标签采用一致结构；编号仅供索引时不能替代动作说明，也不能让读者查表才能理解关系。两行表达、对齐与编号含义按视觉语法的「连线标签与编号」处理。
- 长标识加宽卡片或用 `tspan` 明确分行；长说明按作用范围安排，不能仅因篇幅长就将关键条件移出图。内容过密时拆成相关视图，保持共同节点和配色一致。
- 布局容量不足时换布局、增加空间或拆图，不截取组件列表、隐藏正文或自动缩到难以阅读的字号。同类示例的卡片数和通道尺寸只是起点，不能据此补出默认顺序、回路或调用。
- 转义输入中的 `<`、`>`、`&` 及属性引号。每张 SVG 提供 `role="img"`、概括图意的可访问名称及必要描述。
- 同一文件的所有 SVG ID 必须唯一。复制图形时更换 ID 前缀，并同步 marker、`aria-labelledby`、`aria-describedby` 等引用。

默认输出单个 HTML，包含标题、必要图例、说明及事实来源或版本。使用用户指定的路径，否则遵循目标仓库的文档存放约定。仅在用户要求时另交付独立 SVG、图片或 PDF。

## 验证与交付

先核对图意与阅读顺序：每张图的问题集中，主要节点与关系突出，节点类型明确；关键关系的真实起止对象有依据，短期对象与共享实例的范围明确，实例与存储归属正确，解释卡片未成为调用者，步骤编号没有替代状态归属。更新或简化后对照原图，确认读者仍能识别任务分组、协作者、交接条件与结果；不以节点更少、连线更短代替表达效果的检查。

检查独立节点是否有清楚的关系或分组归属。发现孤立节点时，先核对它是实际对象还是说明，再调整表达，不能为消除孤块编造连线。另查改变执行顺序、准入或终止结果的条件是否仍在图中可见，不能只留在图注中。

逐层核对真实组件是否被压缩成横幅或标签串，以及新增卡片是否都有事实依据。组件通过层内归属表达组成时，不要求为每张卡片额外补线。

对显式坐标的 HTML/SVG，先运行包内只读检查器（命令中的脚本路径相对于本 Skill）：

```bash
python3 scripts/check_diagram.py <图文件.html>
```

先修复 `error`，再逐项判断 `warning` 和 `coverage.skipped`。`ok: true` 只表示没有检出的错误，不证明图意或视觉效果合格；真实文字边界、标签含义、端点接触和背景避让仍需渲染复核。支持范围、标签绑定和回归检查见 [工具与布局示例](references/tools-and-examples.md)。不支持的几何保留原意，不能为了通过检查删线或改成错误关系。

在可用浏览器中实际渲染，检查浅色、深色主题以及宽屏、窄屏：

- 先缩小看完整构图：主要层和并列区域的轮廓稳定，对齐关系清楚，留白服务于分组与走线。再按实际显示尺寸阅读节点、条件与图例，最后检查几何细节。重排任务在相同显示宽度下对照改前版本，不以画布变短或没有重叠代替观感判断。
- 标题、组件标识、条件和图例可读，文字不被遮挡或裁切。
- 箭头起止位置、方向、线型和标签一致。分组与内部组件承担不同关系时，端点位置须能区分责任主体，不能仅靠标签纠正错误的视觉连接。检查非预期交叉、箭头前的短促折弯、穿字、借有色区域绕行、穿越无关分组或与边框重合；优先调整位置与通道解决问题。
- 按实际显示尺寸逐条对应标签与连线：标签归属唯一，主行能说明动作与对象，必要条件仍可就近读到；编号、API 名或下方表格不能替代图内的关系说明。没有碰撞不等于标签关联清楚。
- 模块职责色和共同节点跨图一致。公开入口与内部契约同时出现时，检查蓝色入口与绿色契约是否清楚区分。默认公共基础设施为橙色，工具与能力适配为琥珀金色。
- 窄屏允许图形容器横向滚动，页面其他部分不溢出；按实际显示尺寸检查字号和阅读负担，必要时增大最小显示宽度。
- HTML/SVG 结构有效，ID 无重复，引用有效，没有残留示例事实或非预期在线资源。

修复问题后复看受影响区域及整图。分别报告图意、视觉复看和结构检查的结果。浏览器不可用时可交付结构检查后的草稿，明确写出「未完成浏览器视觉验证」，并说明实际完成的离线复看范围。结构检查通过、生成了截图或 DOM 尺寸正常，都不能单独证明布局可读。

交付文件链接、完成的验证和仍未确认的事实。按本次请求完成绘图，不附带安装、发布或 Git 历史操作。
