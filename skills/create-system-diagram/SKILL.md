# Create System Diagram

创建、更新或检查系统架构、职责协作、局部流程与数据流图。默认交付一个可独立打开、可编辑的静态 HTML 文件，内嵌 CSS 与 SVG。图回答组件职责、归属边界和主要关系，默认使用固定色板，并按模块建立配色映射。用户指定的风格、路径和范围优先。

## 确定图意

从请求和材料确定读者、图要回答的问题、范围及事实版本。更新任务先读取目标文件、来源材料和已确认决定，核对适用的项目约定。材料能确定的事实自行核对，已确认决定直接沿用。

修改前明确目标对象、动作和影响范围。将「SDK」「引擎」「接入层」等通称对应到具体组件，用现有标题定位页面分区或图内对象，区分页面排布与模块、阶段、连线的修改。遇到对象或范围歧义时，按[对象、修改范围与澄清](references/visual-grammar.md#对象修改范围与澄清)判断。

- 区分生产实现、已确认设计和用户提供的外部现状。仓库行为及具体观测字段核对实际生产者，外部能力按用户确认呈现，待建设在对应对象旁标明；未亲验范围在交付说明中交代。详见视觉语法的「事实来源与状态」。
- 按架构职责划分模块，源码归属作为核对依据。大框表达大模块的职责边界，小框展开组成与分工；结合协作关系、资源与生命周期归属确定包含关系，源码标识用于定位实现。源码结构或构建视图明确采用对应维度。具体判断见视觉语法的「按架构职责划分模块」。
- 区分模块、类型、运行实例、存储、产物、条件与解释文字，先按信息职责决定是否画成独立节点。为关键节点、归属、箭头方向和条件找到依据；运行实例图还须确认创建者、持有者和实例范围。
- 涉及运行实例时，分别核对职责归属、执行线程与存储边界。创建与管理连线接实际责任组件，内部异步工作保留业务归属；进程视图将持久化介质放在进程框外，进程内的访问组件与句柄另行区分。具体判断见视觉语法的「职责归属、执行线程与存储边界」。
- 保留可选、未接入、运行模式和关键失败结果。查阅材料后，仍有会改变图意或修改范围的信息缺口、歧义或冲突时，说明未确定的含义、可选解释及影响并询问用户。暂停依赖答案的修改，继续整理已确认部分。

先按问题选择表达：职责与归属用架构图，任务如何完成用流程图，指标或方案比较用表格；需要时组合。为每张图确定一个主要问题，并按回答这个问题所需的层级展开。拆图或重排时保留请求范围内的性能、本期工作和验收信息。总览突出参与者、职责、主要关系与产物归属，局部流程展示关键协作。属于同一任务的组件、执行角色和产物可以共同出现，须标明类型与关系。常规间距、折线路径和文字换行由绘图代理决定。

路线、目标和评测摘要共同回答一个问题时，可放在同一页面分区，用内部标题与间距区分主体和摘要。问题、对象或展开深度明显不同时拆成相关视图；内容过密时仍按容量调整，不强制合并。

按主要问题安排视觉优先级：主流程突出连续的入口、处理与结果，职责对照保持同级对象相近的视觉权重。用位置、面积、留白与字重表达主次，模块色继续表达身份。总览与局部视图沿用名称、配色及有助于阅读的相对关系，局部注明所属模块；已有跳转或展开保留返回来源位置的路径。

## 绘制或更新

新建图、重排布局或修改架构含义时，先读 [visual-grammar.md](references/visual-grammar.md)，据此选择布局、模块配色和关系图例。仅修订文字或局部样式时，读取目标文件中受影响的节点、连线及对应样式。

绘制前先核对模块的架构身份、职责边界、协作边界及包含依据，再确定「模块 → 独立主色或继承对象 → 样式类」，安排共同边界与连线通道。详细判断见视觉语法的「模块、子模块与职责分区」及「模块配色」。事实关系决定箭头，布局决定位置。先核对职责与关系，不从名称中的「接口」「公共」或上下层位置直接推导颜色、箭头与布局。重排时保持关系的真实起止对象，不用构建或解析机制替代依赖目标。这个判断不要求额外交付清单。

新建图复制 [architecture-template.html](assets/architecture-template.html)，保留配套 CSS、字体回退与需要的箭头定义，替换示例内容。模板是样式与色值的唯一运行时来源；通用示例中的组件、关系和来源说明均须替换为本次任务的内容。

需要分层、并列工作流、回路、模块嵌套或场景能力与验收骨架时，按 [工具与布局示例](references/tools-and-examples.md) 选择对应 HTML。复杂图可参考示例生成脚本：节点尺寸只定义一次，端点从节点边界推导，标签候选位置从线段推导。最长线段只是标签的候选位置，仍须检查字宽与邻近线段。简单修改直接编辑 HTML，不强制改成 JSON 配置或生成脚本。

- 默认浅色主题，保留深色主题定义；不增加主题切换控件、在线字体或其他在线静态资源。
- 同组图共用模块映射，主色覆盖模块及继承配色的子模块。用户指定或已有明确依据的映射优先；其余子模块默认继承。只有本图主要比较或追踪多个同级子模块的分工与协作时，才为这一组统一制定独立配色。职责类别、接口、进程、连线或职责数量不自动触发换色。
- 为尚未定色的模块从固定色板选色，优先考虑淡橙、淡黄和淡红并兼顾冷暖搭配；按主要区域面积复看，保留已确认映射。模块名对应的 `module-*` 类负责选色，具体变量和继承规则见视觉语法。
- 外层模块及独立配色的子模块用自身主色浅底；继承配色的子模块用统一卡片背景与继承主色边框。同组职责使用所属色系中统一的一档较明显浅色，通过名称与分区区分职责。层次通过包含关系表达，不逐层加深。
- 性能、本期工作和验收说明的边框及归属标题沿用模块主色；正文、当前值用正文色，优化目标数值及比较符号局部橙色加粗并标明目标。跨模块汇总和页面分区用中性样式。图例在对应视图内容框外的下方左侧纵排，直接使用页面背景；模块色块在前，实际使用的连线样例在后，图例文字用次级文字色。
- 填色与边框按视觉语法处理，保留约 `2px` 的卡片边框和无填充的应用、进程边界。运行线程、接口回调与通信通道先确定实际所属模块，再沿用模块映射。
- 更新已有图时保留用户内容，只改受影响部分。根据最新文档更新时同步事实变化，沿用当前图稿已确认的简洁程度、信息粒度和删除项，只补充理解变化所需的信息。文件由脚本或模板生成时，修改实际生成源并重新生成，避免下次生成覆盖修正。用户未要求重配时，沿用文件已明确的颜色含义，新增节点使用同类节点的配色。调整模块主色时同步边框、模块标题、背景、图例及图注；只改文字配色时保留模块背景与边框；有对照页时同步新版视图，保留改前视图。
- 混合组件、执行角色、文件或产物时，用简短类型标签区分。职责说明放在实际负责的角色旁；跨角色收尾动作可与产物一起呈现，并明确执行者。节点保持稳定对象含义，执行阶段另在局部流程中表达。
- 场景图交代发起者、处理组件、输出与调用方用途。同一请求往返默认保留一个调用方，返回线接回原节点。按生命周期阶段展开时才按需重复组件，标明阶段并保持身份与颜色一致；独立实例须另有依据。加载、显式释放、自动回收从实际发起者出发，资源状态作为结果，后续请求从真实入口进入。区分已完成的现状、本期工作与待确认内容。指标须有对象、单位、适用范围、统计口径和来源，实测、估算与目标分别标明。详细规则见视觉语法的「场景能力与验收」。
- 当标题、分组和连线已能说明本场景作用时，允许只保留标题，同级节点保持相近的信息粒度。需要块内解释时，优先说明当前场景最相关的动作、对象、结果用途和必要条件，核心解释保持正文层级；辅助信息才降为次级文字。模块名称用模块色，内部组件与职责标题用正文色，按文字用途选样式，不全局染色 `.node-title`。完整规范见视觉语法的「文字用途与配色」「块内文字与场景作用」。
- 主要节点保留名称与必要定位标识，按需补充本场景核心作用。简化时保留工作流分组、关键协作与交接条件，让读者仍能追踪任务如何完成；次要资料降为注释或链接。
- 在本图展开范围内，优先展示回答问题所需的真实子模块，再补充必要职责；二者可以共存。有明确组件的层应展示具体卡片，保留组件名称及必要说明，不能为紧凑只剩层标题或一条空横幅。卡片数量以真实组成为准，不为填满空间虚构、重复或无依据地拆分组件；属性和状态仍用标签表达。外框须提供额外的归属或边界信息，不为统一轮廓重复包裹同一对象。
- 影响流程走向的条件接入主线，在分叉处明确择一或并行，标明分支条件与结果。创建、初始化与业务调用同图时，按事实标明各自触发时机。局部说明放进对应节点或紧邻对象；共同范围优先在图标题下说明一次，图下仅保留必要约束摘要，完整约束通过来源链接查看。具体分类见视觉语法的「按信息职责选择表达」。
- 授权和另行触发等决定能否执行的前提，在执行入口处醒目标明；文件交接与执行触发分别表达，不能靠小字让读者辨别是否自动执行。
- 使用显式坐标。先确定完整的层、并列区域、共同边界与连线通道，再放节点。外部轮廓保持稳定，内部按内容分配列宽；同层节点共享基线，并列区域优先顶底对齐。同组内容更紧凑，跨组间距更清楚；按邻近关系检查标题、解释与标签的归属。间距与紧凑表达按视觉语法的「排版」执行。
- 优先为主要关系安排相邻节点和直接通道，再放辅助组件。跨区域连线走空白通道，仅在端点处必要地短距离穿入或穿出所属区域。先调整节点、标题与留白，再处理折线；多条侧边线统筹端口顺序和走线通道，避免相互交叉及箭头前的短促折弯。具体方法见视觉语法的「连线与整图复核」。
- 标签紧邻对应线段，同组统一采用动作与对象或场景与载荷，请求与返回成对且顺序一致，必要时第二行补充实现方式或条件；编号仅供索引时不能替代动作说明，也不能让读者查表才能理解关系。两行表达、对齐与编号含义按视觉语法的「连线标签与编号」处理。
- 主要工作、比较结论与关键条件保持正文层级，不能因文字长就降成小字。沿用来源中的术语，按语义分行；总览保留角色、关系、结果与判断条件，完整实现细节放到来源材料。长标识加宽卡片或用 `tspan` 明确分行；长说明按作用范围安排，不能仅因篇幅长就将关键条件移出图。内容过密时拆成相关视图，保持共同节点和配色一致。
- 布局容量不足时换布局、增加空间或拆图，不截取组件列表、隐藏正文或自动缩到难以阅读的字号。同类示例的卡片数和通道尺寸只是起点，不能据此补出默认顺序、回路或调用。
- 从目标显示尺寸反推字号、画布与最小显示宽度，复核实际字号及中文混排。HTML 文字使用相对单位；显式坐标 SVG 的字号、卡片与通道一起调整。模板以 `1400px` 最小图宽保留图内横向滚动。具体参数见视觉语法的「画布与文字」。
- 转义输入中的 `<`、`>`、`&` 及属性引号。每张 SVG 提供 `role="img"`、概括图意的可访问名称及必要描述。
- 同一文件的所有 SVG ID 必须唯一。复制图形时更换 ID 前缀，并同步 marker、`aria-labelledby`、`aria-describedby` 等引用。

默认输出单个 HTML 图示页，包含标题、必要图例和说明及事实来源或版本；涉及目标与评测时仅保留相关摘要。完整路线表、验证步骤和验收细则留在来源文档，用户明确要求完整资料页时再按指定范围展开。使用用户指定的路径，否则遵循目标仓库的文档存放约定。仅在用户要求时另交付独立 SVG、图片或 PDF。

## 验证与交付

绘制后逐项对照用户要求，核对要求是否在正确模块中通过节点、关系或说明表达，状态与适用场景是否就近可见。有明确依据的遗漏直接补齐。

涉及场景与指标时，先确认调用方及结果用途完整，数据与测量对象对应，当前事实、本期工作、目标和待确认项有据可查；重排未漏掉请求范围内的信息。

复看整个 HTML 的信息量，精简图注、表格和说明中的重复细节；保留理解本图所需的目标与关键条件。先核对图意与阅读顺序：每张图的问题集中，主要节点与关系突出，节点类型明确；架构分组有职责与协作依据，源码标识用于定位和核对实现；关键关系的真实起止对象有依据，短期对象与共享实例的范围明确，实例与存储归属正确，解释卡片未成为调用者，步骤编号没有替代状态归属。更新或简化后对照原图，确认读者仍能识别任务分组、协作者、交接条件与结果；不以节点更少、连线更短代替表达效果的检查。

复核创建、持有和关闭关系的实际责任组件、线程标注对应的调度代码，以及进程驻留对象与持久化介质的边界。归属修正时同步检查节点位置、包含关系、连线端点、配色和说明，完成必要的结构调整。

检查独立节点是否有清楚的关系或分组归属。发现孤立节点时，先核对它是实际对象还是说明，再调整表达，不能为消除孤块编造连线。另查改变执行顺序、准入或终止结果的条件是否仍在图中可见，不能只留在图注中。

逐层核对真实组件是否被压缩成横幅或标签串，以及新增卡片是否都有事实依据。组件通过层内归属表达组成时，不要求为每张卡片额外补线。

对显式坐标的 HTML/SVG，先运行包内只读检查器（命令中的脚本路径相对于本 Skill）：

```bash
python3 scripts/check_diagram.py <图文件.html>
```

先修复 `error`，再逐项判断 `warning` 和 `coverage.skipped`。`ok: true` 只表示没有检出的错误，不证明图意或视觉效果合格；真实文字边界、标签含义、端点接触和背景避让仍需渲染复核。支持范围、标签绑定和回归检查见 [工具与布局示例](references/tools-and-examples.md)。不支持的几何保留原意，不能为了通过检查删线或改成错误关系。

验证范围跟随修改对象：节点或文字修改检查卡片排版与相关连线；页面分区或容器修改还须检查整个 HTML 的标题层级、间距、图注、框外图例与滚动。页面组织效果须在浏览器中复看，离线 SVG 复看只覆盖图形本身。未受影响且仍有效的检查结果可以复用。

在可用浏览器中实际渲染，检查浅色、深色主题以及宽屏、窄屏：

- 按每张图的主要问题选择一个阅读任务，沿最终图稿追踪入口、关系与结果，或核对持有和关闭责任。修正需要猜测归属、远处找标签或查表才能理解的位置；涉及局部视图时检查进入与返回。代理走读和实际用户测试分别报告。
- 先缩小看完整构图：主要层和并列区域的轮廓稳定，对齐关系清楚，留白服务于分组与走线。再按实际显示尺寸阅读节点、条件与图例，最后检查几何细节。重排任务在相同显示宽度下对照改前版本，不以画布变短或没有重叠代替观感判断。
- 标题、组件标识、条件和图例可读，文字不被遮挡或裁切。
- 箭头起止位置、方向、线型和标签一致。多色模块中的普通交接可用中性色；按实际字号和显示比例调整线宽与箭头，保留方向辨识及已有条件、事件、失败含义。性能等注释关联使用无箭头线或分组表达。分组与内部组件承担不同关系时，端点位置须能区分责任主体，不能仅靠标签纠正错误的视觉连接。检查非预期交叉、箭头前的短促折弯、穿字、借有色区域绕行、穿越无关分组或与边框重合；优先调整位置与通道解决问题。
