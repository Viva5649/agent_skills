# Create System Diagram

创建、更新或检查系统图，默认交付可独立打开、可编辑的静态 HTML，内嵌 CSS 与 SVG。使用固定色板与布局规范，按读者问题选择节点和关系。用户指定的风格、路径、范围与已确认决定优先。

## 规则选择

采用「通用规则 + 图类型规则 + 专项规则」。每张主视图选择一个图类型，再叠加触发条件成立的专项；同一 HTML 可以包含不同图类型。普通架构图无需增加起止事件、循环、性能区或交互。

1. 全部图遵守下面的通用规则。新建、重排或改变图意时读取 [visual-grammar.md](references/visual-grammar.md)；局部文字或样式修改只读取受影响对象与对应章节。
2. 按主要问题读取 [diagram-types.md](references/diagram-types.md) 中的对应章节。
3. 按下表只读取 [specialized-rules.md](references/specialized-rules.md) 中已触发的章节。专项可以跨图类型使用，不扩大任务授权。

| 图类型 | 适用问题 | 节点粒度与主要关系 |
| --- | --- | --- |
| 架构图 | 有哪些模块，职责如何划分，如何组成与协作 | 有依据的架构单元；包含、依赖、调用、实现与协作 |
| 流程图 | 输入或事件如何推进到结果 | 功能操作、判断与结果；执行顺序、条件与循环 |
| 数据流图 | 数据在哪里产生、传递、保留与使用 | 数据或存储对象及必要操作；读写、传递、复制与映射 |

| 专项规则 | 触发条件 |
| --- | --- |
| 多视角对应 | 同一对象或链路需要多个视角共同解释 |
| 性能指标 | 出现耗时、吞吐、内存、占比、基线、比较或目标 |
| 资源与存储 | 图意涉及持有、生命周期、线程、读写或搬运 |
| 配置与实现差异 | 比较或切换后端、平台、场景、版本或运行配置 |
| 交互与分享 | 已有或用户要求展开、切换、跳转、动画或独立分享 |

纯指标或方案比较可用表格。混合视图先确定主要问题，标明节点与关系类型；展开深度服从问题，不强制每层同样多的块或每个视角一一对应。

## 通用规则

### 确定图意与事实

读取请求、目标文件、来源材料、已确认决定与项目约定，确定读者、主要问题、对象范围、展开层次及事实版本。修改前用已有标题或对象名称定位目标，区分页面分区、模块、阶段和连线。材料足以确定的事实自行核对，常规坐标、换行与避让由绘图代理决定。

关键节点、归属、关系方向与条件须有依据。区分生产实现、已确认设计和用户提供的外部现状；具体观测字段核对实际生产者。仍有会改变图意、范围或授权的信息缺口时，说明含义与影响并询问用户，只暂停依赖答案的修改。已有证据足以确定主线时先形成图稿，未确认部分就近标明；构建、真机测试和性能采集按任务授权另行执行。

同层节点保持可比较的身份与粒度。模块、类型、运行实例、功能操作、数据、产物、条件与说明分别判断，重要性本身不决定是否独立成块。局部说明放在对应对象旁，全图共同范围在标题下说明；影响入口、分支或结果的条件保留在实际作用位置。不为消除孤立节点编造关系。

### 信息、配色与版式

- 每张图回答一个主要问题。标题、解释文字与连线共同说明当前场景中谁做什么、作用于什么对象、产生什么结果。名称已足够清楚的节点可只保留标题；核心解释用正文色，辅助信息才降为次级文字。
- 同一概念沿用已有名称，主图、明细和生成源保持一致。操作标题说明当前作用或结果，函数名与公式按需补充。展开内容承接父节点，主要结果与关键条件在主视图可见，完整推导、日志和工程细节留在来源材料。
- 默认按模块建立「模块 → 独立主色或继承对象 → 样式类」映射。子模块默认继承，仅在已有明确决定或本图需要追踪一组同级模块协作时统一制定独立配色。职责、接口、线程和上下位置不自动触发换色。按视角配色只在多视角专项条件成立时启用，并声明颜色维度。
- 使用模板固定色板。尚未定色时优先考虑淡橙、淡黄与淡红，兼顾冷暖面积；已有映射优先。外层模块保留主色浅底，继承子模块用卡片背景与主色边框，同组职责共用一档填色。层次用包含关系表达，不逐层加深。配色和文字用途详见视觉语法。
- 先安排主要区域、共同边界和连线通道，再放节点。同层基线协调，内部宽度按内容分配。同组更近，跨组留白更清楚；尺寸调整时同步移动区域、端点和标签，避免只缩卡片而拉长连线。
- 真实关系决定连线端点。主关系优先采用相邻节点和直接通道；跨区域线走空白通道，侧边回路统筹端口顺序。复核交叉、穿字、穿无关区域和箭头前的短促折弯，先调整位置与留白，再增加折线。
- 标签紧邻对应线段，同组按动作与对象或场景与载荷描述。编号说明索引或顺序含义，主行仍表达关系，不让读者查表才能理解主线。两行标签、端点与图例规范见视觉语法。
- 布局容量不足时增大空间、换布局或拆成相关视图，保留必要节点和条件。按目标显示尺寸检查字号，SVG 字号、卡片和通道一起调整；窄屏允许图内横向滚动。图例在视图内容框外左下方纵排，只列实际使用的颜色与关系。

### 模板与更新

新建图复用 [architecture-template.html](assets/architecture-template.html) 的 CSS、字体与 marker，再按[工具与布局示例](references/tools-and-examples.md)选择骨架。模板是样式与色值的唯一运行时来源，示例只提供虚构场景，节点、关系、数据和条件须按本次任务替换。纯架构、局部流程、多视角与数据流示例分别适用，不复制无依据的步骤或回路。

默认浅色主题，保留深色定义；不增加主题切换、在线字体或其他在线资源。简单修改直接编辑 HTML，不强制引入 JSON、生成器或交互。文件由脚本或模板生成时，修改实际生成源并重新生成。

更新保留当前图稿已确认的信息粒度、内容与删除项，只修改受影响部分。文案修改限于文字与必要排版；仅改文字颜色时保留背景和边框。修改主色时同步标题、背景、边框、图例、图注及新版对照视图，改前视图保留。局部删除要求不固化为其他图的全局规则，已撤回方案不再作为默认依据。

默认交付单个 HTML，包含标题、必要图例、说明及事实来源或版本。完整验证步骤、路线表和工程资料保留在来源文档，只有用户要求时才扩成资料页或另交付 SVG、图片、PDF。输入文字正确转义；SVG 提供可访问名称，文件内 ID 唯一，复制后同步 marker 与可访问引用。

## 图类型规则

按选定类型执行 [diagram-types.md](references/diagram-types.md)：

- 架构图按职责、协作及包含依据确定模块，源码作为核对依据。有明确子模块时按问题展开真实组件，职责说明可共存；不为填满区域造块或为紧凑压成空横幅。
- 流程图按「执行者在什么输入或状态下，完成什么操作，得到什么结果」确定功能操作。复杂或有争议的粒度先用代表性局部校准，再展开。入口、完成边界及实际出现的循环、分支和条件出口明确。
- 数据流图先确定逻辑数据、存储对象或物理分配层次，明确读写、复制、转换、映射与别名。固定存储列仅在需要跨阶段连续追踪读写时采用。

## 专项规则

只应用已触发的 [specialized-rules.md](references/specialized-rules.md) 章节。多视角保留各自主线并允许一对多映射；指标注明对象、范围、口径和来源，区分累计、包含、重叠与未知；资源管理责任、执行线程与存储边界分别核对；配置差异区分支持能力、选择配置与实际执行；交互维护当前对象、配置与返回位置，独立分享按交付环境验证。

## 验证与交付

先逐项对照用户要求，按选定图类型检查节点、分组、关系与条件。只有专项触发时才执行对应检查。按本图主要问题选择一个阅读任务：架构图找职责与协作；流程图追踪入口到结果及已有循环；数据流图追踪来源、变化与使用；指标图解释统计范围与比较。修正需要猜归属、远处找标签或查表重建主线的位置。

对显式坐标 HTML/SVG，运行包内只读检查器，以下脚本路径相对于本 Skill：

```bash
python3 scripts/check_diagram.py <图文件.html>
```

先修复 `error`，再逐项判断 `warning` 和 `coverage.skipped`。支持范围外的几何不算通过；不能为了通过检查删线或改成错误关系。真实文字边界、标签关联和背景避让继续渲染复核，详见工具参考。

在可用浏览器中检查实际显示。节点修改复看相关卡片与连线；页面容器修改还须复看整页标题、图注、图例及滚动。新模板或共享样式变更检查明暗主题、宽窄屏与实际字号，配色变更再用等面积色板复核灰度。先看整体轮廓与分组，再读文字和主要关系，最后查几何。重排以相同显示宽度对照改前版本。已有链接和控件检查键盘、焦点与返回，动态效果按专项规则验证。

修正后复看受影响区域及整图，同组图的术语、指标口径、标签、字号和颜色含义一致。检查未残留示例事实、真实项目资料或非预期外部资源，包内通用示例只用虚构内容。有效且未受影响的检查可以复用。

交付文件链接，分别报告图意走读、结构检查、视觉复看及实际交互测试的结果。浏览器不可用时明确写出「未完成浏览器视觉验证」，说明离线复看覆盖范围；截图生成或结构通过不单独证明可读性。未进行的用户测试或运行实验不声称通过。本 Skill 不附带安装、发布或 Git 历史操作。
