# 离线文档处理方案输入

以下资料是一次独立的虚构项目练习，全部事实以本文为准。

## 已确认需求

- 方案给产品、设计、评测和技术评审，也要指导文档引擎后续实施。
- 文档引擎服务三个场景：阅读应用的预览生成、资料应用的归档转换、搜索应用的语义检索。
- 预览生成和归档转换都使用文档渲染能力；语义检索使用文本向量化能力。
- 本期文档引擎负责渲染性能优化，以及渲染包在线下载与版本切换。搜索应用的索引和排序由搜索应用维护。
- 文档引擎没有单独 PRD，总需求在离线办公方案中。交付日期未定，使用「本期」。
- 预览生成、归档转换的吞吐都要求较同条件基线提升至少 20%，渲染进程内存均值降低至少 10%。语义检索本期没有引擎优化目标。
- 内容一致性测试采用固定 120 份文档，按现有评分脚本比较，得分不能低于基线。
- 没有安排产品试读的条件；图先留占位。

## 现有文档和代码摘录

- `DocumentEngine.render()` 提供文档渲染；`DocumentEngine.encode()` 提供文本向量化。阅读应用、资料应用均已接入渲染；搜索应用已经接入本地 encode。
- 搜索应用负责内容入库、向量索引及排序，文档引擎只返回向量。
- 模型包目前由开发者预部署。在线下载与版本切换尚未实现。
- 已确认目标：内容服务提供包地址，文档引擎下载并校验目标包；准备期间使用当前包；目标包准备成功后，新请求使用目标包；准备失败继续使用当前包。就绪判定细节与旧包保留期限尚未确定。
- 当前运行器支持 CPU、GPU。设备 B 的 GPU 路线尚未验证。
- `RemoteEncodeTestServer` 只用于工程测试，不是生产回退方案，也没有质量评测结果。
- 监控平台已经能够查询单次失败请求，来自运维确认；仓库尚未收录平台截图。

## 候选优化措施

- 调整渲染缓存容量：可能降低进程内存，也可能增加重复渲染耗时；实际收益未测。
- 合并相邻绘制操作：减少 GPU 提交次数，预期提高渲染吞吐；数值收益未测。
- 内核实现和实验参数在后续渲染优化专题展开。

## 当前待补

- 搜索应用没有正式业务评测集、相关性标注和通过阈值。
- 下载地址服务接入条件待内容服务确认。
- 没有专门的引擎团队，只有项目开发者负责引擎工作。
