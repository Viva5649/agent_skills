# 内容迁移与一致性检查

用于重大重组、新旧稿比较、总览替换、详细内容下沉和多文档同步。单句修改无需建立迁移表。

## 先确定权威与内容归宿

区分三类差异：

| 差异 | 处理 |
| --- | --- |
| 结构或详略不同 | 核对事实、条件与关键参数是否仍有归宿 |
| 已确认的决定发生变化 | 采用最新已确认决定，更新受影响的有效文档与图稿 |
| 两稿说法冲突，尚无明确决定 | 查对应证据；仍不能判断时提出具体问题，保留待定状态 |

「新版」只是文件状态，不能单凭新旧推定技术决定。也不要从旧决策日志中恢复已撤回的范围。

需要替换整稿时，先记录每项仍有效的重要信息：

| 原内容 | 当前有效结论 | 目标文件与章节 | 处理与验证 |
| --- | --- | --- | --- |
| 业务用途、主要指标、技术取舍 | 最新已确认结论 | 总览场景或机制章节 | 保留摘要，核对数字及条件 |
| 接口、状态、资源归属、异常结果 | 当前契约或已确认目标 | 现有技术文档或详细专题 | 已有则引用，缺失则先补齐 |
| 实验配置、完整采样、运行记录 | 对应报告事实 | 报告或验证资料 | 保持可追溯引用 |
| 已退出本期的工作 | 最新范围决定 | 按项目约定保留历史记录 | 从活动计划、验收与待补项同步移除 |

使用真实路径和章节，不能只写「详见专题」。检查目标正文是否真的承接了语义，不能只因文件名相似就判为已有。

## 替换顺序

1. 保留原稿快照，按授权在副本调整结构。
2. 完成信息去向核对，将没有归宿的有效技术细节补到对应资料。
3. 同步总览、专题、图示文字、待补清单和引用。
4. 核对目标文件与章节锚点，抽查迁移后上下文能否独立理解。
5. 满足用户的替换条件后更新唯一维护入口，处理副本和失效引用。

用户只授权分析时，交付差异与迁移建议，不执行替换。

## 按变更检查相关内容

| 变更 | 一并核对 |
| --- | --- |
| 本期范围或业务决定 | 场景用途、工作项、验收、依赖、详细专题及图稿 |
| 基线或目标 | 绝对值、相对比例、比较符号、单位、口径与来源 |
| 术语 | 标题、正文、表格、图内文字、图例和占位；保留代码及 API 标识原样 |
| 机制或调用关系 | 参与者、所属边界、触发条件、结果及失败处理 |
| 章节或文件移动 | 内部锚点、文末依据、图片源和其他文档入口 |

只更新仍在维护且受本次变更影响的内容。保留已明确作为历史记录的原文。图稿尚未同步时如实列出，不声称整套方案已经一致。

精简后从实施者角度复查：关键细节能否通过声明的引用找到，是否仍需依赖聊天记忆才能理解。找不到归宿的有效细节继续保留，直到迁移完成。
