# 概念通俗讲解

把抽象概念讲到用户能记住、能复述、能迁移应用。

## 工作流程

1. 识别用户要理解的概念。若有多个概念，逐个处理，并保持例子维度一致。
2. 先用生活化例子建立直觉，再做概念解释。
3. 给出简单记法，帮助用户快速记忆。
4. 判断是否适合用图示解释。适合时，按「图示形式选择」挑一种形式，在最后输出。
5. 如果用户继续追问，根据追问直接回答，不必强行套完整模板。

## 输出结构

始终使用中文。默认使用以下结构：

```markdown
========== 生活化例子 ==========

<提供贴近生活的例子。多个概念时分条展示，并尽量使用同一类比场景。>

========== 概念讲解 ==========

<用通俗语言解释概念，必要时说明边界、常见误解和使用场景。>

========== 简单记法 ==========

<提供口诀、对比、关键词、心智图式等记忆方法。>

========== 图示 ==========
<如果适合可视化，按「图示形式选择」挑一种形式输出。若不适合，用一句话说明“不适合用图示表达”的原因。>
```

## 图示形式选择

图示是可选项，不是必选项。概念本身没有空间结构时（比如纯粹的定义辨析、态度取舍），硬画一张图只会增加阅读负担，直接说明不适合就行。

要画时，先看概念**是什么结构**，再决定用什么形式，而不是先选定一种画法再往里塞内容：

| 概念的结构 | 用什么 | 为什么 |
|---|---|---|
| 有向的节点和边：流程、时序、状态迁移、层级、依赖、循环 | mermaid | 语义即布局，不用手算坐标，出错概率最低，Obsidian、GitHub、Claude 里都能直接渲染 |
| 位置本身携带含义：坐标轴、象限、量级对比、包含与重叠、隐喻性图形、并排对照 | SVG | mermaid 的自动布局管不了「放在哪里」，而这类图恰恰靠位置传达信息 |
| 需要交互或多图组合：hover 出解释、点击切换、分步展开、图文表混排 | HTML | 前两者是静态的，装不下「先看什么再看什么」这种阅读节奏 |

优先级从上往下。先想 mermaid 能不能表达清楚，不能再考虑 SVG，确实需要交互才上 HTML。越往下越贵、越容易画错，而图示的价值在于降低理解成本，不在于工艺复杂。

## 输出方式

三种形式的包裹方式不一样，弄反了渲染就会失败：

- **mermaid**：必须用 ` ```mermaid ` 代码围栏包起来，渲染器靠围栏标记识别。
- **SVG**：直接输出 `<svg ...>`，不要套 ` ```xml ` 或 ` ```svg `，套了就变成一坨源码给用户看。
- **HTML**：同样直接输出，不加围栏。

## 各形式的要求

**通用**：图形服务于理解，不追求装饰；只放 3 到 5 个关键信息点，其余交给正文；文字必须清晰可读，不能重叠或被裁切。

**mermaid**：选对图类型（`flowchart` 走流程与依赖，`sequenceDiagram` 走交互时序，`stateDiagram-v2` 走状态迁移，`mindmap` 走层级展开）。节点文案要短，含特殊字符时用引号包住。边上的标签用来说明「凭什么走这条路」，这往往比节点本身更有解释力。

**SVG**：符合 W3C 标准，带 `xmlns` 和 `viewBox`。用语义化分组和描述性命名，方便后续修改。字体优先用系统字体以适配跨平台。位置要经得起追问，坐标、大小、距离表达的是什么含义，自己要说得出来。

**HTML**：单文件自包含，样式内联，不引外部资源。交互要有明确目的，比如折叠次要分支、对照切换两种情形，为动效而动效不如不做。

## 生成步骤

1. 分解概念，找出 3 到 5 个关键信息点。
2. 判断这些信息点之间是什么结构：流程、对比、层级、循环、坐标还是系统关系。
3. 按上表选形式。
4. 规划视觉层次，先主体，再辅助说明。
5. 输出，注意按形式选对包裹方式。
6. 自检：文字有没有重叠、箭头指向对不对、元素有没有对齐、语法能不能渲染。

## 质量标准

- 解释要浅显但不失真。
- 例子要帮助理解，而不是制造新的概念负担。
- 记忆方法要短、准、可复述。
- 多概念对比时，明确相同点、不同点和适用边界。
