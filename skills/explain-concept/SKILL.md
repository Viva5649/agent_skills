# 概念通俗讲解

把抽象概念讲到用户能记住、能复述、能迁移应用。

## 工作流程

1. 识别用户要理解的概念。若有多个概念，逐个处理，并保持例子维度一致。
2. 先用生活化例子建立直觉，再做概念解释。
3. 给出简单记法，帮助用户快速记忆。
4. 判断是否适合用图示解释。适合时，在最后输出 SVG。
5. 如果用户继续追问，根据追问直接回答，不必强行套完整模板。

## 输出结构

始终使用中文。默认使用以下结构：

```markdown
========== 生活化例子 ==========

<提供贴近生活的例子。多个概念时分条展示，并尽量使用同一类比场景。>

========== 概念讲解 ==========

<用通俗语言解释概念，必要时说明边界、常见误解和使用场景。>

========== 简单记法 ==========

<提供口诀、对比、关键词、心智图式等记忆方法。>

========== 图示 ==========
<如果适合可视化，直接输出 SVG。若不适合，用一句话说明“不适合用图示表达”的原因。>
```

## SVG 图示规范

当需要生成 SVG 时，遵循以下规则：

1. 直接输出 `<svg ...>`，外层不要套 ```xml 或 ```svg。
2. SVG 必须符合 W3C 标准，包含 `xmlns` 和 `viewBox`。
3. 图形要服务于理解，不追求复杂装饰。
4. 文本和图形不能重叠，所有文字必须清晰可读。
5. 使用语义化分组和描述性命名。
6. 适配跨平台显示，优先使用系统字体。

## SVG 生成步骤

1. 分解概念，找出 3 到 5 个关键信息点。
2. 选择最适合的可视化结构，如流程、对比、层级、循环、坐标、系统图。
3. 规划视觉层次，先主体，再辅助说明。
4. 输出完整 SVG。
5. 检查文字是否重叠、箭头是否清晰、元素是否对齐。

## 质量标准

- 解释要浅显但不失真。
- 例子要帮助理解，而不是制造新的概念负担。
- 记忆方法要短、准、可复述。
- 多概念对比时，明确相同点、不同点和适用边界。
